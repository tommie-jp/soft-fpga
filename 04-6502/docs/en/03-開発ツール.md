# Development Tools for Apple-I

## 1. C Compilers

### 1.1 cc65 (Recommended)

- **URL**: [https://cc65.github.io/](https://cc65.github.io/)
- Cross-development package for 6502 that runs on Linux
- Bundles a C compiler, assembler, linker, and libraries
- No official Apple-1 target, but a single custom linker script is enough to support it
- Install with: `sudo apt install cc65`

```bash
cc65 -t none -O foo.c       # C → assembly
ca65 foo.s -o foo.o         # assembly → object
ld65 -C apple1.cfg foo.o -o foo.bin  # link (custom cfg required)
```

Minimal linker script for Apple-1 (`apple1.cfg`):

```text
MEMORY {
  RAM: start = $0300, size = $CD00, file = %O;
}
SEGMENTS {
  CODE: load = RAM, type = ro;
  DATA: load = RAM, type = rw;
  BSS:  load = RAM, type = bss;
}
```

#### Limitations

- Subset of ANSI C (no `long long`, etc.)
- No OS or standard library — `printf` and friends must be implemented from scratch
- The equivalent of `putchar` is handled by writing directly to DSP (`$D012`)

### 1.2 llvm-mos (Optimization-focused)

- **URL**: [https://llvm-mos.org/](https://llvm-mos.org/)
- LLVM-based C/C++ compiler targeting 6502
- More powerful optimization than cc65 (uses zero-page as virtual registers)
- Supports C99 / C++11 (used via the `clang` command)
- No official Apple-1 target; SDK customization required
- Binary releases available (Ubuntu supported): [https://github.com/llvm-mos/llvm-mos](https://github.com/llvm-mos/llvm-mos)

## 4. The Reality of C Development on the Apple-1

The Apple-1 has no OS and no standard library.
Even code written in C can only do pure computation; all I/O requires direct hardware access.

```c
/* Character output on Apple-1 (cc65 / llvm-mos compatible) */
#define DSP  (*(volatile unsigned char *)0xD012)
#define DSPCR (*(volatile unsigned char *)0xD013)

void putch(char c) {
    DSP = c | 0x80;
    while (DSP & 0x80)  /* busy wait */
        ;
}
```

Given the memory constraints (4 KB RAM = `$0000–$0FFF`), writing directly in assembly is often
more practical than using C.
