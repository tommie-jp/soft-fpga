## 1. Purpose

First CPU example.
This is the first showcase of the project's unique value: visualizing internal signals that are invisible in instruction-level emulators.
It launches wozmon (Woz Monitor) and delivers an interactive experience where the user can dump memory, write to it, and execute programs.

### 3.3 cpu_65c02.v Port List

```verilog
module cpu_65c02( clk, reset, AB, DI, DO, WE, IRQ, NMI, RDY, SYNC );

input        clk;       // clock (rising-edge triggered)
input        reset;     // synchronous reset (active high)
output reg [15:0] AB;   // address bus (register output)
input  [7:0] DI;        // data bus input (memory → CPU)
output [7:0] DO;        // data bus output (CPU → memory)
output       WE;        // write enable (High = write)
input        IRQ;       // interrupt request (active low)
input        NMI;       // non-maskable interrupt (active low)
input        RDY;       // ready (Low = pause)
output reg   SYNC;      // instruction fetch lead cycle (High = fetch)
```

### 3.4 Memory Timing (AB Register Output)

Because AB is `output reg`, a 1-clock synchronous memory model is used.

| Timing | Action |
| --- | --- |
| posedge T | AB updates to next address; CPU samples DI |
| negedge T | harness sets `DI ← memory[AB]` |

![AB bus timing diagram](../img/04-ab-bus-timing.png)

> Example: `LDA #$42` ($FF00: A9, $FF01: 42) — 2 cycles.
> AB is updated on posedge; harness finalizes DI on negedge.

Unlike the combinational AD output of arlet-65C02-microcode, AB is a register, so the harness does not need to wait for AD to settle after clk=0, keeping the harness simple.

```cpp
// Correct memory access sequence in harness
void step() {
    // 1. Falling edge: finalize DI (current AB = address registered in previous cycle)
    top->clk = 0; top->eval();
    top->DI = memory_read(top->AB);

    // 2. Rising edge (AB update, DI sample)
    top->clk = 1; top->eval();

    // 3. Write processing (WE / DO / AB already registered on same posedge)
    if (top->WE) memory_write(top->AB, top->DO);

    // 4. Ring buffer sampling
}
```

### 3.5 Internal Register Exposure Policy

Internal signals in cpu_65c02.v are declared with `/* verilator public */` and accessed from the Verilator C++ API as `top->cpu_65c02->signal`.
Only a single comment line is added to the source; no logic changes are made.

| Internal signal | Type | Exposure method |
| --- | --- | --- |
| `A` | `[7:0]` | Add `/* verilator public */` |
| `X` | `[7:0]` | Same |
| `Y` | `[7:0]` | Same |
| `S` | `[7:0]` | Same (stack pointer) |
| `P` or individual flags | `[7:0]` | Same |
| `state` | approx. `[5:0]` | Same (T-state equivalent) |

> PC: the `AB` value during the cycle where `SYNC=1` equals the opcode fetch address (PC).
> To expose it directly, add `/* verilator public */` to the `PC` register.

Example access from Verilator:

```cpp
#include "Vapple1_top.h"
#include "Vcpu_65c02.h"  // generated by Verilator

auto* core = top->apple1_top->u_cpu;  // hierarchy name adjusted with --prefix
uint8_t a  = core->A;
uint8_t x  = core->X;
```

## 8. C++ Harness Design

### 8.1 Memory Access and PIA Emulation

```cpp
static uint8_t ram[0x10000];   // 64KB flat (including ROM region)
static uint8_t kbd_data = 0;   // KBD data (bit7 = strobe)
static uint8_t kbd_cr   = 0;   // KBDCR (bit7=1 means key waiting)

static uint8_t memory_read(uint16_t addr) {
    switch (addr) {
        case 0xD010: {
            uint8_t d = kbd_data; kbd_data &= 0x7F; return d;  // clear strobe
        }
        case 0xD011: return kbd_cr;
        case 0xD012: return 0x00;  // DSP ready
        case 0xD013: return 0x00;
        default:     return ram[addr];
    }
}

static void memory_write(uint16_t addr, uint8_t data) {
    switch (addr) {
        case 0xD012: enqueue_display(data & 0x7F); break;  // character output
        default:
            if (addr < 0xD000) ram[addr] = data;  // do not write to ROM region
            break;
    }
}
```

### 8.2 One-Clock Flow (step function)

![step() sequence diagram](../img/04-step-sequence.png)

```cpp
EMSCRIPTEN_KEEPALIVE void step() {
    // Falling edge (finalize DI)
    top->clk = 0; top->eval();
    top->i_di = memory_read(top->o_ab);

    // Rising edge (AB update, DI sample, WE/DO registration)
    top->clk = 1; top->eval();

    // Write processing
    if (top->o_we) memory_write(top->o_ab, top->o_do);

    // Ring buffer write
    write_ring();
}
```

### 8.3 Ring Buffer Bit Layout (2 uint32_t / sample)

```cpp
// Word 0 (bus cycle)
//   [15: 0] = AB    address bus 16-bit
//   [23:16] = DB    data bus 8-bit (DO if WE=1, DI if WE=0)
//   [24]    = WE    write enable
//   [25]    = SYNC  instruction fetch pulse
//   [26]    = reset
//   [31:27] = spare

// Word 1 (register snapshot)
//   [ 7: 0] = A
//   [15: 8] = X
//   [23:16] = Y
//   [31:24] = SP
```

PC, flags, and state are provided via separate APIs (`get_pc()`, etc.).

| Function | Role |
| --- | --- |
| `sim_init()` | Initialize CPU, clear RAM, load ROM, assert reset |
| `step()` | Advance one clock |
| `step_instruction()` | Run until next SYNC (single instruction step, max 20 clocks) |

### 9.3 xterm.js Integration

Loaded from CDN (xterm.js 5.x). This is a browser terminal emulator licensed under MIT, also used in VS Code's built-in terminal and GitHub Codespaces.

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/xterm/css/xterm.css" />
<script src="https://cdn.jsdelivr.net/npm/xterm/lib/xterm.js"></script>
```

```javascript
const term = new Terminal({ cols: 40, rows: 24 });
term.open(document.getElementById('terminal'));

// Keyboard → 6502 (uppercase conversion + 7-bit)
term.onData(s => {
    const code = s.toUpperCase().charCodeAt(0);
    Module._send_key(code);
});

// 6502 → screen output (polling via requestAnimationFrame)
function pollDisplay() {
    while (Module._get_display_count() > 0) {
        const ch = Module._get_display_char();
        if (ch === 0x0D) term.write('\r\n');   // CR → CRLF
        else term.write(String.fromCharCode(ch));
    }
    requestAnimationFrame(pollDisplay);
}
```

#### 9.3.1 Apple-I Specific Notes

| Item | Details |
| --- | --- |
| Character encoding | 7-bit ASCII uppercase only (bit7 is strobe flag) |
| Input conversion | Use `toUpperCase()` + `charCodeAt(0)` to fit in 7 bits |
| Line ending | Apple-I outputs CR (`$0D`) only. xterm expects `\r\n`, so convert `\r` → `\r\n` |
| Backspace | Apple-I uses `_` (`$DF`) as BS. In xterm, erase the character with `\b \b` |

#### 9.3.2 Communication with Web Worker (without SharedArrayBuffer)

```text
[Web Worker]                    [Main Thread]
  step() loop  → postMessage({type:'char', ch}) → term.write()
               ← postMessage({type:'key',  code}) ← term.onData()
```

In environments where SharedArrayBuffer is available, the ring buffer can be shared for zero-copy transfer.

## 12. Technical Issues and Notes

### 12.1 AB One-Cycle Delay

Because AB is `output reg`, data from `DI = memory_read(top->AB)` in the harness reaches the CPU on the **next** posedge after the one that registered AB.
This matches the actual 6502 behavior (address output → data bus settles → latch on next cycle), so it is correct.

### 12.2 Valid Timing of WE / DO

AB and DO are registered simultaneously on the posedge when WE is High.
Checking `top->WE` after `clk=1 → eval()` and then performing the write is correct.

### 12.3 Applying `/* verilator public */`

Verilator makes public-annotated signals accessible as `top->u_cpu->signal_name`.
Confirm the exact names by opening `cpu_65c02.v`, then add the annotations in Step 2.

### 12.4 Obtaining Opcode via SYNC

```cpp
// Inside harness.cpp (after posedge in step())
if (top->o_sync) {
    last_opcode = top->o_do;  // During SYNC cycle, DI (not DO) is correct
    // Strictly speaking, save the DI value (already read by memory_read)
}
```

### 12.5 Safety Limit for step_instruction()

The longest 65C02 instruction takes 7 cycles. Set the limit to 20 to prevent infinite loops.

```cpp
EMSCRIPTEN_KEEPALIVE void step_instruction() {
    int guard = 0;
    do { step(); } while (!top->o_sync && ++guard < 20);
}
```

### 12.6 Handling Verilator Warnings

Suppress warnings from `casex` usage with `-Wno-CASEX`.
Handle `1'bx` assignments with `--x-assign fast`.
