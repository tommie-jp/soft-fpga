# 65. 8080 テスト拡充の提案（ギャップ分析）

「8080 のテストで追加すべきものは何か（例: CP/M 全標準コマンドの実行テスト）」への回答メモ。
現状のテスト資産を実コードで確認したうえでのギャップ分析と優先度。

## 1. 現状のカバレッジ（既にある強み）

| 層 | テスト | 内容 |
|----|--------|------|
| 命令正確性 | `test/test_all.asm` 20 グループ | 全レジスタ・全条件分岐・RST を網羅。OUT で P/F 出力 |
| 命令正確性 | 8080EX1（`--exec 8080EX1`） | CRC ベースの定番エクササイザ。実機等価検証 |
| タイミング/信号 | Vitest 418 件（`timing/` 331 + `signals/` 87） | T-state 数・マシンサイクル数・各サイクル T 数・レジスタ・フラグ・バス信号 |
| システム | `--boot-test` / `--ddt-ctrlc-test` | CP/M ブート、DDT Ctrl+C ウォームブート |
| UI | Playwright | LA・WASM FS・docs・copy/paste・sim API |
| RTL | cocotb（`verif/cocotb/06-8080/test_8080_timing.py`） | cpm_top の f1/f2 二相クロック・SYNC タイミング |

### 1.1 マシンサイクル/T-state は既にテスト済み

`timing/` の `expectTiming()` は `machineCycles`・`totalTStates`・各サイクルの `perCycle` を
アサートしている（SYNC 立ち上がりエッジで分割する `groupByMachineCycle` 方式）。
「命令ごとに何マシンサイクル・何 T-state か」は網羅済みで、ここは堅い。

### 2.5 M-CYC フィールドのクロスチェック（低・おまけ）

ring buffer の `mcycle` フィールド（vm80a の `m1`〜`m5` を 1..5 にエンコード）には
アサートが無い。ただしマシンサイクル数・境界は SYNC 方式（§1.1）で既にカバー済みのため、
「SYNC 由来」と「m1..m5 由来」の 2 経路が一致するかのクロスチェックにとどまる。致命的な穴ではない。

## 3. 割り込みはテストできるか

vm80a は割り込み・HLT を完全実装（`pin_int` / `pin_inte`、内部 `intr/inta/inte`、
`sy_hlta = id_hlt`）。一方 **cpm_top.v は `pin_int(1'b0)` 固定**で外部割り込み経路を殺している
（CP/M は割り込み不要なので妥当）。対象により 3 段階。

| 対象 | 現状 | テスト方法 |
|------|------|-----------|
| RST 命令 | ✅ 済 | `test_all` G20 / Vitest |
| EI/DI・INTE | ✅ 済 | `test_all` G16。INTE は `dbg_inte` で観測 |
| HLT 停止 | △ | `dbg_hlta`（`status[3]`）を 1 本追加すれば Vitest で可 |
| INT→INTA→ベクタ | ❌ cpm_top 経由 / ✅ cocotb | **vm80a を直接 DUT にして cocotb でテスト** |

### 3.1 外部割り込みシーケンスの実現方法

- **方式 A（推奨）**: vm80a を直接 toplevel にして `dut.pin_int` を制御。
  INT アサート → 現命令完了 → INTA サイクルで `sy_inta` 確認 → データバスに `RST n` 供給 →
  ベクタへジャンプ、という 8080 割り込みの教科書的シーケンスを検証。cpm_top を汚さない。
- **方式 B**: cpm_top にテスト用 INT 経路を追加。本番経路（CP/M）に手が入るため非推奨。
- 既存 cocotb テストが cpm_top と vm80a.v の両方を `VERILOG_SOURCES` に持つため、土台はある。

### 3.2 HLT 可視化の補足

`status` バイトの INTA(bit0)/HLTA(bit3) は現状 ring に出していない（出しているのは INP/OUT のみ）。
HLT を可視化・アサートするには cpm_top に `dbg_hlta = status[3]` を 1 本追加するのが筋。

## 4. 残作業と優先順位

1. **割り込み**（§3）── `dbg_hlta` 追加 + HLT の Vitest（小）→ cocotb で外部割り込みシーケンス（方式 A）
2. 既存ソフト起動スモーク・M-CYC クロスチェック（§2.4 / §2.5）── 余力があれば

§2.1（CP/M コマンド）と §2.2（8080PRE）は実装済みのため着手不要。
