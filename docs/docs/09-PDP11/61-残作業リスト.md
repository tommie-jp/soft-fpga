**アーキテクチャ**: 式文字列 → `_trigParse`（UI）→ `trigCompileToWasm`（UI）→ `postMessage` → Worker 内で `new WebAssembly.Instance` → simLoop 毎フレームに全新着サンプルを Wasm ネイティブ評価（≈ 2–5 ns/sample）。Expr Set 時に `ring_tick_mask=0`（毎 tick サンプリング）へ自動切り替え。

**信号対応状況**:

| 比較種別 | 対応信号 | 非対応 |
|---------|---------|-------|
| 数値比較 `== != < > <= >=` | 全信号（VA, PC, RD, Mode, istate, ISN, PSW, R0-R5 等） | Cycle（仮想信号） |
| 文字列比較 | `Mode == "USER"/"KERNEL"/"SUPER"`, `istate == "F1"/"C1"` など | `ISN == "MOV …"`, `PSW == "…"`, `Cycle == "FETCH"` |
| エッジ検出 `.rising/.falling/.edge` | 全非仮想信号 | Cycle（仮想信号） |

**Cycle / ISN 文字列 / PSW 文字列の代替式**:

| やりたいこと | 代替式 |
|------------|-------|
| `Cycle == "FETCH"` | `RD.rising && istate == "F1"` |
| `Cycle == "MEM_RD"` | `RD == 1 && istate != "F1"` |
| `ISN == "CLR R1"` | `ISN == 0o5001` |
| `PSW` フラグ確認 | `PSW == 0o0340`（数値） |

**残課題**: Cycle（仮想信号）・ISN 文字列・PSW 文字列に対して Worker 内 JS フォールバック（`importScripts` + `_trigEvalExpr`）を追加すれば完全対応できる。現状はコンパイルエラーを表示して代替式を案内している。

harness.cpp の ring buffer Word3 に既に収録済みだが `sft-pdp11-la-defs.js` に信号定義がない。

| 信号 | Word3 ビット | 意味 |
|------|------------|------|
| `waited` | [18] | CPU バス待ちストール |
| `iopage_access` | [20] | I/O ページアクセス |
| `mmu_on` | — | MMR0[0]（MMU 有効化タイミング、要 obs 追加） |

- 変更: `js/sft-pdp11-la-defs.js`
