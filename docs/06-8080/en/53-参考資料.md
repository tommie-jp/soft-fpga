# 53. References

External resources useful for understanding soft-FPGA (particularly the Altair 8800 / 8080
configuration) and the CP/M implementation.

Recommended reading order: **Tsue-yasu series → Section 5 original → Grant Searle → Qiita boot guide**

---

## 1. Understanding the Minimum Requirements (Japanese)

### Tsue-yasu "Building an 8080 Emulator and Running CP/M-80" (5 parts)

→ <https://tsueyasu.com/2024/08/11/...> (Part 1 through Part 5)

Written specifically about implementing **just four BIOS calls to run a large number of
CP/M-80 applications**, giving concrete insight into the bare minimum BIOS implementation.

- Written for emulators, but applies directly to soft-FPGA for determining "what to
  implement in hardware vs. what to delegate to ROM / monitor."
- Covers CBIOS.ASM source acquisition, disk image creation with cpmtools,
  and the 62K→64K patch, all in one place.

---

## 2. The FPGA Implementation Standard (English)

### Grant Searle "Multicomp" CP/M Page

→ <http://searle.hostei.com/grant/Multicomp/cpm/fpgaCPM.html>

The canonical reference for building a full CP/M 2.2 machine on a low-cost FPGA board
using Z80. Covers boot ROM, BIOS, formatter, system transfer, and file transfer program
design and implementation.

- Z80-based, but the memory map, ROM-off mechanism (write to port 38H), and
  serial + SD card configuration translate almost directly to an 8080.
- The first place to look when building a CP/M-capable machine with soft-FPGA.

### JeeLabs "Building a MultiComp-based Z80"

Written from the perspective of actually assembling Grant Searle's design; easy to
follow as an introduction to building a full-scale CP/M system on FPGA.

## 3. Address 0 Problem and Boot Sequence

### Qiita "Various CP/M Notes" (yamori813)

The 8080 / Z80 starts execution at address 0 after reset, but CP/M requires the first
disk sector to be loaded into RAM at address 0. This article explains how that was handled:

- Manual entry via front-panel switches
- DMA
- Logic that switches to RAM at address 0 after ROM boot

Essential reading for understanding how to handle the boot ROM / front-panel equivalent
when reproducing an Altair 8800.

## 4. Official CP/M Structure Reference (Primary Source)

### gaby.de "Section 5: CP/M 2 System Interface"

→ <http://www.gaby.de/cpm/manuals/archive/cpm22htm/ch5.htm>

CP/M is logically divided into four parts: BIOS, BDOS, CCP, and TPA. The BIOS is
a hardware-dependent module; the explicit procedure for field-rebuilding the standard
BIOS supplied by Digital Research is described in Section 6. Keep this as the primary reference.

## 7. CPU Timing and M-Cycle / T-State Reference

### Intel 8080 Data Sheet (Official Primary Source)

→ <https://deramp.com/downloads/intel/8080%20Data%20Sheet.pdf>

The top reference for bus timing research.

- **Table 2-4** — Full instruction list with M-cycle count, T-state count, and byte count
- **Figure 2-2 through 2-4** — Timing waveforms for SYNC / DBIN / WR_N
- **Status Byte definition** — Bit patterns driven on `cpu_dout` when SYNC=1 at T1
  (`0xA2`=FETCH, `0x82`=MEMR, `0x00`=MEMW, `0x10`=OUT, etc.)

### Intel 8080 Opcodes Table

→ <https://pastraiser.com/cpu/i8080/i8080_opcodes.html>

Color-coded table of all instructions with byte count and cycle count.
Useful when writing T-state test cases.

### GeeksforGeeks — MVI Instruction Timing Diagram

→ <https://www.geeksforgeeks.org/timing-diagram-mvi-instruction/>

Explains the Opcode Fetch (M1: T1–T4) and Operand Read (M2: T5–T7) with
waveform diagrams using MVI A as an example.
**The movement of the 8080-specific SYNC signal can be verified visually.**

### Key Points Summary

| M-cycle Type | T-states | Notes |
|-------------|----------|-------|
| Opcode Fetch (M1) | 4T | SYNC=1 appears at T1 |
| Memory Read | 3T | Operand read, etc. |
| Memory Write | 3T | |
| I/O Read / Write | 3T | |

vm80a implementation note: SYNC goes High during **both f1 and f2 phases** of T1,
so detect M-cycle boundaries on the SYNC rising edge (0→1 transition) in the ring buffer.
See [26-Vitestタイミングテスト.md](26-Vitestタイミングテスト.md) §3.2 for details.

## 8. rtlscope Design Application

The purpose of reading these references is to design a system that **visualizes which
I/O ports are accessed at the moment of each BIOS call, using the I/O Bus Analyzer**.

- Tsue-yasu series: understand the I/O port mapping for CONIN / CONOUT / READ / WRITE
- Section 5 original: confirm BIOS jump table entry numbers and meanings
- Grant Searle: cross-check the memory map and ROM-off mechanism
- Qiita article: identify the address-0 switchover timing in the boot sequence

With all of these, you can read what is happening at each clock cycle on the Analyzer.
