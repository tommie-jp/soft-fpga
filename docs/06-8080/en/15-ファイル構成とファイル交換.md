# 15. File Layout and Host File Exchange

This document summarizes where files used by the `cpm` command
(Intel 8080 / CP/M 2.2 soft-FPGA simulator) are located,
and how to transfer files between CP/M and the host Ubuntu system.

## 1. Directory Layout

```text
examples/06-8080/               ← sub-project root
├── CMakeLists.txt              ← build definition (output: build/cpm)
├── cxx/
│   ├── harness.cpp             ← Verilator harness · I/O port handling
│   └── main_linux.cpp          ← Linux entry point · argument parsing · path resolution
├── verilog/
│   ├── cpm_top.v               ← top module (RAM · I/O bus)
│   └── vm80a/                  ← Intel 8080 RTL (sub-module)
├── rom/
│   └── cpm22.bin               ← CCP + BDOS binary (5632 B)
│                                  derived from RunCPM's CPM22.SYS
├── sw/cpm/
│   ├── bios/
│   │   ├── bios.asm            ← custom BIOS source (z80asm)
│   │   └── bios.bin            ← pre-built BIOS binary
│   └── disks/
│       └── cpm22.dsk           ← CP/M disk image (IBM 3740: 256 KB)
│                                  contains ED.COM / PIP.COM / DDT.COM etc.
├── test/
│   ├── test_all.bin            ← bare-metal integration test binary
│   └── 8080ex1_bare.bin        ← 8080 instruction exerciser (bare-metal)
└── build/                      ← cmake build directory
    └── cpm                     ← executable binary
```

## 2. Path Resolution at Startup

`cpm` locates each file relative to the directory **one level above** its own binary.

```text
executable: examples/06-8080/build/cpm
base directory: examples/06-8080/   ← parent of build/
```

| File | Default path (relative to base directory) |
|------|-------------------------------------------|
| BIOS | `sw/cpm/bios/bios.bin` |
| CCP+BDOS | `rom/cpm22.bin` |
| Disk image | `sw/cpm/disks/cpm22.dsk` |
| Test binary | `test/test_all.bin` |

A different path can be specified via command-line options
(see [14-cpm-コマンド説明.md](14-cpm-コマンド説明.md)).

## 3. CP/M Memory Map (at Boot)

```text
$FFFF ┬──────────────────────────────
      │  BIOS (custom)               ← bios.bin loaded at $F200
$F200 ├──────────────────────────────
      │  BDOS                         ┐
$E400 ├──────────────────────────────  ├ cpm22.bin loaded at $DC00
      │  CCP                          ┘
$DC00 ├──────────────────────────────
      │  TPA (Transient Program Area)  ← .COM files loaded here
$0100 ├──────────────────────────────
      │  Page 0 (vectors · BDOS entry)
$0000 ┴──────────────────────────────
```

## 4. File Exchange with the Host

### 4.1 cpmtools (reliable today · no additional implementation needed)

Operate the DSK image directly from the host while CP/M is **stopped**.

```bash
# Host → CP/M disk
cpmcp -f ibm-3740 sw/cpm/disks/cpm22.dsk ./hello.asm 0:HELLO.ASM

# CP/M disk → Host
cpmcp -f ibm-3740 sw/cpm/disks/cpm22.dsk 0:RESULT.TXT ./result.txt

# List files on disk
cpmls -f ibm-3740 sw/cpm/disks/cpm22.dsk
```

> **Warning**: Manipulating the DSK file while `cpm` is running may corrupt its contents.
> Always stop CP/M with `Ctrl+\` before using these commands.

### 4.2 `--exec` Flag (CP/M → Host, text files only)

```bash
# Extract a text file to the host
./build/cpm --exec "TYPE RESULT.TXT" > result.txt

# Extract an ASM source file
./build/cpm --exec "TYPE PROG.ASM" > prog.asm
```

- Transfer in the Host → CP/M direction is not supported.
- Binary files must not be used here because CONOUT garbles non-text data.

### 4.3 R / W Commands (while CP/M is running · already implemented)

The disk image includes `R.COM` / `W.COM` (custom utilities v1.0).
They signal the host via I/O port `$A1h`; `harness.cpp` handles them in
`handle_io` / `read_io`.

```text
A>R SOURCE.ASM      ← copy a file from the host PC to the CP/M disk
A>W OUTPUT.TXT      ← copy a file from the CP/M disk to the host PC
```

- Files are read from / written to the current working directory of the `cpm` process.
- Filenames must follow CP/M conventions (uppercase letters, digits, symbols;
  no underscores; 8+3 characters maximum).
- See [12-CP_M-コマンドリファレンス.md](12-CP_M-コマンドリファレンス.md) for details.

#### Why STAT shows "1k" after an R command

R.COM reads host files in **128-byte units (1 sector)**.
CP/M disk allocation is in **1 KB units (allocation block = 8 sectors)**,
so even a file that is only a few bytes long shows a minimum of "1k" in `STAT`.
This is normal.

```text
Host file 6 B → DMA buffer 128 B (6 B real data + 122 B zero-fill)
              → CP/M disk 1 KB (1 allocation block)
STAT: "Recs 1  Bytes 1k"  ← file contents are stored correctly
```

When extracting with the W command, data is also written in 128-byte units,
so trailing zero bytes may appear. For text files, use `TYPE` to view only the
actual content.

### 4.4 Method Comparison

| Method | Host→CP/M | CP/M→Host | While running | Extra work |
|--------|:---------:|:---------:|:-------------:|:----------:|
| **cpmtools** | yes | yes | no — must stop | none |
| **--exec** | no | yes (text only) | no | none |
| **R/W commands** | yes | yes | yes | already done |

## 5. Build Instructions

```bash
cd examples/06-8080
cmake -B build
cmake --build build
# → build/cpm is created
```

Dependencies: Verilator, C++17 compiler.
