# 66. 命令エクササイザ追加方針

[65-8080テスト拡充の提案.md](65-8080テスト拡充の提案.md) §2.2「別系統の命令エクササイザ」の
実装方針と過去の知見を記録する。

## 1. 対象と範囲

| エクササイザ | 採否 | 理由 |
|------------|------|------|
| `8080PRE.COM` | ✅ 実装 | ソース (`verilog/vm80a/tst/8080pre.asm`) 既存、低コスト |
| `CPUTEST.COM` | ❌ スコープ外 | Supersoft 商用ソフト・入手困難。8080PRE + 8080EX1 で命令前段は十分カバー |

## 2. 実行モード選択：`--exec` vs `--run-test`

`8080pre.asm` は `org 0h`（ベアメタル）で書かれているが、**CP/M 版 (`org 0x0100`) に変換して
`--exec 8080PRE` で実行する**。理由は以下の通り。

| 観点 | `--run-test`（ベアメタル） | `--exec`（CP/M） |
|------|--------------------------|----------------|
| 既存パターン | `test_all.bin` 一択 | `8080EX1.COM` で確立済み |
| 成功検出 | P/F 文字カウント | "Tests complete" 文字列検出 |
| ファイル管理 | `test/` 以下 `.bin` | `sw/cpm/disks/cpm22.dsk` に追加 |
| 失敗レポート | 出力なし → groups=0 でFAIL | タイムアウト or ERROR 文字列 |

**結論**:  `--exec` の方が 8080EX1 と同一インフラで完結し、BDOS 呼び出しもそのまま動くため採用。

## 3. `8080pre_cpm.asm` 変換方針

`sw/cpm/8080ex1_cpm.asm` を手本に最小変更で変換する。

### 3.1 変更点（3 箇所のみ）

1. **ORG とスタック**: `org 0h` → `org 0x0100`、先頭に `lxi sp, 0x7F00`
2. **`allok:` を成功出力に置換**: `lxi H, 0FFFFh; ...` を削除し、
   "Tests complete\r\n" を `OUT 0x01` で出力してから `ret`
3. **コメント更新**: ビルド手順を `z80asm --output=8080PRE.COM 8080pre_cpm.asm` と明示

### 3.2 失敗パスの扱い

既存の `jmp fault+$`（`fault equ 8000h`）は CP/M 環境で CP/M 外アドレスへのジャンプとなり、
BIOSウォームブートアドレス付近を踏む。出力なしで終了するため `--exec` はタイムアウト→FAIL
と正しく判定する。**明示的なエラー出力変更は不要**。

## 4. ビルドとディスク追加

```bash
# アセンブル
z80asm --output=sw/cpm/8080PRE.COM sw/cpm/8080pre_cpm.asm

# cpm22.dsk に追加
cpmcp -f ibm-3740 sw/cpm/disks/cpm22.dsk sw/cpm/8080PRE.COM 0:8080PRE.COM
```

ディスク追加は `test/Makefile` の `disk` ターゲットに組み込む（または手動管理）。

## 5. テストスクリプト追加

`scripts/_test-8080-cpm-inner.sh` に `run_test` 1 行を 8080EX1 の直後に追加するだけ。

## 6. Playwright トリガーの信頼性注意点

`type="reg", regId=9`（PC 値トリガー）は **vm80a 内部の `tree0` レジスタが 1 のタイミングで
`setPC()` が処理されると、最初の rising edge で PC が即座に +1 されてトリガー発火チャンスを逃す**。
HLT で停止するコードでは PC が目標アドレスに戻らないため 60 秒待っても発火しなかった。

### 対処法

| 状況 | 推奨トリガー |
|------|------------|
| 特定 PC で命令フェッチを検出したい | `type="instr", pc=0xXXXX`（SYNC エッジ起点で確実） |
| PC=0xXXXX を `type="reg"` で検出したい | **ループプログラム**にして PC=0xXXXX が繰り返し現れるようにする |
| レジスタ値（A/F/BC など）で停止したい | `type="reg"` + 値が安定して保持されるレジスタを選ぶ |

`type="reg"` で PC を使う場合は `JMP <target>` でループさせるか、発火後も PC が循環するコードを
書くこと。`test_trigger_fires_on_pc` はこの方針で修正済み（[コミット 5cec2a0](../COMMITS)）。
