## 1. 実装の最小要件を理解する（日本語）

### 末安泰三氏「8080 エミュレータを作って CP/M-80 を動かす」（全 5 回）

→ <https://tsueyasu.com/2024/08/11/...>（その 1〜その 5）

CBIOS.ASM をベースに、**4 つの BIOS コールをエミュレートするだけで多数の CP/M-80
アプリが動作する**という、最小限の BIOS 実装の勘所が具体的に書かれている。

- エミュレータ向けの記事だが、soft-FPGA でも「どこまでをハードウェアで実装し、
  どこからを ROM / モニタに任せるか」の境界線を見極めるのにそのまま使える。
- CBIOS.ASM の入手先、cpmtools でのディスクイメージ作成、62K→64K 化のパッチまで
  一通り揃っている。

## 2. FPGA 実装の正典（英語）

### Grant Searle "Multicomp" CP/M ページ

→ <http://searle.hostei.com/grant/Multicomp/cpm/fpgaCPM.html>

低コストな FPGA ボードでフル CP/M 2.2 を動かす Z80 機を構築する方法を示す定番資料。
Boot ROM・BIOS・フォーマッタ・System Transfer・File Transfer プログラムの設計・実装を含む。

- Z80 前提だが、メモリマップ・ROM オフ機構（port 38H 書き込み）・シリアル + SD カード
  構成は 8080 でもほぼそのまま流用できる。
- soft-FPGA で CP/M 対応機を作る際にまず参照する定番。

### JeeLabs "Building a MultiComp-based Z80"

Grant Searle の設計を実際に組み立てる視点で書かれており、FPGA でフル規模の CP/M
システムを構築する過程が追える。入門としてはこちらの方が読みやすい。

## 3. 0 番地問題と起動シーケンス

### Qiita「CP/M いろいろ」（yamori813 氏）

8080 / Z80 はリセット後 0 番地から実行を開始するが、CP/M はディスクの最初のセクタを
0 番地の RAM に貼り付ける必要がある。この処理が

- スイッチでの手打ち
- DMA
- ROM 起動後に RAM が 0 番地に切り替わるロジック

で処理されていたことのポイントを解説。Altair 8800 を再現する場合のブート ROM /
フロントパネル相当の扱いを考える上で重要。

## 4. CP/M 公式構造リファレンス（原典）

### gaby.de "Section 5: CP/M 2 System Interface"

→ <http://www.gaby.de/cpm/manuals/archive/cpm22htm/ch5.htm>

CP/M は BIOS・BDOS・CCP・TPA の 4 部に論理分割される。BIOS はハードウェア依存
モジュールであり、デジタルリサーチから提供される標準 BIOS をフィールドで再構成する
明示的な手順が Section 6 に記載されている。一次資料として手元に置いておく。

## 7. rtlscope 設計上の活用ポイント

これらの資料を読む目的は、**「BIOS コールの瞬間にどの I/O ポートが叩かれているか」
を I/O Bus Analyzer で可視化する設計**を考えることにある。

- 末安氏のシリーズで CONIN / CONOUT / READ / WRITE の I/O ポートマッピングを把握
- Section 5 原典で BIOS ジャンプテーブルのエントリ番号と意味を確認
- Grant Searle でメモリマップと ROM オフの仕組みを照合
- Qiita 記事でブートシーケンスの 0 番地切り替えタイミングを特定

これらが揃うことで、どのクロックサイクルで何が起きているかを Analyzer 上で読めるようになる。
