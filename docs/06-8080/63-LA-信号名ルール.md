# 63. Logic Analyzer 信号名ルール

## 1. 基本方針

Logic Analyzer (LA) の信号レーンには、性質の異なる信号が混在する。
混乱を防ぐため、**実 Intel 8080A ピンに直接対応する信号** のラベルには
`pin_` プレフィックスを付ける。

| カテゴリ | ラベル規則 | 例 |
|---|---|---|
| 実 8080A 出力ピン（vm80a が直接公開） | **`pin_` プレフィックス付き** | `pin_WR_N`, `pin_SYNC` |
| harness 合成信号（実ピンにない） | プレフィックスなし | `io_req`, `io_wr` |
| バス信号（harness がラッチ・合成） | プレフィックスなし | `addr`, `dbus`, `din` |
| 外部デコード信号 | プレフィックスなし | `memr`, `memw` |
| CPU 内部状態 | プレフィックスなし | `ir`, `t_state`, `status` |
| vm80a 内部フェーズ | プレフィックスなし | `f1`, `f2` |

> **注意:** `id` フィールドは変更しない。変更するのは LA 表示用の `label` フィールドのみ。
> これにより harness.cpp / test_timing_ss.py / ring.mjs への影響をゼロに保つ。

---

## 2. `pin_` を付ける信号（実 8080A 出力ピン）

以下の 6 信号は vm80a が `pin_*` として直接出力しており、
実 8080A データシートのピンに 1 対 1 対応する。

| LA `id` | `label` | vm80a ポート | 8080A ピン名 |
|---|---|---|---|
| `dbin` | `pin_DBIN` | `pin_dbin` | DBIN |
| `sync` | `pin_SYNC` | `pin_sync` | SYNC |
| `wr_n` | `pin_WR_N` | `pin_wr_n` | WR̄ |
| `hlda` | `pin_HLDA` | `pin_hlda` | HLDA |
| `wait` | `pin_WAIT` | `pin_wait` | WAIT |
| `inte` | `pin_INTE` | `pin_inte` | INTE |

---

## 3. `pin_` を付けない信号と理由

### 3.1 合成信号（harness が生成）

| LA `id` | 理由 |
|---|---|
| `io_req` | cpm_top.v が合成する 1 クロックパルス。実 8080 バスに存在しない |
| `io_wr` | cpm_top.v が合成。`io_req` と同様 |
| `port` | harness が `io_addr` / `io_port` からラッチした値 |
| `data` | harness が `io_dout` / `io_din` を選択して提示 |

### 3.2 バス信号（harness がラッチ・複数ソースを合成）

| LA `id` | 理由 |
|---|---|
| `addr` | 実ピンは `pin_a[15:0]`（A15–A0）だが、harness が SYNC タイミングでラッチ補正している（vm80a は T2 以降アドレスバスを 0 にするため） |
| `dbus` | MEMR=RAM 読み値 / MEMW=cpu_dout / IO IN=io_din を harness が選択合成 |
| `din` | IO IN 時の `pin_din` 値だが、harness の `read_io()` が書き込む |

### 3.3 外部デコード信号（実 8080 バスではデコード IC が生成）

| LA `id` | 理由 |
|---|---|
| `memr` | `!cycle_io && dbin` を cpm_top.v が合成 |
| `memw` | `!cycle_io && !wr_n` を cpm_top.v が合成 |

### 3.4 CPU 内部状態（ピンには出ない）

| LA `id` | 理由 |
|---|---|
| `ir` | 命令レジスタ（CPU 内部） |
| `t_state` | T ステートカウンタ（harness が管理） |
| `status` | SYNC 時にデータバスへ出力されるバイトを harness がラッチ |
| `pc`, `sp`, `acc`, `reg_*` | CPU 内部レジスタ |

### 3.5 vm80a 固有フェーズ信号

| LA `id` | 理由 |
|---|---|
| `f1` | vm80a への **入力**（cpm_top.v が生成）。実 8080A にこのピンはない |
| `f2` | 同上 |

> 実 8080A は CLK 1 本のみ。`f1` / `f2` は vm80a が内部の 2 相クロック動作を
> シミュレートするための実装都合の信号であり、実チップには存在しない。

---

## 4. 実 8080A 入力ピンの LA 対応

実 8080A の入力ピンは、このシミュレーターでは定数なので LA に出していない。

| 8080A 入力ピン | 値 | LA |
|---|---|---|
| INT | 常に 0（割り込みなし） | なし |
| HOLD | 常に 0（DMA なし） | なし |
| READY | 常に 1（ウェイトなし） | なし |
| RESET_IN | 起動時のみ | なし |
| CLK | 一定クロック | なし |

---

## 5. raw ピン信号の追加について

`addr`（harness ラッチ済み）に加えて、vm80a の生 `pin_a` を表示する `pin_ADDR` を
追加する案も検討したが、以下の理由で **見送り**。

- vm80a は T2 以降 `pin_a` を 0 にする（実 8080A と異なる挙動）ため、
  `pin_ADDR` raw を表示すると学習者が混乱する可能性がある
- ring buffer に Word 7 追加が必要（harness.cpp / index.html の変更コスト）
- `addr`（latched）が実 8080 の正しい仕様を反映しており学習用途には十分

`dbus` / `din` についても同様の理由で raw ピン版は追加しない。
