Reversi UART Protocol (RUP) v0.2 ドラフト

自作 CPU を PC につなぐ、UART 上の約束事

github.com/tommie-jp/reversi-uart-protocol
仕様書（日本語・英語）、状態遷移図、設計判断の背景、検討事項。Issue でも意見を受け付けます。

何を決めたか

  • コマンドは大文字 2 文字、行末は CR+LF。シリアル端末で手打ちして試せる。
  • 応答は+（成功）／-（エラー）の 1 文字で見分ける。印のない行は CPU 自身の通知（着手など）。
  • 必須は受信 9 種・送信 4 種だけ。BO など残りは任意で、読み飛ばしてよい。

プロトコルを決めるとできること

  • 大会に持ち寄った自作 CPU を、同じ PC 側プログラムにつないで対局できる。
  • CPU 側と PC 側を、別々の人が仕様書だけで作れる。
  • 端末ソフトで手打ちして確かめられ、pyserial などで自動試験もできる。

1 局の流れ（仕様書 §10 の抜粋）

<PIPING（起動・生存確認）
>+PIPI 成功応答
<VEVERSION 問い合わせ
>+VE02MyCPU-v1VE 成功応答（先頭 2 桁はプロトコルバージョン）
<SBSTART BLACK（黒先攻・初手要求）
>MOf5MOVE f5（CPU 自発の着手）
<MOd6MOVE d6（相手着手通知）
…（以下、手番ごとに交互）
>ENEND（CPU 自発の投了・終局）

< PC→CPU　> CPU→PC　行末の CR LF は省略

必須コマンド

方向書式意味
PC→CPUSB SWあなたは黒（先攻）／白
MOd3相手が d3 に置いた
PA相手がパス
EB EW ED終局（黒勝ち／白勝ち／引分）
VE PIバージョン／生存の問い合わせ
CPU→PCMOd3 PA着手／パス
+PI +VE02…問い合わせへの成功応答
-00仕様違反を受けたときの応答（固定で可）
PC 側の例: tommieChat のオセロ対戦画面

意見をください（仕様はまだ決まっていません）

  1. 合法手があるのに CPU が PA を返してきた。PC はパスとして通すか、不正応答にするか。
  2. 対局中に SB / SW が届いた。現対局を捨てて新規にするか、無視するか。
  3. 自分の手番中に PA（相手パス通知）が届いた。無視するか、-06 を返すか。

デモ机soft‑FPGA × WebAssembly

Verilog で書いたレトロ CPU を Verilator で C++ にし、WebAssembly にしてブラウザで動かします。命令エミュレータでは見えない内部信号（T‑state、バスサイクル、状態遷移）をリアルタイムに観測できるのが取り柄です。

  • 6502 / Apple‑I（wozmon → Integer BASIC）
  • 8080 / CP/M 2.2（MBASIC、BDS C、ゲーム）
  • PDP‑11 / Unix V6（MMU、ロジックアナライザ表示）

デモ机では 6502 / Apple‑I を Raspberry Pi Pico 2 の実機でも動かします（当日の状況により Wasm 版）。

部品管理QR Note

部品に貼った QR シールをスマホで読むと、その部品のノート（特性表、回路図、メモ）が開きます。部品が増えても、読み取るだけで該当ノートにたどり着けます。

  • 数式・回路図・図表の記法、シールの印刷

回路図tommie‑fence

Markdown のコードフェンスに YAML で部品と配線を書くと、回路図、ブレッドボードの実体配線図、ユニバーサル基板の配線図、銅張り基板の寸法図になります。回路図と実体配線図を同じ記法で並べて描けます。

  • 何も入れずにブラウザで試せる playground
  • VS Code 拡張（.vsix）をリリースで配布

図の流儀（信号は左から右、電位の高いほうが上、など）を Claude 用の skill 集にもしています。
