# 実装計画：01-counter

## 1. 方針

- 8 ビット二進カウンタ（clk / rst / count のみ）
- メインスレッド直実行（Worker・SharedArrayBuffer は後回し）
- `requestAnimationFrame` 1 本で step × N ＋ 描画（`setInterval` は使わない）
- Logic Analyzer は 06-8080 / 09-pdp11 と同じ共通ライブラリ [`js/rtlscope-la.js`](../../js/rtlscope-la.js)（RTLScopeLA）を使う
- Freeze・トリガー・LA ON/OFF は CPU 非依存の共通部品（[`cxx/rtlscope_ring.h`](../../cxx/rtlscope_ring.h)・
  [`js/sft-la-ctrl.js`](../../js/sft-la-ctrl.js) ほか）に切り出し、02〜05 でも同じものを使う（[91 章](../91-rtlscope-la-LogicAnalyzerライブラリ.md)）
- Docker は不要（ホスト直インストールの Verilator ＋ Emscripten を使用）

## 4. ring buffer

1 サンプル = 1 word（`RING_WORDS = 1`）、深さ 4096。1 クロックにつき 1 サンプルを記録する。

| ビット | 信号 | 内容 |
| --- | --- | --- |
| [7:0] | count | カウンタ出力 |
| [8] | rst | リセット入力（Reset ボタンで 2 クロック 1 になる） |

`reset_sim()` は履歴を消さない。rst が立つ区間と、そこから count が 0 に戻る様子を波形に残す。

## 5. エクスポート関数（C → JS）

| 関数 | 役割 |
| --- | --- |
| `sim_init()` | Vcounter 生成・初期リセット（rst 区間も 2 サンプル記録） |
| `step()` / `sim_run_n(n)` | 1 クロック / n クロック進める。`sim_run_n` はトリガー停止で打ち切る |
| `reset_sim()` | カウンタをリセットし、Freeze とトリガー発火状態を解除する |
| `get_ring_ptr()` | ring buffer の先頭アドレス（バイト） |
| `get_head()` | 書き込み済みサンプル数（ラップなし） |
| `get_ring_size()` / `get_ring_words()` | ring buffer の深さ / 1 サンプルのワード数 |
| `sim_freeze_ring()` / `sim_thaw_ring()` / `sim_ring_frozen()` | ring への書き込みを止める / 再開（Thaw はトリガーも再武装） |
| `sim_set_la(on)` | LA OFF の間は ring へ書かない（トリガー判定は継続） |
| `sim_set_edge_trigger(word, bit, dir)` | エッジトリガー（dir: 0=立ち上がり 1=立ち下がり） |
| `sim_set_value_trigger(word, mask, cmp)` | 値一致トリガー（`(w & mask) == cmp`） |
| `sim_set_post_delay(n)` | 発火後に記録するクロック数（0 = 即停止） |
| `sim_clear_trigger()` | トリガー解除 |
| `sim_trigger_hit()` / `sim_trigger_fired()` | Freeze 完了 / 発火済み |
| `sim_get_trig_fire_head()` | 発火時点の head（未発火は -1）。赤い縦線の位置になる |

API 名と意味は 06-8080 のハーネスに合わせてある。

## 6. Logic Analyzer

- 信号: count（16 進）・count10（10 進、既定は非表示）・rst・b7〜b0
- ズーム（1/4x〜64x）・パン・カーソル・マーカー A/B/C・信号チップの表示切替は RTLScopeLA が提供する
- 起動時のズームは 8x。b0 の周期と count の値が読める
- 速度スライダーで 1 フレームあたりのクロック数を 1〜2000 に変更する
- Freeze: ring への書き込みを止める。回路は動き続け、Thaw で記録を再開する
- Trigger: 信号と条件（`==`・立ち上がり・立ち下がり）を選んで Set する。発火後 post クロック記録して Freeze し、実行を一時停止する
- 例: count `==` `80`、post `100` → count が 0x80 になった前後を捕まえて停止し、赤い TRIG マーカーを表示する
- LA ON/OFF・Fill・Hatch は 06-8080 と同じ

## 8. Wasm ビルドで解決した問題

### 8.1 emsdk のパス

`~/emsdk/emsdk_env.sh` ではなく `~/emsdk/emsdk/emsdk_env.sh` が正しい。
`build-wasm.sh` は複数候補を探して自動ソースする。

### 8.2 verilated.cpp のバージョン不一致

29-project の verilated.cpp は Verilator 5.042 より新しいため API 不一致でコンパイルエラー。
ビルド時にシステムから `cxx/verilated.cpp` へコピーする方式に変更（`.gitignore` 追加）。

### 8.3 `pthread_getaffinity_np` リンクエラー

`verilatedos_c.h` がシステムの verilated.cpp 末尾でインクルードされ、
Emscripten の `<thread>` → `<pthread.h>` → `<sched.h>` 経由で `CPU_ZERO` が定義されると
Linux 用の `pthread_getaffinity_np` 呼び出しがコンパイルされてしまう。

**解決**: `cxx/verilatedos_c.h` に Wasm 向けスタブを作成し、
`-I$ROOT/cxx` をコンパイルパス先頭に追加してシステム版より優先させる。
（`getProcessAvailableParallelism` は 1 固定、`memUsageBytes` は 0 固定）

## 9. ブラウザ起動からカウンタ動作までの流れ

```text
① index.html をブラウズ
     ├─ HTML/CSS パース → ボタン・スライダー・LA ツールバー・canvas が表示される
     └─ <script> を順に実行

② インラインスクリプトが Module オブジェクトを定義
     └─ onRuntimeInitialized コールバックを登録するだけ（まだ動かない）

③ js/sft-counter-la-defs.js・js/rtlscope-la.js・js/sft-la-ctrl.js を読み込み、
   続いて sim.js を実行
     └─ Emscripten グルーが起動
          ├─ fetch("sim.wasm") で Wasm バイナリをダウンロード
          └─ WebAssembly.instantiate() でコンパイル・インスタンス化

④ Wasm ロード完了 → Module.onRuntimeInitialized() が呼ばれる
     ├─ Module._sim_init()          DUT 生成・リセットシーケンス
     ├─ RING_SIZE / RING_WORDS / ringBase を取得
     ├─ new RTLScopeLA(COUNTER_LA_CONFIG) → buildToggles() → setZoom(8x)
     ├─ initLaCtrl({ la, backend, ... })   Freeze / Trigger / LA ON-OFF を配線
     └─ requestAnimationFrame(loop) を最初の 1 回だけ呼ぶ

⑤ 毎フレーム loop() が呼ばれ続ける（≈60Hz）
     ├─ running なら sim_run_n(speed)        トリガー発火で Freeze → 自動 Pause
     ├─ la.update(head, ringView, frozen, trigFireHead)
     │    └─ Module.HEAPU32.subarray() で ring buffer をゼロコピー参照して描画
     └─ requestAnimationFrame(loop) で自分を再予約 → ⑤ に戻る

⑥ Run ボタンを押す
     └─ running = true → ⑤ の sim_run_n() が実行されカウンタが動き出す
```

> **ポイント**: ring buffer は Wasm 線形メモリ上にあり、JS は TypedArray ビューで直接読む。
> メモリ拡張で `HEAPU32` が差し替わるため、ビューは毎フレーム取り直す。
