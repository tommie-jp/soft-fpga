# 26. 式トリガー（Expr Trigger）リファレンス <a class="qr-link" href="../../../docs/09-PDP11/26-式トリガー-リファレンス-QR.png">QR</a>

PDP-11 デバッグパネルの「式（Expr）」トリガーについて、  
構文・信号対応・内部アーキテクチャを説明する。

---

## 1. 概要

**式トリガー**は、複数の信号を任意の条件式で組み合わせて停止条件を記述できるトリガー種別。

- `PC 値一致` や組み込みトリガーでは表現できない複合条件を捕捉できる
- `VA == 06 && Mode == "USER"` のように、アドレスと CPU モードを同時指定できる
- エッジ検出（`.rising` / `.falling` / `.edge`）を信号に付けて使える

### 他のトリガー種別との比較

| 種別 | 条件 | 速度 |
|------|------|------|
| PC 値一致 | 特定の仮想アドレス（Wasm ハードウェア） | ★★★ |
| I/O ページ | I/O ページアクセス検出（Wasm ハードウェア） | ★★★ |
| Bus Error / TRAP | バスエラー・トラップ検出（Wasm ハードウェア） | ★★★ |
| **式（Expr）** | 任意の複合条件（Wasm ネイティブ評価） | ★★☆ |

---

## 2. 設定手順

1. `種別` セレクトを **`式(Expr)`** に切り替える
2. 式入力欄（CodeMirror エディタ）に条件式を入力する
   - Ctrl+Space で信号名・値の補完が使える
3. `Set` ボタンを押す
   - サンプリング間隔が自動的に **1tick/smpl** に切り替わる（後述）
4. `▶ Run` を押してシミュレーションを開始する
5. 条件が成立した瞬間に LA が停止し、`⏸ Triggered!` が表示される

## 3. 式構文リファレンス

### 3.1 比較演算子

```text
==    等しい
!=    等しくない
<     より小さい（符号なし）
>     より大きい（符号なし）
<=    以下（符号なし）
>=    以上（符号なし）
```

比較の右辺には数値リテラルまたは文字列リテラルを書く（信号によって対応が異なる）。

### 3.2 エッジ検出

```text
信号名.rising    0 → 1 の立ち上がりエッジ
信号名.falling   1 → 0 の立ち下がりエッジ
信号名.edge      立ち上がり / 立ち下がりどちらも
```

例:

```text
RD.rising               RD が 0 から 1 になった瞬間
RD.rising && istate == "F1"   命令フェッチ開始
```

### 3.3 論理演算子

```text
&&    AND（両方 true）
||    OR（どちらか true）
!     NOT
()    グループ化
```

### 3.4 数値リテラル

```text
010     8 進数（PDP-11 の伝統的表記）
0o10    8 進数（0o プレフィックス）
0x10    16 進数
10      10 進数
```

### 3.5 文字列リテラル

```text
"USER"     大文字小文字は区別しない（"user" でも可）
"KERNEL"
"F1"       istate の状態名
```

## 4. 信号リファレンスと対応状況

### 4.1 主要信号

| 信号名 | 内容 | 数値比較 | 文字列比較 | エッジ検出 |
|--------|------|:--------:|:----------:|:----------:|
| `VA` | 仮想アドレスバス | ✅ | ❌ | ✅ |
| `PC` | プログラムカウンタ（フェッチ後 +2 済み） | ✅ | ❌ | ✅ |
| `RD` | バス読み取りストローブ | ✅ | ❌ | ✅ |
| `WR` | バス書き込みストローブ | ✅ | ❌ | ✅ |
| `Mode` | CPU モード | ✅ | ✅ `"KERNEL"` `"SUPER"` `"USER"` | ✅ |
| `istate` | 内部ステートマシン状態 | ✅ | ✅（下表参照） | ✅ |
| `ISN` | 命令レジスタ（生オペコード） | ✅ | ❌ | ✅ |
| `PSW` | プロセッサステータスワード | ✅ | ❌ | ✅ |
| `Cycle` | バスサイクル種別（仮想信号） | ❌ | ❌ | ❌ |
| `R0`–`R5` | 汎用レジスタ | ✅ | ❌ | ✅ |
| `SP` | スタックポインタ（R6） | ✅ | ❌ | ✅ |
| `bus_error` | バスエラーフラグ | ✅ | ❌ | ✅ |

### 4.2 istate の文字列値

```text
H1     HALT 状態
F1     命令フェッチ
C1     命令デコード
S1–S4  ソースアドレス計算
D1–D4  デスティネーションアドレス計算
E1     実行
W1     ライトバック
O1–O3  オフセット計算
P1     プッシュ（JSR）
T0–T4  トラップシーケンス
I1     割り込みアック
```

### 4.3 Cycle / ISN 文字列 / PSW 文字列の代替式

`Cycle`（仮想信号）・`ISN` の文字列比較・`PSW` の文字列比較は現在 Wasm コンパイル非対応。  
コンパイル時にエラーメッセージと代替式が表示される。

| やりたいこと | 代替式 |
|------------|-------|
| `Cycle == "FETCH"` | `RD.rising && istate == "F1"` |
| `Cycle == "MEM_RD"` | `RD == 1 && istate != "F1"` |
| `Cycle == "MEM_WR"` | `WR == 1` |
| `ISN == "CLR R1"` | `ISN == 0o5001` |
| `ISN == "MOV R0,R1"` | `ISN == 0o10001` |
| PSW の N フラグ確認 | `PSW == 0o10` や `PSW >= 0o10 && PSW < 0o20`（数値比較） |
| PSW の C フラグ確認 | `PSW == 1` |

## 5. 使用例

### 5.1 ユーザーモードで特定アドレスの命令を捕捉

```text
VA == 06 && Mode == "USER"
```

VA=6（8 進）の命令をユーザーモードで実行した瞬間に停止。  
`Mode == "USER"` を付けることで、カーネルが同じ仮想アドレスをアクセスした場合の誤検出を防ぐ。

### 5.2 命令フェッチ開始の立ち上がりを検出

```text
RD.rising && istate == "F1" && Mode == "USER"
```

ユーザープロセスの命令フェッチが始まる瞬間を捕捉する。

### 5.3 アドレス範囲指定

```text
VA >= 04 && VA <= 012 && Mode == "USER"
```

ループ本体（仮想アドレス 4〜10 の 8 進範囲）の全命令を捕捉する。

### 5.4 書き込み発生時の停止

```text
WR.rising && VA == 0xfffe
```

特定のアドレスへの書き込み開始を捕捉する。

### 5.5 カーネルの特定アドレスを捕捉

```text
VA == 015670
```

Mode 指定を省略すると、カーネル・ユーザー両方のアクセスを捕捉する。

## 6. `VA` vs `PC` の使い分け

| シグナル | 内容 |
|---------|------|
| `VA` | バスに出ている仮想アドレス（命令アドレスに対応） |
| `PC` | CPU 内部の PC レジスタ（命令フェッチ後に +2 済み） |

**特定の命令アドレスを指定するときは `VA` を使う。**  
`PC` はフェッチ後に自動インクリメントされるため、命令の仮想アドレスより 2 大きい値になる。

---

## 7. サンプリングレートの自動切り替え

`Set` ボタンを押すと、LA ヘッダの **サンプリング間隔** が自動的に **1tick/smpl** に切り替わる。

| サンプリング | 設定値 | 用途 |
|------------|--------|------|
| 4tick/smpl | `ring_tick_mask = 3` | 通常操作・Unix V6 速度優先（デフォルト） |
| 1tick/smpl | `ring_tick_mask = 0` | 式トリガー（取りこぼし防止） |

4tick/smpl では、1 tick 以内に成立する条件（バスストローブの単一クロック幅など）を取りこぼすことがある。  
式トリガーを解除（`Clear` または PC トリガーに変更）すると、セレクトに従って元のレートに戻る。

## 8. 内部アーキテクチャ（参考）

```text
UI スレッド
  │  _trigParse(exprStr)       → AST
  │  trigCompileToWasm(ast)    → Wasm バイナリ (Uint8Array, ~70-150 byte)
  │  postMessage({type:'set_expr_trigger', wasmBytes}, [wasmBytes])
  ↓
Worker スレッド
  │  new WebAssembly.Module(bytes) / new WebAssembly.Instance(mod, {})
  │  eval = inst.exports.eval    ← i32×18 → i32 のネイティブ Wasm 関数
  │
  └─ simLoop() 毎フレーム:
       ring buffer の新着サンプルを全件スキャン
       eval(w0..w8, pw0..pw8)    ← ~2–5 ns/sample
       → true なら triggered して停止
```

`trigger-expr-compiler.js` が生成する Wasm 関数のシグネチャ:

```text
(i32×9, i32×9) → i32
 ├── params 0-8:  現サンプルの ring buffer ワード w0..w8
 └── params 9-17: 前サンプルの ring buffer ワード pw0..pw8（エッジ検出用）
```

メモリ共有は行わず、各サンプルの ring ワードを直接パラメータとして渡す設計。  
Worker 内で同期インスタンス化できるため、`WebAssembly.instantiate` の非同期 API は不要。
