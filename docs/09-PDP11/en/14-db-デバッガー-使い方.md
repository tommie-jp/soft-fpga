# 14. db — Unix V6 Debugger Usage <a class="qr-link" href="../../../docs/09-PDP11/img/14-en-QR.png">QR</a>

This disk image includes `/bin/db` (the Unix V6 standard debugger) and
`/bin/cdb` (a C language debugger). This document covers `db`.

> **⚠️ In this simulator, `db` and `cdb` do not work (known unresolved issue — under investigation)**
>
> Both `db` and `cdb` internally perform `fork` → `ptrace(0)` → `exec` and
> control the target process via ptrace (sys 26) as **dynamic debuggers**.
> In this simulator, the fork/exec/stop() flow of ptrace does not complete correctly,
> and the process crashes with `Trace/BPT trap -- Core dumped` or `Bus error -- Core dumped`.
> The T-bit (PSW[4], vector 14) is implemented in the RTL, but the V6 kernel's
> ptrace implementation is not compatible with this simulation environment.
>
> **What cannot be done currently (`db` / `cdb` related):**
>
> - `db a.out` / `cdb a.out` — crashes with Bus error or Trace/BPT trap
> - `db core a.out` — post-mortem core dump analysis (crashes similarly)
> - Setting breakpoints and single-step execution
> - Inspecting memory/registers of a running process
>
> **Investigation status:** The root cause has been identified as
> `missing psignal(SIGTRC) in exec() of the V6 kernel source`
> (→ §9.1). A fix via binary patch to the disk image or kernel recompilation
> is under consideration but has not been implemented.
> Use `nm` / `od` / the debug panel as alternatives (→ §8.1 and §10).
>
> The command syntax descriptions (§2–§8) are retained for reference.
> **To check virtual addresses, use `nm a.out` or `od -o a.out`** (see §8.1).

---

## 1. Starting

```text
# db a.out             ← inspect a.out (disassemble / dump)
# db core a.out        ← post-mortem analysis of core dump with a.out symbols
```

`db` **displays no prompt**. After launching it silently waits for input
(it has not frozen). Enter commands directly and press Enter.
Use `%` to quit.

---

## 2. Address Expressions

Place an address (expression) before an inspection command. Expressions are built from the following elements:

| Element | Meaning |
|---------|---------|
| Symbol name | Assembly symbol value (e.g., `start`) |
| Octal number | Absolute value (e.g., `777`) |
| Decimal number + `.` | Absolute value (e.g., `123.`) |
| Octal number + `r` | Relocatable quantity (e.g., `100r`) |
| `.` | Current position (current pointer) |
| `*expr` | Indirect reference (the word at that address) |
| `+` / space | Addition (at most one relocatable quantity) |
| `-` | Subtraction |

Evaluation is left-to-right. Register names `r0`–`r5` / `sp` / `pc` / `fr0`–`fr5`
can also be used in expressions (mainly meaningful when inspecting a core file).

---

## 3. Inspection Commands

The format is `address<command character>`. The command character serves as the
**display format** (rather than taking a separate format string, one character
specifies both the address and display format).

| Command | Description |
|---------|-------------|
| `/` | Display the word at that address in octal |
| `\` | Display the byte at that address in octal |
| `"` | Display the word at that address as 2 ASCII characters |
| `\|` | Display the byte at that address as 1 ASCII character |
| `g` | Display the word at that address in decimal |
| `?` | **Disassemble** the address as a machine instruction (with symbols) |
| `&` | Display the address as a **symbolic address** (nearest symbol + offset) |
| `<Enter>` | Advance the current position and display using the previous format |
| `^` | Move back one position and display using the previous format |
| `%` | Quit |

Example usage:

```text
0?              ← disassemble 1 instruction at address 0
<Enter>         ← advance to next instruction
start?          ← disassemble at the address of symbol start
0200/           ← display word at address 0200 in octal
msg"            ← display contents of msg as ASCII
```

---

## 4. Repeated Display (count)

Appending `,expression` after an address causes the command to **execute repeatedly
the number of times specified by the expression**.

```text
0,6?            ← disassemble 6 instructions starting at address 0
0200,20/        ← display 20 words starting at address 0200 in octal
```

The current position advances to the last displayed location.

---

## 5. Expression Evaluation

Evaluate an expression without accessing address space.

| Command | Description |
|---------|-------------|
| `=` | Display the value of the preceding expression in octal (`.` if no expression) |
| `:` | Display the preceding expression as a symbolic address (symbol + offset) |

```text
start=          ← display the address of start in octal
1000+10=        ← display the result of the expression (1010)
4014:           ← display 4014 as the nearest symbol name + offset
```

---

## 6. Memory Write

| Command | Description |
|---------|-------------|
| `!` | Store the value of the preceding expression at the address pointed to by `.` |

`!` must always be preceded by an expression. It writes to `.` (current position),
so first open the target address with an inspection command.

```text
0200/           ← open 0200 (. = 0200)
177777!         ← write 177777 to address 0200
```

---

## 7. Register / Fault Display

| Command | Description |
|---------|-------------|
| `$` | Display the fault type and general-purpose / other registers in octal + symbolic form |

`$` is most useful when **inspecting a core file**, showing which fault
(illegal instruction, bus error, etc.) caused the crash and the register state at that point.

## 8. Typical Usage

### 8.1 Alternative ways to check virtual addresses in a.out

Since `db a.out` does not work in this simulator, use the following to check virtual addresses.

```text
# nm a.out              ← list symbol names and virtual addresses (octal)
0000006 T loop
0000000 T start

# od -o a.out           ← octal dump of binary (first 8 words are the a.out header)
# size a.out            ← byte counts of text / data / bss segments
```

The virtual address to enter in the Logic Analyzer PC trigger can be confirmed with `nm`
(→ [25 as/db Instruction Sequence Demo](?doc=25-as-db-命令シーケンスデモ.md)).

### 8.2 Post-mortem core dump analysis (reference: procedure on real hardware)

When a program crashes, a `core` file is generated. On a real PDP-11,
use `db core a.out` to examine the state at the time of the fault.

```text
# ./a.out            ← crashes with bus error etc. → core generated
# db core a.out
$                    ← display fault type and registers
pc?                  ← disassemble the instruction at the faulting pc
sp,10/               ← dump top 10 words of the stack
%
```

## 9. Notes for This Simulator

### 9.1 `db` does not work (exec() bug in the V6 kernel)

`db` crashes with `Bus error -- Core dumped` for every command
(including `0,6?` and `%`). **The root cause is a bug in the V6 kernel itself
on this disk image, not in the simulator.**

#### Failure sequence

1. Running `db a.out` causes db to internally call `fork()`
2. The child process calls `ptrace(TRACEME=0)` → the kernel sets the STRC flag
3. The child calls `exec(a.out)` → **the kernel bug is triggered here**
4. The parent db expects `wait()` to return WIFSTOPPED (status & 0377 == 0177), but it does not
5. db attempts to read memory via ptrace → ESRCH error (child is not in SSTOP)
6. db uses the return value -1 as a pointer → **Bus error**

#### Kernel bug details

The regular V6 source (`/usr/sys/ken/sys1.c`) `exec()` should have the following
in the "clear sigs, regs and return" section, but
**these 2 lines are missing from `exec()` in this disk image:**

```c
if (u.u_procp->p_flag&STRC)
    psignal(u.u_procp, SIGTRC);
```

Without these lines, after `exec()` `p->p_sig` remains 0,
`issig()` does not call `stop()`, and the child process never enters SSTOP.

#### Verification results

Confirmed by exhaustive search of the kernel source (raw read of all blocks of
`/usr/sys/ken/sys1.c`). Running a probe script (`ptrace(TRACEME) + exec("/tgt")`)
in the V6 shell showed that the child process did not stop (output `n` instead of `s`).

The T-bit (PSW[4]), trace trap (vector 14), and mfpi previous-mode selection
at the RTL level are all correctly implemented. A fix requires kernel recompilation.

### 9.2 Verify operation by running a.out directly

For self-contained programs, the `a.out` output from `as` can be executed directly.
If it exits normally, the shell prompt returns.

```text
# a.out
#      ← no output, prompt returns = normal exit
```

### 9.3 When a.out gives "syntax error"

Pasting source directly at the command line can cause UART character corruption,
and `cc`/`as` may generate a corrupted `a.out`.
Using the **EDITOR button** to enter source avoids corruption.

## 10. Using the Web UI Debug Panel as an Alternative

Since `db` does not work, use the following for address-level observation:

| Tool | What it observes | Granularity | Notes |
|------|-----------------|-------------|-------|
| `nm a.out` | Symbol virtual addresses | Instruction level | Alternative to `db` |
| `od -o a.out` | Binary dump | Byte level | Check headers and opcodes |
| GPR panel | Real-time CPU register display | Clock level | |
| Logic Analyzer | Unibus signals and bus cycles | Clock level | |

By entering the **virtual address** looked up with `nm` directly into the LA PC trigger,
bus cycles for that instruction can be captured at the hardware level
(→ [25 as/db Instruction Sequence Demo](?doc=25-as-db-命令シーケンスデモ.md)).
