# 21. Logic Analyzer — Bus Cycle Examples <a class="qr-link" href="../../../docs/09-PDP11/img/21-en-QR.png">QR</a>

This page explains the waveform patterns observable in the Logic Analyzer debug panel.

---

## 1. Decode Lane Color Meanings

The **Cycle** band at the top of the waveform shows the type of each bus cycle by color.

| Color | Type | Description |
|----|------|------|
| Blue | FETCH | Instruction fetch (read where VA == PC) |
| Green | MEM\_RD | Memory read (typically RAM) |
| Red | MEM\_WR | Memory write |
| Light green | IO\_RD | I/O page read (device register) |
| Orange | IO\_WR | I/O page write (device register) |
| Orange | TRAP | Trap occurred |

## 2. Unix V6 Boot Waveform

### 2.1 Bootrom Phase (0 to several thousand clocks)

```text
Cycle:   [FETCH][FETCH][FETCH][MEM_RD][IO_RD][IO_WR]...
PC:      173000 → 173002 → 173004 ...
Mode:    Kernel
PhysAddr: 0o773000（bootrom ROM region）→ 0o777564（DL11 XCSR）
```

While PC is around `0o173000`, the bootrom is running.
IO\_RD to `0o777564` (DL11 transmit status) corresponds to `@` prompt output.

### 2.2 Kernel Load Phase

```text
Cycle:   [IO_RD][IO_RD]...[MEM_WR][MEM_WR]...
PC:      0o173xxx（bootrom）
RK:      Idle → St=1（disk transfer started）
PhysAddr: 0o177404（RKCS）→ 0o177410（RKBA）→ 0o000000〜（RAM write）
```

The interval where `rk_state` becomes non-zero is the kernel load from disk to RAM.
`PhysAddr` shows a continuous stream of MEM\_WR to the start of RAM (`0o000000`〜).

### 2.3 Kernel Execution Phase

```text
Cycle:   [FETCH][MEM_RD][FETCH]...
PC:      0o000000 → 0o002000 → ...
Mode:    Kernel（light green background）
```

The moment PC switches to `0o000000` marks kernel startup.
The `INT` signal going High periodically is the KW11 line clock (60 Hz) interrupt.

## 3. KW11 Line Clock Interrupt

The timer backbone of Unix V6. Occurs at 60 Hz (every 16.7 ms).

```text
INT:     _____|‾‾‾‾|_____
Vec:     0o100（KW11 vector）
PC transition: (normal code) → 0o000100（vector）→ interrupt handler
Mode:    Kernel（switches to Kernel when user code is interrupted）
```

Points to check in the waveform:

1. Look for a `bus_int=1` pulse
2. Confirm `int_vec` is `0o100` (= 64)
3. Confirm `pc` jumps to near the interrupt vector address

## 4. RK11 Disk Transfer (During System Call)

Observable when performing I/O operations such as `ls /`.

```text
Cycle:   [IO_WR][IO_WR][IO_WR][IO_WR][IO_WR]
PhysAddr: 0o177404（RKCS ← command write）
          0o177406（RKWC ← word count）
          0o177410（RKBA ← bus address）
          0o177412（RKDA ← disk address）
RK:      0 → 1 → 2 → ... → 0（transfer complete）
INT:     High at transfer completion（RK11 interrupt, Vec=0o220）
```

One disk access cycle consists of:

1. Setting RKCS, RKWC, RKBA, RKDA via IO\_WR (4 IO\_WR operations)
2. `rk_state` becomes non-zero and DMA transfer begins
3. On transfer completion, `INT=1` and `Vec=0o220` (RK11) are asserted

## 5. Kernel Mode → User Mode Switch

The moment a process is exec'd and transitions to user mode.

```text
Mode:  Kernel ──────────────▶ User
PC:    0o003512（RTT instruction — return to user）
PSW:   KK P6 ... → UU P0 ...（CM changes to 11=User）
```

How to read the waveform:

1. The `cm` (Mode) signal background changes from light green (Kernel) to light blue (User)
2. `pc` jumps to a low address (start of user code)
3. From this point, `PhysAddr` points to the user process's physical pages

---

## 6. Full Sequence During `ls /` Execution

```text
1. [User] sh waits for command input（DL11 RX polling: continuous IO_RD at 0o177560）
2. [Kernel] TRAP → system call（fork）
3. [Kernel] exec → MMU PAR rewrite（large number of IO_WR to UISA）
4. [Kernel] RK11 disk access（directory read）
5. [User] ls runs, DL11 TX IO_WR（0o177566）for each output character
6. [Kernel] TRAP → wait → ls exits
7. [User] returns to sh, redisplays prompt
```

The UISA IO\_WR burst in step 3 occurs simultaneously with PAR value changes in the MMU panel.

## 7. Procedure for Reading Waveforms

### Step 1: Narrow Down Signals

Starting with 4 signals makes them easier to read:

- `PhysAddr` (address)
- `bus_rd` / `bus_wr` (direction)
- `cm` (Mode)
- `rk_state` (disk activity)

### Step 2: Enable the Decode Lane

Turn on the `Cycle` toggle in the LA header to display FETCH/MEM\_RD/IO\_WR as colored bands.

### Step 3: Capture a Target Point Using PC Trigger

Example: capturing the moment `ls` is executed

1. Set PC Trigger to `user mode RTT` (`0o003512`)
2. Click Run → resume simulation
3. When auto-stopped, click the Freeze button to lock the waveform
4. Zoom out to see the surrounding context
