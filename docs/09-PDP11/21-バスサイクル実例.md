# 21. Logic Analyzer — バスサイクル実例集 <a class="qr-link" href="../../../docs/09-PDP11/21-バスサイクル実例-QR.png">QR</a>

デバッグパネルの Logic Analyzer で実際に観測できる波形パターンを解説する。

---

## 1. デコードレーンの色の意味

波形上部の **Cycle** 帯は各バスサイクルの種別を色で示す。

| 色 | 種別 | 説明 |
|----|------|------|
| 青 | FETCH | 命令フェッチ（VA == PC の読み出し）|
| 緑 | MEM\_RD | メモリ読み出し（通常 RAM）|
| 赤 | MEM\_WR | メモリ書き込み |
| 薄緑 | IO\_RD | I/O ページ読み出し（デバイスレジスタ）|
| 橙 | IO\_WR | I/O ページ書き込み（デバイスレジスタ）|
| 橙 | TRAP | トラップ発生 |

## 2. Unix V6 ブート波形

### 2.1 bootrom フェーズ（0 〜 数千クロック）

```text
Cycle:   [FETCH][FETCH][FETCH][MEM_RD][IO_RD][IO_WR]...
PC:      173000 → 173002 → 173004 ...
Mode:    Kernel
PhysAddr: 0o773000（bootrom ROM 領域）→ 0o777564（DL11 XCSR）
```

PC が `0o173000` 付近にある間は bootrom が動作中。
`0o777564`（DL11 送信ステータス）への IO\_RD が `@` プロンプトの出力。

### 2.2 カーネルロードフェーズ

```text
Cycle:   [IO_RD][IO_RD]...[MEM_WR][MEM_WR]...
PC:      0o173xxx（bootrom）
RK:      Idle → St=1（ディスク転送開始）
PhysAddr: 0o177404（RKCS）→ 0o177410（RKBA）→ 0o000000〜（RAM 書き込み）
```

`rk_state` が非ゼロになる区間がディスクから RAM へのカーネルロード。
`PhysAddr` が RAM 先頭（`0o000000`〜）への MEM\_WR が続く。

### 2.3 カーネル実行フェーズ

```text
Cycle:   [FETCH][MEM_RD][FETCH]...
PC:      0o000000 → 0o002000 → ...
Mode:    Kernel（薄緑背景）
```

PC が `0o000000` に切り替わった瞬間がカーネル起動。
`INT` 信号が定期的に High になるのは KW11 ラインクロック（60 Hz）割り込み。

## 3. KW11 ラインクロック割り込み

Unix V6 のタイマー基盤。60 Hz（16.7 ms ごと）に発生する。

```text
INT:     _____|‾‾‾‾|_____
Vec:     0o100（KW11 ベクタ）
PC 遷移: (通常コード) → 0o000100（ベクタ）→ 割り込みハンドラ
Mode:    Kernel（ユーザーコード実行中に割り込まれると Kernel に切り替わる）
```

波形で確認するポイント:

1. `bus_int=1` のパルスを探す
2. `int_vec` が `0o100`（= 64）であることを確認
3. `pc` が割り込みベクタアドレス付近にジャンプする

---

## 4. RK11 ディスク転送（システムコール中）

`ls /` など I/O を伴う操作をすると観測できる。

```text
Cycle:   [IO_WR][IO_WR][IO_WR][IO_WR][IO_WR]
PhysAddr: 0o177404（RKCS ← コマンド書き込み）
          0o177406（RKWC ← ワードカウント）
          0o177410（RKBA ← バスアドレス）
          0o177412（RKDA ← ディスクアドレス）
RK:      0 → 1 → 2 → ... → 0（転送完了）
INT:     転送完了時に High（RK11 割り込み, Vec=0o220）
```

ディスクアクセスの 1 サイクルは:

1. RKCS・RKWC・RKBA・RKDA を IO\_WR で設定（4 回の IO\_WR）
2. `rk_state` が 0 以外になり DMA 転送が始まる
3. 転送完了で `INT=1`、`Vec=0o220`（RK11）が出る

---

## 5. カーネルモード → ユーザーモード切り替え

プロセスが exec されてユーザーモードに移行する瞬間。

```text
Mode:  Kernel ──────────────▶ User
PC:    0o003512（RTT 命令・ユーザーへの復帰）
PSW:   KK P6 ... → UU P0 ...（CM が 11=User に変化）
```

波形の見方:

1. `cm`（Mode）信号の背景が薄緑（Kernel）から薄青（User）に変わる
2. `pc` が低いアドレス（ユーザーコード先頭）にジャンプ
3. 以降 `PhysAddr` がユーザープロセスの物理ページを指す

---

## 6. `ls /` 実行中のフルシーケンス

```text
1. [User] sh がコマンド入力を待つ（DL11 RX polling: IO_RD 0o177560 が連続）
2. [Kernel] TRAP → システムコール（fork）
3. [Kernel] exec → MMU PAR 書き換え（UISA への IO_WR 大量発生）
4. [Kernel] RK11 ディスクアクセス（ディレクトリ読み込み）
5. [User] ls が実行、出力文字ごとに DL11 TX IO_WR（0o177566）
6. [Kernel] TRAP → wait → ls 終了
7. [User] sh に戻り、プロンプトを再表示
```

ステップ 3 の UISA IO\_WR 群は MMU パネルの PAR 値変化と同時に発生する。

## 7. 実際に波形を読む手順

### 手順 1: 信号を絞る

最初は 4 本に絞ると読みやすい:

- `PhysAddr`（アドレス）
- `bus_rd` / `bus_wr`（方向）
- `cm`（Mode）
- `rk_state`（ディスクアクティビティ）

### 手順 2: デコードレーンをオンにする

LA ヘッダの `Cycle` トグルをオンにすると FETCH/MEM\_RD/IO\_WR が色帯で表示される。

### 手順 3: PC トリガーで狙った地点を捕捉する

例: `ls` が実行される瞬間を捕捉

1. PC Trigger に `user mode RTT`（`0o003512`）を設定
2. Run → シミュレーションを再開
3. 自動停止したら Freeze ボタンで波形を固定
4. 波形をズームアウトして前後の文脈を確認
