# 20. デバッグパネル・Logic Analyzer の使い方

RTL シミュレーターには CPU の内部状態をリアルタイムで観測するための
デバッグ機能が組み込まれています。
このドキュメントでは **GPR パネル**・**MMU パネル**・**Logic Analyzer**・
**PC トリガー**の各機能を説明します。

---

## 1. GPR パネル（汎用レジスタ表示）

ターミナルの右側に表示される「Registers」ペインです。

```text
Registers
R0  003710     R1  013220
R2  000000     R3  000377
R4  001234     R5  017532
SP  177600
PC  004014
PSW KK P6 T.NZVC
```

### 1.1 レジスタフィールド

| フィールド | 説明 |
|-----------|------|
| `R0`–`R5` | 汎用レジスタ（16 ビット、8 進表示）|
| `SP` | スタックポインタ（R6）|
| `PC` | プログラムカウンタ（R7）|
| `PSW` | プロセッサステータスワード（後述）|

### 1.2 PSW 表示形式

PSW は `CM PM P# T NZVC` の形式で表示されます。

```text
KK P6 T.NZVC
^^  ^  ^^^^^
||  |  |||||── C: キャリー
||  |  ||||─── V: オーバーフロー
||  |  |||──── Z: ゼロ
||  |  ||───── N: 負
||  |  |────── T: トレース（1 命令後にトラップ）
||  └───────── P#: 割り込み優先レベル（0–7）
|└──────────── PM: 直前のモード (K=Kernel, S=Super, U=User)
└───────────── CM: 現在のモード
```

大文字 = フラグ ON、`.` = フラグ OFF。

### 1.3 レジスタ値の色

| 色 | 意味 |
|----|------|
| 水色 | 通常（Kernel モード）|
| 青 | ユーザーモード（CM=User）|
| 橙 | トラップ発生直後のスナップショット |
| 黄 | 直前の更新から値が変化したフィールド |

## 2. MMU パネル

GPR パネル下部の「MMU」エリアです（「MMU」ボタンで展開/折り畳み）。

PAR（Page Address Register）と PDR（Page Descriptor Register）を
Kernel I-space（8 ページ）と User I-space（8 ページ）に分けて表示します。

```text
MMU
Kernel I-space             User I-space
#  PAR        PDR    PA    #  PAR        PDR    PA
0  000000o  077406  000000  0  020000o  077406  020000
1  000200o  077406  020000  1  023400o  077406  034000
...                         ...
7  017600o  077406  176000  7  —
```

### 2.1 各列の意味

| 列 | 説明 |
|----|------|
| `#` | ページ番号（0–7）|
| `PAR` | ページアドレスレジスタ（物理アドレスの上位 12 ビット、8 進）|
| `PDR` | ページ記述レジスタ（アクセス権・ページ長・D/W ビット）|
| `PA` | 実際の物理ベースアドレス（PAR × 64 バイト、8 進）|

### 2.2 PDR の主要ビット

| ビット | 名前 | 意味 |
|--------|------|------|
| [3:1] | PLF | ページ長フィールド（有効セクション数）|
| [2] | ED | 展開方向（0=上向き / 1=下向き）|
| [1] | W | 書き込み済みビット（1=このページに書き込みが発生）|
| [0] | D | ページアクセス許可（0=なし / 1=読み取りのみ / 2=読み書き）|

値 `077406` は「全長・読み書き可」の典型値。

### 2.3 観察のヒント

- Unix V6 ブート直後は Kernel I-space の PAR が設定され、
  User I-space はすべてゼロ（ユーザープロセス未起動）。
- `login:` が表示される直前に User I-space の PAR が変化する（init → getty のフォーク）。
- ユーザーコマンド実行中は CM=User になり、User I-space のマッピングが有効になる。

## 3. Logic Analyzer（信号波形表示）

ページ下部の波形表示エリアです。
リングバッファに記録された最新 4096 クロック分の信号を描画します。

### 3.1 デコードレーン（バスサイクル表示）

波形最上部の **Cycle デコードレーン** が各バスサイクルの種別を色帯で表示します。

| 色 | バスサイクル種別 | 意味 |
|----|---------------|------|
| 青 | FETCH | 命令フェッチ（VA == PC の読み出し）|
| 緑 | MEM\_RD | メモリ読み出し（通常 RAM）|
| 赤 | MEM\_WR | メモリ書き込み |
| 薄緑 | IO\_RD | I/O ページ読み出し（物理 0o760000–）|
| 橙 | IO\_WR | I/O ページ書き込み |
| 橙 | TRAP | トラップ発生 |

### 3.2 表示信号一覧

信号はトグルボタンで個別に ON/OFF できます。

#### バスアドレス / データ

| 信号 ID | ラベル | デフォルト | 説明 |
|---------|-------|----------|------|
| `addr_p` | PhysAddr | ON | Unibus 物理アドレス（18 ビット、16 進）|
| `addr_v` | VA | off | 仮想アドレス（MMU 変換前、16 ビット）|
| `data` | Data | ON | バスデータ（読み値または書き値）|

#### バス制御

| 信号 ID | ラベル | デフォルト | 説明 |
|---------|-------|----------|------|
| `bus_wr` | WR | ON | バス書き込みストローブ |
| `bus_rd` | RD | ON | バス読み出しストローブ |
| `byte_op` | BYTE | off | バイト操作フラグ（MOVB/CMPB 等）|

#### CPU 状態

| 信号 ID | ラベル | デフォルト | 説明 |
|---------|-------|----------|------|
| `pc` | PC | ON | プログラムカウンタ（8 進表示）|
| `psw` | PSW | off | プロセッサステータスワード（`KK P6 TNZVC` 形式）|
| `cm` | Mode | ON | CPU 現在モード（Kernel / User）|
| `pri` | Pri | off | 割り込み優先レベル（PSW[7:5]）|

#### トラップ / ホルト

| 信号 ID | ラベル | デフォルト | 説明 |
|---------|-------|----------|------|
| `trapped` | TRAP | ON | トラップ発生フラグ |
| `halted` | HALT | ON | CPU ホルトフラグ（HALT 命令）|

#### 割り込み

| 信号 ID | ラベル | デフォルト | 説明 |
|---------|-------|----------|------|
| `bus_int` | INT | ON | 割り込みリクエスト中フラグ |
| `int_vec` | Vec | off | 割り込みベクタ（8 進）|
| `int_ipl` | IPL | off | 割り込み優先レベル |

#### RK11 ディスク

| 信号 ID | ラベル | デフォルト | 説明 |
|---------|-------|----------|------|
| `rk_state` | RK | ON | RK11 ステート（0=Idle、非 0 でディスク転送中）|

### 3.3 ズーム・スクロール操作

| 操作 | 動作 |
|------|------|
| マウスホイール | 水平ズーム（ポインタ位置を中心に拡大/縮小）|
| 左ドラッグ | 水平スクロール |
| Shift+クリック | A マーカー設置 |
| Ctrl+クリック | B マーカー設置 |

A・B マーカーを設置すると波形上部に差分クロック数が表示されます。

### 3.4 Ring Buffer の仕様

- サイズ: 4096 サンプル（1 クロックに 1 サンプル）
- 形式: 160 ビット/サンプル（32 ビット × 5 ワード）

```text
Word0 [31:0]:
  [17:0]  = Unibus 物理アドレス（18 ビット）
  [18]    = bus_wr
  [19]    = bus_rd
  [21:20] = cpu_cm (00=Kernel, 11=User)
  [22]    = byte_op
  [23]    = trapped
  [24]    = halted
  [25]    = bus_int
  [30:26] = rk_state（5 ビット）

Word1 [31:0]:
  [15: 0] = バスデータ（16 ビット）
  [31:16] = PSW

Word2 [31:0]:
  [15: 0] = PC（仮想）
  [31:16] = 仮想アドレス（MMU 変換前）

Word3 [31:0]:
  [ 7: 0] = 割り込みベクタ（8 ビット）
  [15: 8] = 割り込み優先レベル（8 ビット）

Word4 [31:0]:
  予備
```

## 4. PC トリガー

「PC Trigger」パネルで指定した PC 値に CPU が到達した瞬間にシミュレーションを自動停止します。

### 4.1 設定手順

1. **PC Trigger** パネルの入力欄に停止させたい PC 値を **8 進** で入力する。
2. プルダウンから既知のランドマークを選択するか、数値を直接入力する。
3. **Set** ボタンを押す。
4. シミュレーション実行中にその PC に到達すると自動停止する。
5. 停止後は **Resume** ボタンで再開できる。

### 4.2 既知の PC 一覧

| ラベル | PC（8 進）| 説明 |
|--------|----------|------|
| `bootrom entry` | `0173000` | bootrom.v エントリポイント |
| `kernel entry` | `0000000` | Unix V6 カーネル m40.s エントリ |
| `printf(mem=)` | `0004014` | main.c の `printf("mem=")` |
| `user mode RTT` | `0003512` | ユーザープロセスへの RTT 命令 |
| `login wait` | `0015670` | getty/login キー入力待ちループ |
| `KW11 vec` | `0000100` | ラインクロック割り込みベクタ |
| `RK11 vec` | `0000220` | RK11 ディスク割り込みベクタ |
| `TTY RX vec` | `0000060` | DL11 受信割り込みベクタ |

## 5. ブート進行インジケータ

シミュレーション開始直後に「Boot Progress」バーが表示され、
カーネルのブートフェーズが段階的にハイライトされます。

典型的なステップ:

```text
[ bootrom ] → [ kernel ] → [ mem= ] → [ user RTT ] → [ login ]
```

各ステップは Logic Analyzer の `pc` 信号値が既知の PC に到達した時点で
「完了（緑）」に変わります。`login:` が表示されるとブート完了です。

## 6. 典型的なデバッグ手順

### シナリオ A: カーネルモード/ユーザーモード切り替えを追う

1. `cm`（Mode）信号をオンにする。
2. シミュレーション実行。
3. Kernel（薄緑背景）→ User（薄青背景）に変わる瞬間を Logic Analyzer で確認する。
4. RTT 命令（復帰時）前後で `psw` 信号も追加すると PSW[CM] の変化が見える。

### シナリオ B: RK11 ディスク転送を観察する

1. `rk_state`・`addr_p`・`bus_rd`・`bus_wr`・`data` をオンにする。
2. デコードレーンをオンにする。
3. Unix V6 上で `ls /` など I/O を発生させる。
4. `rk_state` が 0 以外になる区間が DMA 転送中。
5. IO\_RD / IO\_WR の帯で RK11 レジスタ（`0o177400`–）へのアクセスが確認できる。

### シナリオ C: 割り込み発生タイミングを確認する

1. `bus_int`・`int_vec`・`int_ipl` をオンにする。
2. シミュレーション実行。
3. `bus_int=1` の瞬間と `int_vec=0o100`（KW11）または `0o220`（RK11）を確認する。
4. トラップベクタに制御が移る直前に `trapped=1` が立つ。

### シナリオ D: PC トリガーで unix 起動直後の printf を捕捉する

1. PC Trigger で `printf(mem=)` (`0004014`) を選択して **Set**。
2. **Run**。
3. ターミナルに `mem =` が出力される直前に自動停止する。
4. GPR パネルで R0–R5・SP を確認し、カーネル初期化直後のレジスタ状態を読む。

## 7. デバッグセッション実例

### セッション 1: Unix V6 ブートシーケンスをトレースする

**目的**: `bootrom → kernel → printf → user RTT → login` の PC 遷移を Logic Analyzer で確認する。

#### 手順

1. `pc`・`cm`・`bus_rd`・`bus_wr` をオンにする。
2. デコードレーンをオンにする。
3. **Reset** → `rkunix` を送信してブートを開始する。
4. ブート完了後に **Pause** を押す。
5. 波形をズームアウトして `pc` の大きな変化点（カーネル遷移）を探す。

#### 観察ポイント

- `pc` が `0o173000` 付近（bootrom）から `0o000000` 付近（カーネル）に急変する瞬間が
  カーネルロードの完了を示す。
- `cm=Kernel` の間は薄緑背景、`cm=User` になると薄青背景に変わる。
- KW11 割り込み（`int_vec=0o100`）がカーネル動作中に定期的に発生する。

### セッション 2: cc コンパイル中のバスアクティビティを観察する

**目的**: `cc hello.c` 実行中の RK11 ディスクアクセスと MMU マッピングを観察する。

#### 手順

1. `rk_state`・`addr_p`・`cm`・`trapped` をオンにする。
2. Unix V6 プロンプトで `cc hello.c` を入力して Enter。
3. コンパイル中に **Pause**（または Freeze ボタン）を押す。
4. 波形で `rk_state` が激しく変化する区間を確認する。

#### 観察ポイント

- コンパイラ（`/bin/cpp`→`/bin/c0`→`/bin/c1`→`/bin/c2`→`/bin/as`→`/bin/ld`）が
  exec で次々に呼ばれるたびに `addr_p` が新しいページに変化する（プロセス置き換え）。
- `rk_state` が長期間 0 以外になる区間がオブジェクトファイルの読み書き。
- ユーザーモード実行中（`cm=User`）と `exec` システムコール中（`cm=Kernel`）が交互に現れる。
