Unix V6 に搭載されているのは Dennis Ritchie が書いたオリジナルの C コンパイラ（1975年頃）。
ANSI C（1989年）より 14 年前の仕様であり、現代の C とは書き方が異なる点がある。

## 1. Hello, World

### 1.1 ソースファイルの作成

`ed` を使うか、`cat >` でリダイレクト入力する。

```text
# cat > hello.c
main()
{
    printf("Hello, World!\n");
}
```

最後に **Ctrl-D**（EOF）を入力してファイルを閉じる。

> Unix V6 C の注意点
>
> - `#include <stdio.h>` は不要（`printf` は暗黙的に使える）
> - `main()` の戻り値型 `int` は省略可能
> - 文末の `return` も省略可能

### 1.2 コンパイル

```text
# cc hello.c
```

エラーがなければ `a.out` が生成される。

### 1.3 実行

```text
# ./a.out
Hello, World!
```

## 2. コマンドライン引数を受け取る

K&R 方式（ANSI 以前）の関数引数宣言を使う。

```text
# cat > greet.c
main(argc, argv)
int argc;
char **argv;
{
    int i;
    if (argc < 2) {
        printf("usage: greet <name>\n");
        exit(1);
    }
    for (i = 1; i < argc; i++)
        printf("Hello, %s!\n", argv[i]);
}
```

```text
# cc greet.c
# ./a.out Unix V6
Hello, Unix!
Hello, V6!
```

## 4. コンパイラの内部動作

`cc` は以下のパスを順に呼び出すドライバーである。
コンパイル中に MMU PAR/PDR と GPR が激しく変化するため、
Logic Analyzer ビューとの組み合わせがデモのクライマックスに最適。

```text
/lib/c0   — フロントエンド（字句解析・構文解析）
/lib/c1   — コード生成（PDP-11 アセンブリ出力）
/lib/c2   — ピープホール最適化
/bin/as   — アセンブラ（.s → .o）
/bin/ld   — リンカ（.o + /lib/libc.a → a.out）
```

中間ファイルを確認したい場合:

```text
# cc -S hello.c       # アセンブリを hello.s として残す
# cat hello.s
```

## 5. よくある V6 C の落とし穴

| 現象 | 原因 | 対処 |
|------|------|------|
| `int` がデフォルト型 | 戻り値・変数の型省略可 | 意図的。警告も出ない |
| `void` が使えない | V6 C に `void` 型はない | 戻り値なし関数も `int` と書くか省略 |
| 配列範囲チェックなし | C の仕様通り | 手動で境界確認が必要 |
| `//` コメント不可 | `/* */` のみ有効 | ANSI C 以前の仕様 |
| `%d` に `long` を渡すと化ける | `printf` は型情報を持たない | `long` には `%ld` を使う（V6 では `%D`） |

## 7. EIS 命令

**EIS（Extended Instruction Set）** は PDP-11 のオプション命令群で、乗算・除算・算術シフトを提供する。

| 命令 | 動作 |
|------|------|
| `MUL Rn, src` | 符号付き 16×16 bit 乗算 → 32 bit 結果を Rn/Rn+1 に格納 |
| `DIV Rn, src` | 符号付き 32÷16 bit 除算 → 商を Rn、余りを Rn+1 に格納 |
| `ASH Rn, src` | 算術シフト（正=左、負=右、最大 ±31 bit） |
| `ASHC Rn, src` | 32 bit 算術シフト（Rn:Rn+1 を一体シフト） |

`cc` コンパイラは整数乗除算のコード生成に `MUL`/`DIV` を使う。

### 7.1 本プロジェクト（cpus-pdp11）での状況

本 RTL（Brad Parker `cpus-pdp11`）は **EIS を実装済み**。
MAINDEC 診断テスト FKACA0（11/34 EIS 命令テスト）が PASS していることで確認済み。
WASM 版でも `MUL`/`DIV`/`ASH`/`ASHC` を含む `a.out` は正常動作する。

`cc` のバスエラーは EIS とは無関係で、トラップ優先度バグが原因だった。
詳細は [41-cc-コンパイル-バグ調査.md](41-cc-コンパイル-バグ調査.md) 参照。

### 7.2 実機モデル別 EIS 搭載状況

| 環境 | EIS |
|------|-----|
| cpus-pdp11（本プロジェクト） | **実装済み**（FKACA0 PASS） |
| SIMH pdp11 | デフォルトで実装 |
| 実機 PDP-11/40 | オプション基板で追加可能 |
| 実機 PDP-11/45, /70 | 標準搭載 |
