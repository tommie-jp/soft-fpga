# 22. 全命令タイミング図 <a class="qr-link" href="../../../docs/09-PDP11/22-QR.png">QR</a>

PDP-11 主要命令 61 ケースについて、Logic Analyzer で観測したタイミング図の
**読み方・ケース一覧・生成方法**を一冊にまとめたリファレンス。

[スクリーンショット ギャラリー](../../../../test/ss/pdp11/index.html)

---

## 1. 概要

ベアメタルモードで Python アセンブラが各命令を RAM に直接書き込み、PC トリガーで
命令フェッチを検出して Logic Analyzer キャプチャを取る。Unix V6 をブートせず
テスト対象の命令だけを実行するため、OS 割り込み・デバイスアクセスの影響なしに
純粋な命令サイクルを観測できる。

> **EIS 命令（Phase N）を 61 ケースに拡張済み（2026-06-06）**
>
> `MUL`・`DIV`・`ASH`・`ASHC` の 6 ケースを追加。zoom=8 で内部ハードウェアの
> 多サイクル待機（`mul1616` ~16 clk・`div3216` ~32 clk）を可視化する。

## 2. タイミング図の構成

### 2.1 T 軸とトリガーマーカー

```text
T: -20 -19 … -2 -1 | 0 | +1 +2 … +14
                    ↑
                  TRIG（赤点線）
```

| 記号 | 意味 |
|------|------|
| **T = 0** | トリガー発火点 = 観測対象命令のオペコードフェッチ開始（1 クロック目） |
| **T < 0** | プリトリガー期間。直前に実行された**準備命令**（レジスタセットアップ等）が見える |
| **T > 0** | 命令実行フェーズ（デコード・オペランド取得・演算・ライトバック）|

> **T = 0 でトリガー条件**: `bus_rd=1` かつ `VA == trigger_pc`。
> 命令フェッチの最初のバスサイクルで一致したときのみ発火する。

### 2.2 Cycle デコードレーン（最上行の色帯）

波形最上部の **Cycle** 帯が各バスサイクルを自動判別・色付けする。

| 色 | 種別 | 判別条件 |
|----|------|---------|
| 青 | **FETCH** | `bus_rd=1` かつ `VA == PC`（命令フェッチ）|
| 緑 | **MEM\_RD** | `bus_rd=1` かつ `VA ≠ PC`（データ読み出し）|
| 赤 | **MEM\_WR** | `bus_wr=1`（データ書き込み）|
| 薄緑 | **IO\_RD** | I/O ページ（`0o760000〜0o777777`）からの読み出し |
| 橙 | **IO\_WR** | I/O ページへの書き込み |
| 橙 | **TRAP** | トラップ発生フラグ |

色帯が現れない期間 = バスが非アクティブ（CPU 内部処理のみ）。

### 2.3 ISN 行（命令逆アセンブル）

istate が **f1（フェッチ）** のサンプルで取得した 16 bit オペコードを
**簡易ニモニック**に変換して表示する。即値・インデックス語はバス波形から読み取った
後続ワードの実値で表示（取得できない場合は `#imm` / `X(Rn)` のプレースホルダ）。

```text
ISN: MOV #1200,R1   →   CLR R2   →   MOVB (R1),R2   →   BR .-5
```

「準備命令 → 観測命令 → ループ戻り」の遷移がそのまま読める。

### 2.4 PhysAddr / VA / PC の関係

```text
PC       = フェッチ直後に +2 された「次命令アドレス」
PhysAddr = バス上の物理アドレス（MMU 変換後 18 bit）
VA       = CPU が発行した仮想アドレス（MMU 変換前 16 bit）
```

命令フェッチサイクルでは **`VA == PC - 2`**（フェッチ対象アドレス）。
PhysAddr は VA を MMU が変換した値。カーネルモード・ページ有効時は VA = PhysAddr。

> バスが非アクティブのクロックでも PhysAddr は直前の値を保持する（ラッチ動作）。

### 2.5 信号一覧

| 信号 | 説明 |
|------|------|
| `PhysAddr` | Unibus 物理アドレス（命令フェッチ時は `PC - 2`）|
| `VA` | 仮想アドレス（メモリアクセス系ケースのみ表示）|
| `Data` | バスデータ（RD なら読み値、WR なら書き値）|
| `RD` / `WR` | バス読み出し / 書き込みストローブ |
| `BYTE` | バイト操作フラグ（バイト命令ケースのみ High）|
| `PC` | プログラムカウンタ（フェッチ直後の次命令アドレス）|
| `PSW` | プロセッサステータスワード（フォーマット: `CM PM P# TNZVC`）|
| `Mode` | CPU 現在モード（`Kernel` / `User`）|
| `istate` | CPU マイクロシーケンサ状態（記号表示: f1/c1/d\*/s\*/e1/w1 等）|
| `ISN` | 現在命令オペコード（逆アセンブル表示）|
| `R0`–`R5`, `SP` | 汎用レジスタ（8 進表示）|
| `M1(addr)` | メモリプローブ値（指定アドレスの RAM 内容を毎サンプル記録）|

## 3. istate シーケンスと命令フェーズ

istate（CPU マイクロシーケンサ）の詳細定義は [57-レジスタとistate.md](57-レジスタとistate.md) を参照。
タイミング図の読み方に必要な要点を示す。

| istate | フェーズ | 内容 |
|--------|---------|------|
| **f1** | フェッチ | `isn ← M[PC]`、`PC ← PC + 2` |
| **c1** | デコード | 命令種別・オペランドフィールド解析 |
| **s1–s4** | ソース | ソースオペランド実効アドレス計算・バスリード |
| **d1–d4** | デスティネーション | デスト実効アドレス計算・バスリード（更新系命令）|
| **e1** | 実行 | ALU 演算・PSW 更新・PC/SP 修正 |
| **w1** | ライトバック | 結果をレジスタ / メモリへ書き戻し |

### T カウント早見表

| 命令カテゴリ | 典型 istate 列 | 周期数 | バスアクセス |
|------------|--------------|--------|------------|
| 単一オペランド・レジスタ（CLR, COM, INC…）| f1→c1→d1→e1→w1 | **5T** | FETCH ×1 |
| 双オペランド・レジスタ間（MOV R0,R1）| f1→c1→s1→d1→e1→w1 | **6T** | FETCH ×1 |
| 即値（MOV #n,R1）| f1→c1→s1→s4→d1→e1→w1 | **7T** | FETCH ×2 |
| レジスタ間接・読み（MOV (R1),R2）| f1→c1→s1→s4→d1→e1→w1 | **7T** | FETCH+MEM\_RD |
| レジスタ間接・書き（MOV R1,(R2)）| f1→c1→s1→d1→d4→e1→w1 | **7T** | FETCH+MEM\_WR |
| 自動インクリメント（MOV (R1)+,R2）| f1→c1→s1→s2→s4→d1→e1→w1 | **8T** | FETCH+MEM\_RD |
| 自動デクリメント（MOV -(R1),R2）| f1→c1→s1→s4→d1→e1→w1 | **7T** | FETCH+MEM\_RD |
| インデックス（MOV X(R1),R2）| f1→c1→s1→s2→s4→d1→e1→w1 | **8T** | FETCH×2+MEM\_RD |
| 分岐（BR/BNE 等、取得・非取得とも）| f1→c1→e1 | **3T** | FETCH ×1 |
| JSR | f1→c1→s\*→e1→p1→w1 | **7–10T** | FETCH+MEM\_WR |
| RTS | f1→c1→o1→e1 | **5T** | FETCH+MEM\_RD |
| SOB（取得・非取得とも）| f1→c1→e1 | **3T** | FETCH ×1 |

各命令の実測値は対応するスクリーンショットで確認すること。

## 4. カテゴリ別タイミング解説

### 4.1 単一オペランド・レジスタ直接（01–14）

代表: `CLR R1`

```text
T: -20… -1 | 0  +1 +2 +3  +4
ISN:        |[CLR R1              ]
istate:     | f1  c1  d1  e1  w1
Cycle:      |[FETCH               ]
```

- バスアクセスは命令フェッチ 1 回のみ。MEM\_RD/MEM\_WR は出ない。
- `d1` でレジスタ番号を確定し、`e1` で ALU 演算、`w1` でレジスタへ書き戻す。
- `SXT` は N フラグによって結果が変わる（09 vs 15 を比較）。

### 4.2 双オペランド・レジスタ間（16–22）

代表: `MOV R0,R1`

```text
T: | 0  +1 +2  +3  +4 +5
   |[MOV R0,R1            ]
   | f1  c1  s1  d1  e1  w1
   |[FETCH                ]
```

- ソース `s1`、デスト `d1` はどちらもレジスタ番号の確定のみ（バスアクセスなし）。
- `CMP` と `BIT` は w1 がない（PSW のみ更新、レジスタは不変）。

### 4.3 即値命令（23–26）

代表: `MOV #5,R1`

```text
T: | 0  +1  +2 +3 +4  +5  +6
   |[MOV #5,R1               ]
   | f1  c1  s1  s4  d1  e1  w1
   |[FETCH][FETCH             ]
      ↑opcode  ↑immediate
```

- 2 ワード命令なので FETCH が 2 回連続で現れる。
- `s4` で PC の指すワード（即値）を読み、`PC ← PC + 2` される。
- プリトリガー期間の ISN 行に `MOV #1200,R1` のように逆アセンブルで見える。

### 4.4 メモリ間接・読み出し（27）

代表: `MOV (R1),R2`

```text
T: | 0  +1  +2 +3    +4 +5  +6
   |[MOV (R1),R2              ]
   | f1  c1  s1  s4   d1  e1  w1
   |[FETCH    ][MEM_RD        ]
```

- `s4` で MEM\_RD バスサイクルが追加され、M[R1] のデータを読む。
- M1 プローブを `mem_probe=0o1200` にセットすると M1 行に RAM の内容が表示される。

### 4.5 メモリ間接・書き込み（28）

代表: `MOV R2,(R1)`

```text
T: | 0  +1  +2 +3    +4 +5  +6
   | f1  c1  s1  d1   d4  e1  w1
   |[FETCH    ][    MEM_WR     ]
                      ↑ WR=1
```

- `d4` で MEM\_WR サイクルが発生。`bus_wr=1` が High になる。
- `Data` バスに書き込み値が出る（ソース R2 の値）。

### 4.6 自動増減（29–30）

代表: `MOV (R1)+,R2`

```text
T: | 0  +1  +2  +3 +4    +5 +6  +7
   | f1  c1  s1  s2  s4   d1  e1  w1
   |[FETCH         ][MEM_RD         ]
```

- `s2` でポスト処理（`R1 ← R1 + 2`）が行われ、バス読み出し前にレジスタ更新が確定。
- `MOV -(R1),R2` では `s1` で `R1 ← R1 - 2` してから `s4` で読む。

### 4.7 インデックス（31）

代表: `MOV 2(R1),R2`

```text
T: | 0  +1  +2  +3   +4    +5 +6  +7
   | f1  c1  s1  s2   s4    d1  e1  w1
   |[FETCH  ][FETCH  ][MEM_RD        ]
      opcode   offset    data
```

- 3 バスアクセス（opcode フェッチ・オフセットワードフェッチ・データ読み出し）。
- `s2` で実効アドレス `= R1 + offset` を計算。

### 4.8 分岐命令（33–40）

```text
（取得）  f1→c1→e1  PC→分岐先
（非取得）f1→c1→e1  PC→次命令
```

- **istate 列は取得/非取得で同じ**（3T）。違いは `e1` 後の PC 値のみ。
- w1 は出ない（PSW 更新なし）。

### 4.9 バイト命令（32、46–49）

```text
BYTE: __________|‾‾‾‾|_______
                  ↑ MEM_RD / MEM_WR サイクル中 High
```

#### MOVB to register は符号拡張する

| デスティネーション | 動作 |
|-----------------|------|
| レジスタ（R0〜R7）| ソースバイトを **16 bit に符号拡張**してレジスタに格納 |
| メモリ | 対象バイトのみ上書き（隣接バイト不変）|

例: `M[0o1200] = 0o377` → `MOVB (R1),R2` → `R2 = 0o177777`（正常動作）。

```text
0o377 (byte) = 0b11111111 → bit7=1 → 符号拡張 → 0o177777 (word)
```

ゼロ拡張したい場合は `clrb R2` → `bisb (R1),R2` のイディオムを使う。

## 5. プリトリガー期間の読み方

テストは次のループ構造で実行される。

```text
. = 01000
1:
  <準備命令>      ← setup（R1 設定など）
  <観測命令>      ← trigger_pc でトリガー
  br 1b          ← ループ先頭へ戻る
```

トリガー発火前に `pre_ticks=40` 分プリラン（≈ 2 ループ実行）し、
ring buffer にプリトリガーデータを充填する。
ISN 行を左から右に読むと「準備命令 → 観測命令 → BR → 準備命令 → …」の繰り返しが見える。

```text
T:  -20 … -15 … -8 -7 … -1 | 0 …
          ↑                   ↑
       MOV #1200,R1          観測命令
      （T=-15 付近から見える）
```

準備命令が長い場合は `pre_ticks` を増やすか `zoom` を小さくして表示範囲を広げる。

## 6. よくある疑問

### Q1: PhysAddr が 00 に見える期間があるのはなぜか？

バスが非アクティブな期間は `bus_addr_p` が 0 に戻る。実機 Unibus の動作
（マスターがバスを開放）と同様。バスサイクル中のみ有効な値が出る。

### Q2: PC がフェッチアドレスより 2 大きいのはなぜか？

PDP-11 は命令ワードをフェッチすると同時に `PC ← PC + 2` を実行する。
ring buffer にサンプルされる時点では PC はすでに次のアドレスを指す。
フェッチアドレスは `PhysAddr`（`VA == PC - 2`）で確認する。

### Q3: CLR R1 が 5T かかるのは正常か？

正常。f1→c1→d1→e1→w1 の 5 状態が 1 命令分。
実機 PDP-11/20 の CLR レジスタ ≈ 1.5 µs（≒ 2 バスサイクル相当）に整合する。

### Q4: MOVB (R1),R2 の結果が 177777 になるのはバグか？

仕様通り。MOVB はデスティネーションがレジスタの場合、バイト値を 16 bit に
符号拡張して格納する（→ 4.9 節）。

### Q5: ISN 行が空白になっているサンプルがある

istate が f1 以外（c1/d1/e1 など）のサンプルは直前の値を保持して表示する。
istate=0（h1/halt）のサンプルは空白。

## 7. 観測例: MOV (R1),R2 の完全な読み方

スクリーンショット: [27-mov-ind-r.png](../../../test/ss/pdp11/timing-2026-06-05-1653/27-mov-ind-r.png)

```text
T軸:  -20…-16  -15…-9  -8…-1  |  0  +1  +2  +3  +4  +5  +6  +7
Cycle: [FETCH ][MEM_RD][FETCH ] | [FETCH      ] [MEM_RD            ]
ISN:         MOV #1200,R1        |  MOV (R1),R2
istate: f1 c1 s1 s4 d1 e1 w1 f1 |  f1 c1 s1  s4     d1 e1  w1
              ↑                  |           ↑
          即値1200フェッチ         |        M[1200]読み出し
PhysAddr: 1000 1002     1004     |  1006       1200        1010
Data:       12701 1200   5002    |   5002       12345         773
R1:    00→1200                   |                  (変わらず)
R2:                     00       |                        12345
M1(1200):                        |       12345 (全期間)
```

1. **T=-15〜-9**: `MOV #1200,R1` — FETCH×2（opcode + 即値 1200）、R1←1200
2. **T=-8〜-1**: ループの BR 戻り + 次ループの `MOV #1200,R1` 再実行
3. **T=0**: TRIG。`FETCH` at addr=1006（`MOV (R1),R2` = opcode `005002`）
4. **T=+3〜+4**: `s4` で `MEM_RD` at addr=1200（M1 の値 12345 を読む）
5. **T=+5〜+6**: `e1→w1` で R2←12345
6. **T=+7**: 次命令フェッチ（BR）

### Phase N — EIS instructions（6 件）

内部ハードウェアユニット（`mul1616` / `div3216` / `shift32`）が動作するため、
通常命令より多くのクロックがかかる。`istate` 信号で待機サイクルを確認できる。
表示信号: `SIG_EIS` = BUS + `cm` + `istate` + `r0` + `r1`、ズーム: 8x。

| # | mnemonic | 説明 | 内部サイクル概算 |
|---|----------|------|----------------|
| 55 | `mul-r-r` | MUL R0×R1 → R0:R1 = 0:15 | `mul1616` ~16 clk |
| 56 | `div-r-r` | DIV R0:R1÷R2 → R0=5(商) R1=0(余数) | `div3216` ~32 clk |
| 57 | `ash-pos` | ASH R0 左シフト 3 (64→512) | `shift32` 可変 |
| 58 | `ash-neg` | ASH R0 算術右シフト 2 (64→16) | `shift32` 可変 |
| 59 | `ashc-r` | ASHC R0:R1 32bit 左シフト 4 ({0,1}→{0,16}) | `shift32` 可変 |
| 60 | `div-ovf` | DIV ゼロ除算 → V=1 abort（短縮） | `div_abort` |
