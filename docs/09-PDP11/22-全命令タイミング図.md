# 22. 全命令タイミング図

PDP-11 の主要命令 55 ケースについて、Logic Analyzer で観測したタイミング図（スクリーンショット）を一覧する。

---

## 1. 概要

ベアメタルモードで Python アセンブラが各命令を RAM に直接書き込み、PC トリガーで命令フェッチを検出して Logic Analyzer キャプチャを取る。Unix V6 をブートせず、テスト対象の命令だけを実行する環境のため、OS 割り込みやデバイスアクセスの影響なしに純粋な命令サイクルを観測できる。

スクリーンショットのギャラリーは以下を参照。

[スクリーンショット ギャラリー](../../../../test/ss/pdp11/index.html)

---

## 2. 信号の見方

Logic Analyzer に表示される信号の意味を以下にまとめる。

| 信号 | 説明 |
|------|------|
| `pc` | プログラムカウンタ（フェッチ直後の次命令アドレス） |
| `addr_p` | Unibus 物理アドレス（命令フェッチ時は `pc - 2` の値） |
| `data` | バスデータ（読み出し時 = 命令ワード / オペランド） |
| `bus_rd` | バス読み出しストローブ（High の期間がメモリ読み出しサイクル） |
| `bus_wr` | バス書き込みストローブ（High の期間がメモリ書き込みサイクル） |
| `cm` | CPU モード（`00` = Kernel, `11` = User） |
| `addr_v` | 仮想アドレス（メモリアクセス系ケースのみ表示） |
| `byte_op` | バイト操作フラグ（バイト命令ケースのみ表示） |

命令フェッチサイクルでは `bus_rd` が High になり、`addr_p` に `pc - 2`（フェッチ対象アドレス）が出る。オペランドアクセスではその後に追加の `bus_rd` / `bus_wr` サイクルが続く。

## 3. ケース一覧

### Phase A — No operand（1 件）

| # | mnemonic | 説明 |
|---|----------|------|
| 00 | `nop` | No Operation |

### Phase B — Single-operand register（9 件）

| # | mnemonic | 説明 |
|---|----------|------|
| 01 | `clr-r` | Clear Register R1 |
| 02 | `com-r` | Complement R1 |
| 03 | `inc-r` | Increment R1 |
| 04 | `dec-r` | Decrement R1 |
| 05 | `neg-r` | Negate R1 (twos complement) |
| 06 | `adc-r` | Add Carry to R1 (C=0) |
| 07 | `sbc-r` | Subtract Carry from R1 (C=0) |
| 08 | `tst-r` | Test R1 (set N/Z flags) |
| 09 | `sxt-r` | Sign Extend (N=1 → R1=177600) |

### Phase C — Shift/Rotate register（6 件）

| # | mnemonic | 説明 |
|---|----------|------|
| 10 | `ror-r` | Rotate Right through Carry (C=0) |
| 11 | `rol-r` | Rotate Left through Carry (C=0) |
| 12 | `asr-r` | Arithmetic Shift Right R1 |
| 13 | `asl-r` | Arithmetic Shift Left R1 |
| 14 | `swab-r` | Swap Bytes of R1 |
| 15 | `sxt-r-n0` | Sign Extend (N=0 → R1=0) |

### Phase D — Double-operand register-register（7 件）

| # | mnemonic | 説明 |
|---|----------|------|
| 16 | `mov-r-r` | Move R0 to R1 |
| 17 | `cmp-r-r` | Compare R0 and R1 (equal, Z=1) |
| 18 | `bit-r-r` | Bit Test R0 AND R1 |
| 19 | `bic-r-r` | Bit Clear: R1 &= ~R0 |
| 20 | `bis-r-r` | Bit Set: R1 \|= R0 |
| 21 | `add-r-r` | Add R0 to R1 |
| 22 | `sub-r-r` | Subtract R0 from R1 |

### Phase E — Immediate operand（4 件）

| # | mnemonic | 説明 |
|---|----------|------|
| 23 | `mov-imm-r` | Move Immediate 5 to R1 |
| 24 | `add-imm-r` | Add Immediate 3 to R1 |
| 25 | `cmp-imm-r` | Compare Immediate 5 with R1 (equal, Z=1) |
| 26 | `bis-imm-r` | Bit Set: R1 \|= 017 |

### Phase F — Memory access（6 件）

| # | mnemonic | 説明 |
|---|----------|------|
| 27 | `mov-ind-r` | Load R2 from memory (R1) |
| 28 | `mov-r-ind` | Store R2 to memory (R1) |
| 29 | `mov-autoinc-r` | Load R2 auto-increment (R1)+ |
| 30 | `mov-autodec-r` | Load R2 auto-decrement -(R1) |
| 31 | `mov-idx-r` | Load R2 indexed 2(R1) |
| 32 | `movb-ind-r` | Byte Load R2 from (R1), sign-extend |

### Phase G — Branch（8 件）

| # | mnemonic | 説明 |
|---|----------|------|
| 33 | `br-taken` | Branch (always taken) |
| 34 | `bne-taken` | Branch if Not Equal (Z=0, taken) |
| 35 | `bne-nt` | Branch if Not Equal (Z=1, not taken) |
| 36 | `beq-taken` | Branch if Equal (Z=1, taken) |
| 37 | `bge-taken` | Branch if >= 0 (N=V=0, taken) |
| 38 | `blt-taken` | Branch if < 0 (N=1, V=0, taken) |
| 39 | `bcc-taken` | Branch if Carry Clear (C=0, taken) |
| 40 | `bcs-taken` | Branch if Carry Set (C=1, taken) |

### Phase H — JSR/RTS（2 件）

| # | mnemonic | 説明 |
|---|----------|------|

| # | mnemonic | 説明 |

## 4. 生成方法

### 全 55 ケースを実行する

```bash
bash scripts/_doTimingSSPDP11.sh
```

### 特定ケースだけ実行する（`-k` オプション）

```bash
# 単一ケース
bash scripts/_doTimingSSPDP11.sh -k "nop"

# 複数ケースを OR で指定
bash scripts/_doTimingSSPDP11.sh -k "mov-r-r or clr-r or add-r-r"
```

`-k` 以降の引数は pytest の `-k` フィルタにそのまま渡される。`mnemonic` 文字列（例: `jsr-r5`, `blt-taken`）で絞り込める。

### 前提条件

実行前に以下を確認する。

- `.venv` が作成済み（`python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`）
- `playwright install chromium` 実行済み
- `examples/09-pdp11/web/sim.wasm` が最新ビルド済み（`scripts/build-wasm-09.sh`）
- ポート 8080 が空いていること
