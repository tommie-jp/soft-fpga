# 42. V6 as アセンブラの制約と落とし穴

このディスクイメージの `/bin/as`（Unix V6 PDP-11 アセンブラ）を
直接使う場合に注意すべき制約をまとめる。  
`cc` 経由でのコンパイルなら通常この問題に当たらない。

---

## 1. ローカル数字ラベル（`1:`、`1f`）は未サポート

このディスクイメージの `as` はローカル数字ラベルを実装していない
古いバージョンである。

```text
# NG — Memory fault -- Core dumped
1:
    add r0,r1
    sob r0,1b    ← 1f / 1b 参照でクラッシュ

# OK — 名前付きラベルを使う
loop:
    add r0,r1
    sob r0,loop
```

---

## 2. `.text` 内の `.word label` は解決されない

`.word label` をテキストセグメント内に置いても、`as` は自力では解決しない。
前方参照・後方参照を問わず、`as` は "u NNNN" メッセージを出して
**リロケーションエントリ（ld 向け）** として扱う。  
`ld` なしで `a.out` を直接実行すると、そのワードは未解決のまま誤ったアドレスになる。

```asm
; NG — .text 内の .word label は as が解決しない
.text
start:
    sys 4
    .word 1
    .word buf     ← buf が .text 内にあっても未解決になる
    .word 1
    sys 1
buf:
    .byte 101     ← 'A'
```

**解決策**: データは `.data` セグメントに置き、`ld` で cross-segment 参照を解決する。

```asm
; OK — .data にデータを置いて ld で解決
.globl start
.text
start:
    sys 4
    .word 1
    .word buf     ← cross-segment ref → ld が解決
    .word 1
    sys 1
.data
buf: <A>
```

```text
# as で生成後、ld でリロケーション解決してから実行
as prog.s
mv a.out prog.o
ld prog.o
a.out
```

> `ld prog.o` のように入力ファイル名を変えておくこと。
> `ld a.out`（入力と出力が同名）は入力を切り詰めてしまう V6 ld の既知問題。

---

## 3. cross-segment 参照は 1 個まで確実

`ld` は `.word label` の cross-segment 参照を処理するが、
**1 ファイルに複数の cross-segment 参照があると 2 番目以降が誤解決される**
場合が確認されている。

| cross-seg ref 数 | 動作 |
|-----------------|------|
| 1 個 | 正常解決（wr.s で確認済み） |
| 2 個以上 | 2 番目以降の解決が壊れる可能性がある |

複数のデータアドレスが必要な場合は、**1 つのデータラベルにまとめる**か、
リロケーションを避ける設計にする。

---

## 4. `ld` は stdout にバイナリを出力する

`ld` はシンボルテーブル等のバイナリデータを stdout へ書き出す。
端末上では無害だが、`a.out` の出力をスクリプトで検査する際に
NUL バイト（`\0`）が混入する点に注意。`strstr` は NUL で止まるため、
NUL 後の文字を検出できない。`memmem` を使うこと。

---

## 5. 正規ワークフロー（推奨）

```text
# 1. C コンパイル（推奨: cc に全部任せる）
cc prog.c
a.out

# 2. アセンブリ直書き（上記の制約を守る場合）
as prog.s          → a.out（1 cross-seg ref 以下のとき直実行可）
# または
as prog.s
mv a.out prog.o
ld prog.o          → a.out（cross-seg ref を ld で解決）
a.out
```

ブランチ命令（`br`、`bne`、`beq` 等）の前方参照は `as` が pass 2 で解決するため、
ラベル間の相対ジャンプには `ld` は不要。

---

## 6. ptrace テストで確認した事実

`tests/v6-scripts/10-ptrace-probe.v6` による実機確認結果:

| テスト | 結果 | 意味 |
|--------|------|------|
| `sys 4`（write）→ `.data` の 1 文字 | 正常出力 | as + ld 動作確認 |
| `sys 2`（fork）→ 親が write | 正常出力 | fork 動作確認 |
| `sys 32`（ptrace TRACEME） + exec | stop しない | →`14-db` §9.1 参照 |
