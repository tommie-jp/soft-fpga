# 62. PDP-11 wasm 版 構造改善メモ

2026-06-10 時点の構造レビュー結果。優先度順に直すべき点を記録する。

---

## 1. 【最優先】`js/` ↔ `web/js/` の手動 cp 同期をやめる ✅ 対応済み

### 1.1 問題

`js/`（ソース）と `examples/09-pdp11/web/js/`（配信コピー）の二重管理が事故を生み続けていた。

- ブラウザが古い `web/js/rtlscope-la.js` を読み「値カラムが表示されない」誤デバッグが発生
- `sft-pdp11-la-defs.js` の `getValue` 追加が `js/` 側に欠落する同期ずれが発生
- `scripts/build-wasm-09.sh` の cp は wasm 再ビルド時しか走らないため、JS のみの変更で必ず stale になる

### 1.2 対応（1c: 配信パスの統一）

8080 版（`examples/06-8080/web/index.html`）と同じ `../../../js/` 直接参照方式に統一した。

- `trigger-expr.js` / `trigger-expr-compiler.js` を `web/js/` から `js/` へ移動（ソースの一元化）
- `index.html` の script タグ 5 本を `../../../js/` 参照に変更
- `tests/trigger/helpers/load-expr.mjs` の読込先を `js/` に変更
- `scripts/build-wasm-09.sh` の web/js cp セクションを削除
- `web/js/` ディレクトリを削除（未使用コピー 4 本含む）

GitHub Pages デプロイは `pages.yml` が `cp -r js _site/js` 済みのため変更不要。

## 2. 【高】index.html のインライン JS 1946 行を分割 ✅ 一部対応済み

`index.html` 2920 行の内訳: インライン JS **1946 行** + CSS 483 行だった。
8080 版は同等機能を `sft-8080-*.js` 群に分割済みで index.html は 1676 行。

切り出し済み（index.html は 2920 → 1776 行）:

| ファイル | 内容 |
| --------- | ------ |
| `js/sft-pdp11.css` | インライン CSS 483 行 |

| `js/sft-pdp11-debug-panel.js` | ブート進行・MMU PAR/PDR・レジスタ・Trap/Mode ログ |
| `js/sft-pdp11-fs-panel.js` | V6 FS jstree・D&D アップロード・折りたたみ/リサイズ |

ハンドラが呼ぶ `_uploadFiles` が D&D 用 IIFE のローカル関数だったため
ReferenceError でボタンが壊れていた。fs-panel.js でトップレベル関数化。

残り候補（インライン約 1400 行）:

| ファイル | 内容 |
| --------- | ------ |

## 3. 【高】sim-worker.js から V6 ファイルシステムを分離 ✅ 対応済み

`sim-worker.js` 1134 行のうち、`v6ReadBlock` / `v6ReadInode` / `v6DskWriteFile` /
`v6DirAddEntry` など **V6 FS 実装が約 6 割**を占めていた。
シミュレーションループと無関係な純粋関数群なので分離した:

- `js/sft-v6fs.js` として独立（worker からは `importScripts('../../../js/sft-v6fs.js')`）
- sim-worker.js は 1134 → 765 行に縮小
- `tests/v6fs/v6fs.test.mjs` に単体テスト 32 件を追加（合成ミニディスクで検証）
- 分離時のテストで **v6ReadInode の潜在バグを発見・修正**: i_size0 を
  オフセット 4（= i_gid）から読んでいたため 64KB 超のファイルサイズが
  欠落していた。正しいオフセット 5 に修正（/unix 等 225KB のカーネル
  ファイルのサイズ表示が正常化）。

## 4. 【中】Playwright 用 sim API の整備

8080 には `sft-8080-sim-api.js` があり、`sim.waitTrigger()` / `sim.write_mem()` /
`sim.set_trigger()` で Web 統合テスト（`verif/web/test_8080.py`、28 件）が書けている。

PDP-11 の `window.sim` には `screenshotCanvas` しかなく、
**PDP-11 の Web 統合テストが存在しない**のはこれが原因。
`sft-pdp11-sim-api.js` を作れば、LA 値カラム・Cycle 表示などの UI 機能も
回帰テストに乗せられる（現状はスクリーンショット目視のみ）。

---

## 5. 【低】ES5 → ES Modules

全 JS が `var` + グローバル汚染の ES5 スタイル。
ESM (`import`/`export`) にすればファイル重複問題も自然に解決するが、
`importScripts` を使う worker や既存の `<script>` 順序依存に手が入るため、
1〜4 を済ませてからで十分。
