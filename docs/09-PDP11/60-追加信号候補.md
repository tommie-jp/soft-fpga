## 2. 追加候補

### 2.1 Logic Analyzer — 高優先

| 信号 | 幅 | 格納先（案） | 理由 |
|------|---|------------|------|
| **istate** | 5 bit | Word4[4:0] | CPU マイクロシーケンサ状態。f1=FETCH, e1=EXEC, t0–t4=TRAP, i1=INT, w1=WAIT 等。パイプライン段が一目瞭然 |
| **isn** | 16 bit | Word4[20:5] | 現在実行中の命令ワード。デコードレーンに助記符（MOV/JSR 等）を出せる |
| **bus_error** | 1 bit | Word3[16] | NXM / I/O no_decode 発生。TRAP より具体的 |
| **trap_abort** | 1 bit | Word3[17] | MMU abort（ベクタ 0o250）。bus_error と分離で原因特定しやすい |
| **waited** | 1 bit | Word3[18] | CPU が DMA / bus_arbitrate 待ちでストール中。RK11 転送との相関 |

### 2.2 Logic Analyzer — 中優先

| 信号 | 幅 | 格納先（案） | 理由 |
|------|---|------------|------|
| **nxm_access** | 1 bit | Word3[19] | 存在しないメモリアクセス。NXM バグ調査時に有用 |
| **iopage_access** | 1 bit | Word3[20] | I/O ページアクセス。デコードレーン IO_RD/IO_WR の根拠信号 |
| **mmu_on** | 1 bit | Word3[21] | MMR0[0]。MMU 有効化タイミングが見える（ブート初期） |
| **trap_bus** | 1 bit | Word3[22] | バスエラートラップ（ベクタ 4）限定 |
| **trap_odd** | 1 bit | Word3[23] | 奇数アドレスアクセス |
| **SP** | 16 bit | Word4[31:16] | スタックポインタ。トラップ時の動きを追える |

### 2.3 istate 値一覧（pdp11.v より）

```text
h1 = 5'b00000  HALT
f1 = 5'b00001  FETCH（命令フェッチ）
c1 = 5'b00010  COMPUTE（アドレス計算）
s1 = 5'b00011  SRC1（ソースオペランド）
s2 = 5'b00100  SRC2
s3 = 5'b00101  SRC3
s4 = 5'b00110  SRC4
d1 = 5'b00111  DST1（デストオペランド）
d2 = 5'b01000  DST2
d3 = 5'b01001  DST3
d4 = 5'b01010  DST4
e1 = 5'b01011  EXECUTE（実行）
w1 = 5'b01100  WRITE-BACK
o1 = 5'b01101  OUTPUT1
o2 = 5'b01110  OUTPUT2
o3 = 5'b01111  OUTPUT3
p1 = 5'b10001  PUSH STATE（トラップ準備）
t0 = 5'b10010  TRAP0（ベクタ決定）
t1 = 5'b10011  TRAP1
t2 = 5'b10100  TRAP2
t3 = 5'b10101  TRAP3（PSW push）
t4 = 5'b10110  TRAP4（PC push）
i1 = 5'b10111  INTERRUPT
```

### 2.4 デコードレーン拡張案

現在: `FETCH / MEM_RD / MEM_WR / IO_RD / IO_WR / TRAP`

追加候補:

| ラベル | 判定条件 | 色 |
|-------|---------|---|
| `INT` | istate==i1 | 紫 |
| `WAIT` | waited==1 | 灰 |
| `NXM` | nxm_access==1 | 赤紫 |
| `ABORT` | trap_abort==1 | 橙 |
| `JSR/RTT` 等 | isn の上位ビットデコード | — |

## 3. レジスタパネル追加候補

| 項目 | 内容 | 実装難度 |
|------|------|---------|
| **istate** 助記符 | f1→FETCH, e1→EXEC, t0→TRAP 等 | 低（JS のみ） |
| **isn** + 簡易ニモニック | `012700` → `MOV #,R0` | 中（デコード関数が必要） |
| **Kernel SP / User SP** | R6[0] / R6[3]（モード別 SP） | 低（harness に既存） |
| **MMR0 raw** | 16 進 1 ワード直接表示 | 中（obs を追加） |
| **trap_type** | Bus / Abort / Odd の区別 | 低（信号追加後） |

---

## 4. 新規パネル候補

| パネル | 内容 | 実装難度 |
|-------|------|---------|
| **Trap ログ** | 直近 8〜16 件のトラップ履歴（PC・ベクタ・モード） | 中（JS 側 CircularBuffer） |
| **MMU D-space** | データ空間 PAR/PDR（Kernel/User）。大きなプロセス解析に必要 | 低（MMU 取得ロジック拡張） |
| **命令統計** | FETCH 回数・TRAP 回数・INT 回数の簡易カウンタ | 低 |

---

## 5. 実装優先順（体感）

1. `bus_error / waited / mmu_on / nxm_access` — 1 bit 信号、Word3 高 16 bit に収まる
2. `istate (5 bit) + isn (16 bit)` — Word4 に収まる。LA に追加すると視覚的インパクト大
3. `SP (16 bit)` — Word4[31:16]。harness.cpp に GPR 配列がすでにある
4. Kernel SP / User SP レジスタパネル追加 — JS のみ
5. Trap ログパネル — JS 側のみ、ring buffer 変更不要
