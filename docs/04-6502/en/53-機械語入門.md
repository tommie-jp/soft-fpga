# 53. 6502 Machine Language Primer — Learn by Running Code in Woz Monitor

Write machine code directly into Woz Monitor and run it to gain hands-on understanding of 6502 behavior.
Each example is structured so that internal signals can be observed via the soft-FPGA Logic Analyzer and Register Panel.

---

## 1. How to Enter Code in Woz Monitor

```text
XXXX: AA BB CC ...    ← address : byte sequence  to write
XXXX.YYYY             ← dump address range (read back to verify)
XXXXR                 ← execute from address
```

Unless noted otherwise, examples are written to `$0300` and started with `0300R`.
They loop infinitely; reset to stop the Logic Analyzer.

## 3. Fundamentals

### 3.1 LDA Loop (5 bytes) — Observing the Fetch Cycle

```text
0300: A9 55 4C 00 03
```

```asm
LDA #$55      ; A ← $55 (immediate)
JMP $0300     ; jump back to $0300
```

What you can see:

- Register Panel: A is always `$55`
- Logic Analyzer: `sync` pulses every 2 clocks (1 instruction = 1 fetch + execute cycle)
- Logic Analyzer: `addr` repeats `$0300 → $0301 → $0300 …`

> A cycle with `sync=1` is an instruction fetch; all others are operand reads or execute cycles.
> This minimal example lets you confirm 6502's non-pipelined sequential execution.

---

### 3.2 Memory Read / Write (9 bytes) — Observing the WE Signal

```text
0300: A9 AA 85 10 A5 10 4C 00 03
```

```asm
LDA #$AA
STA $10       ; WE=1, write to $0010
LDA $10       ; WE=0, read from $0010
JMP $0300
```

What you can see:

- Logic Analyzer: a red `we=1` segment appears at `$0010` (STA)
- Logic Analyzer: the following LDA reads the same address with `we=0`
- Register Panel: A goes `$AA → $AA` (what was written can be read back)

> The zero page (`$0000–$00FF`) uses 1-byte addressing and is 1 cycle faster (ZP access: 3 cycles, ABS: 4 cycles).

---

### 3.3 Flags and Conditional Branch (11 bytes) — Observing Flag Behavior

```text
0300: A9 FF 69 01 B0 03 4C 10 03 4C 00 03
```

```asm
         LDA #$FF
         ADC #$01   ; A=$00, C=1, Z=1, N=0
         BCS $030C  ; C=1 so branch taken → $030C (JMP $0300)
         JMP $0310  ; never reached (would indicate a bug)
$030C:   JMP $0300
```

What you can see:

- Register Panel: Flags show `C=1, Z=1`
- Logic Analyzer: cycle count changes depending on whether BCS branches
  - No branch: 2 cycles; same-page branch: 3 cycles; page-cross branch: 4 cycles
- `$FF + $01 = $100` → lower 8 bits = $00; confirm the carry is set

## 4. Stack and Subroutines

### 4.1 Stack Push / Pop (11 bytes) — Observing SP Changes

```text
0300: A9 11 48 A9 22 48 68 68 4C 00 03
```

```asm
LDA #$11
PHA          ; SP: FF→FE, write to $01FF
LDA #$22
PHA          ; SP: FE→FD, write to $01FE
PLA          ; SP: FD→FE, read from $01FE (A=$22)
PLA          ; SP: FE→FF, read from $01FF (A=$11)
JMP $0300
```

What you can see:

- Register Panel: SP changes `FF → FE → FD → FE → FF`
- Logic Analyzer: alternating `we=1` / `we=0` accesses to `$01FF` and `$01FE`
- LIFO (Last In, First Out) behavior confirmed at the signal level

> The 6502 stack is fixed at `$0100–$01FF`. SP pre-decrements (SP-1 before writing on push).

---

### 4.2 JSR / RTS — Subroutine Call (12 bytes)

```text
0300: 20 08 03 20 08 03 4C 00 03 E8 60
```

```asm
$0300: JSR $0308    ; push PC+2 onto stack (2 bytes), jump to $0308
$0303: JSR $0308    ; second call
$0306: JMP $0300
$0308: INX          ; increment X
$0309: RTS          ; pop return address from stack, add 1, load into PC
```

What you can see:

- Register Panel: X increments by 1 on each call (`$01 → $02 → …`)
- Logic Analyzer: JSR writes to `$01FE/$01FF`; RTS reads from them
- Logic Analyzer: JSR takes 6 cycles, RTS takes 6 cycles (longer `sync` intervals)

> RTS sets PC to the popped address + 1 (because JSR pushes PC+2 - 1 = PC+1).

## 5. Addressing Modes

### 5.1 Absolute X Indexed (18 bytes) — How Array Access Works

Place data first, then run:

```text
0320: 11 22 33 44 55
0300: A2 00 BD 20 03 E8 E0 05 D0 F8 4C 00 03
```

```asm
       LDX #$00
loop:  LDA $0320,X  ; read from address $0320 + X
       INX
       CPX #$05
       BNE loop
       JMP $0300
```

What you can see:

- Logic Analyzer: `addr` advances `$0320 → $0321 → $0322 → $0323 → $0324`
- Register Panel: X counts 0 → 1 → 2 → 3 → 4 → 0
- `LDA abs,X` is normally 4 cycles; 5 cycles on a page cross (see example 9)

---

### 5.2 Zero-Page X Indexed (12 bytes) — Speed Advantage of ZP

Place data first:

```text
0050: 11 22 33 44
0300: A2 00 B5 50 E8 E0 04 D0 F9 4C 00 03
```

```asm
       LDX #$00
loop:  LDA $50,X    ; ZP + X access (reads $50–$53 in sequence)
       INX
       CPX #$04
       BNE loop
       JMP $0300
```

What you can see:

- Logic Analyzer: address moves within ZP: `$0050 → $0051 → $0052 → $0053`
- `LDA zp,X` is 4 cycles (same as `LDA abs,X` at 4–5 cycles), but the instruction is **1 byte shorter** (2 bytes vs 3 bytes)

---

### 5.3 Indirect Indexed (zp),Y — Two-Level Pointer (14 bytes)

Place the pointer and buffer first:

```text
0020: 00 04     ← pointer (little-endian $0400)
0300: A0 00 A9 00 91 20 C8 C0 04 D0 F9 4C 00 03
```

```asm
       LDY #$00
       LDA #$00
loop:  STA ($20),Y  ; ZP[$20/$21]=$0400, +Y → write to $0400+Y
       INY
       CPY #$04
       BNE loop
       JMP $0300
```

What you can see:

- Logic Analyzer: a two-level access pattern — ZP reads (`$0020`, `$0021`) followed by a write to `$0400+Y`
- `STA (zp),Y` is 6 cycles (2 ZP reads + address addition + write)

> This mode corresponds to the C pointer write `*(ptr + y) = val`.

## 6. Bit Manipulation

### 6.1 Logical AND / ORA / EOR (12 bytes) — Mask, Set, Toggle

```text
0300: A9 FF 29 0F 09 F0 49 AA 4C 00 03
```

```asm
LDA #$FF
AND #$0F     ; A=$0F — keep lower 4 bits only (mask)
ORA #$F0     ; A=$FF — set upper 4 bits
EOR #$AA     ; A=$55 — flip bits (XOR)
JMP $0300
```

What you can see:

- Register Panel: A changes `$FF → $0F → $FF → $55`
- Register Panel: N flag changes `1 → 0 → 1 → 0` (tracks bit 7)

| Operation | Typical Use |
|-----------|-------------|
| `AND` | Clear/mask flag bits |
| `ORA` | Set flag bits |
| `EOR` | Toggle flag bits, simple encryption |

---

### 6.2 Shift and Rotate (15 bytes) — Interaction with Carry

```text
0300: A9 01 0A 0A 0A 4A 38 2A 6A 4C 00 03
```

```asm
LDA #$01
ASL A        ; A=$02  C=0 (×2)
ASL A        ; A=$04  C=0
ASL A        ; A=$08  C=0
LSR A        ; A=$04  C=0 (÷2)
SEC          ; set C=1
ROL A        ; A=$09  C=0 (rotate left, C enters bit 0)
ROR A        ; A=$04  C=1 (rotate right, C enters bit 7)
JMP $0300
```

What you can see:

- Register Panel: A's bit pattern and C flag interaction can be verified one step at a time
- `ASL`/`LSR` shift bit 7/bit 0 out into C; `ROL`/`ROR` exchange C with the edge bit

> Multi-byte integer shifts are implemented by chaining ROL/ROR from the most significant byte to the least significant.

## 7. Cycle Accuracy

### 7.1 Page-Cross Penalty (13 bytes) — Observing the +1 Cycle

Place data first:

```text
03FF: 42
0300: A2 01 BD FE 02 A0 01 B9 FE 02 4C 00 03
```

```asm
LDX #$01
LDA $02FF,X  ; $02FF + 1 = $0300 (page cross) → 5 cycles
LDY #$01
LDA $02FF,Y  ; same → 5 cycles
JMP $0300
```

What you can see:

- Logic Analyzer: `LDA abs,X` takes 5 cycles on a page cross (the `sync` interval is 1 longer than usual)
- Logic Analyzer: a spurious access to `$02FF` is visible (reproducing real chip behavior)

> A page cross occurs when the upper address byte (A8–A15) changes (e.g., `$02FF → $0300`).
> When the result of address addition falls on a different page, the 6502 performs one extra read at the wrong address.

---

### 7.2 RMW Instructions INC / DEC (11 bytes) — Observing Read-Modify-Write

```text
0300: A9 00 85 20 E6 20 E6 20 C6 20 4C 00 03
```

```asm
LDA #$00
STA $20      ; initialize $20 = $00
INC $20      ; $20 = $01 (5-cycle Read → Modify → Write)
INC $20      ; $20 = $02
DEC $20      ; $20 = $01
JMP $0300
```

What you can see:

- Logic Analyzer: a single `INC` instruction shows back-to-back **read → write** at `addr=$0020`
- Logic Analyzer: one cycle before the write, a dummy write to the same address occurs (real chip behavior)

> RMW (Read-Modify-Write) instructions include INC / DEC / ASL / LSR / ROL / ROR when applied to memory.
> Internally they perform three phases: read → write old value (dummy) → write new value.
> This well-known behavior can cause bugs when interacting with old hardware such as DMA controllers.
