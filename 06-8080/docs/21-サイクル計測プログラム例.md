# 21. サイクル計測プログラム例

`examples/06-8080/` に置いた BDS C のプログラム。`CYCL.H` / `CYCL.C` ([20-サイクルカウンタ.md](20-サイクルカウンタ.md)) と組み合わせて使う。
コンパイルと実行の手順、**実測の出力**は [22-クロック計測とベンチマーク手順.md](22-クロック計測とベンチマーク手順.md) にまとめた。

> **2026-10-13 に書き直した**: 初版はこのページで `sw/cpm/bench/` の `calib.c`・`instbench.c`・`sort.c` を説明し、出力の予想値を載せていた。
> その置き場は無く、実物は下の表のファイルで、`instbench.c` に当たるのは `BENCH.C`。予想値は実測と合わなかったので消した (実測は 22)。

## 1. プログラムの一覧

| ファイル | 中身 | ループの回数 |
|----------|------|-------------|
| `CALIB.C` | 空ループと、`inp(0x10)` を 4 回入れたループを比べ、カウンタが動いているかを見る | 100 |
| `SORT.C` | バブルソートと挿入ソートを、逆順と乱数の並びで比べる | 要素 16 |
| `BENCH.C` | `inp()`・`outp()`・配列の読み書き・`int` の加算・C の関数呼び出しを、それぞれループに入れて差を取る | 100 |
| `FREQ.C` | ウォールクロックとカウンタから、シミュレーションの等価な周波数を出す | 5000 |
| `CYCL.H` / `CYCL.C` | `cycl_reset()`・`cycl_read()` と、周波数の計測の関数 | — |

BDS C 1.60 は `#asm` が使えないので、命令の代わりに `inp()` / `outp()` と純 C の演算で差を作る。

## 2. 数を読むときの注意

- カウンタは `clk` 1 周期ごとに 1 増え、**1 T ステートで 2 増える**。プログラムが「T」と書いて出す数は T ステート数の 2 倍
- `int` は 16 ビットの符号付きで、差は `%d` で出す。差が 32767 を越えると負の数になる。実測では CALIB・SORT・BENCH のどれもこのあふれを含む (22 の § 2.3〜4.3)
- `inp()` や配列の読み書きは関数呼び出しやアドレス計算を含むので、あふれが無くても命令 1 つの T ステートにはならない

命令 1 つの T ステートを確かめるなら、アセンブラからカウンタを読む ([20 の § 3](20-サイクルカウンタ.md)) か、
Vitest のタイミングテスト ([26-Vitestタイミングテスト.md](26-Vitestタイミングテスト.md)) を使う。
