# 57. PDP-11 レジスタと istate（CPU マイクロシーケンサ） <a class="qr-link" href="../../../docs/09-PDP11/57-QR.png">QR</a>

PDP-11（`cpus-pdp11` コア）のレジスタと、本プロジェクト固有の観測信号 `istate`
（CPU 内部状態機械）の値の意味をまとめる。レジスタパネル／Logic Analyzer で
何を見ているのかを理解するための資料。

---

## 1. アーキテクチャレジスタ

PDP-11 は **16bit のレジスタを 8 本**持ち、すべて命令から `R0`〜`R7` として一様に扱える。

| レジスタ | 別名 | 役割 |
|---------|------|------|
| R0–R5 | — | 汎用（オペランド・アドレス・インデックス）。C/V6 では R5 をフレームポインタ等に使う |
| **R6** | **SP** | ハードウェアスタックポインタ。JSR/RTS/トラップ/割込みで自動 inc/dec |
| **R7** | **PC** | プログラムカウンタ。PC 相対・即値・絶対アドレッシングに使われる |

### 1.1 PDP-11 の美点: PC と SP も「ただの R7/R6」

PC・SP が汎用レジスタ列の一部なので、**アドレッシングモードが一様に適用**できる。

- 即値 `#n` ＝ `(R7)+`（モード2 on R7）
- 絶対 `@#A` ＝ `@(R7)+`（モード3 on R7）
- スタック push/pop ＝ `-(R6)` / `(R6)+`

### 1.2 SP のモード別バンク（実機）

実機 PDP-11 は **モードごとに別の SP** を持つ（カーネル KSP・ユーザー USP・〔スーパー SSP〕）。
ユーザースタックの暴走がカーネルスタックを壊さないための分離。
本コアは現在モードの有効 SP を `cpu.sp`（`wire [15:0]`）として公開する。

### 1.3 PSW（Processor Status Word）

```text
bit: 15 14 | 13 12 | 11 |  7  6  5 | 4 | 3 2 1 0
     CM      PM      GR    IPL       T   N Z V C
```

| フィールド | bit | 意味 |
|-----------|-----|------|
| CM | 15:14 | 現在モード（00=kernel / 01=super / 10=undef / 11=user） |
| PM | 13:12 | 直前モード（mfpi/mtpi の「previous space」選択に使う → [[56-MMU-unix-v6-での使われ方]]） |
| GR | 11 | レジスタセット（11/45+ のみ。本コアでは基本未使用） |
| IPL | 7:5 | プロセッサ優先度（0–7）。これ以下の割込みはマスク |
| T | 4 | トレーストラップ（命令単位デバッグ）。デバッガが使う |
| N Z V C | 3:0 | コンディションコード（負・ゼロ・オーバーフロー・キャリー） |

> モード定数（`pdp11.v`）: `mode_kernel=00` / `mode_super=01` / `mode_undef=10` / `mode_user=11`。

## 2. 本プロジェクトが公開するレジスタ

ハーネス（[`harness.cpp`](../../examples/09-pdp11/cxx/harness.cpp)）の GPR スナップショット
`gpr_snap[8]` は次の並び:

| index | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|-------|---|---|---|---|---|---|---|---|
| 内容 | R0 | R1 | R2 | R3 | R4 | R5 | **SP** | **istate** |

- **PC** は別 API `get_pc()` で取得。
- **PSW・istate・モード・バスサイクル**はリングバッファ（Logic Analyzer）にも毎サンプル記録される。
- つまり register パネルの 8 番目に出る値は CPU の**マイクロシーケンサ状態 `istate`**であり、
  以降で各値の意味を解説する。

## 3. istate（CPU マイクロシーケンサ）の値の意味

`istate` は `reg [4:0]`（5bit）の **CPU 内部状態機械**。1 命令は複数の istate を
遷移しながら実行される（命令エミュレータには存在しない、RTL 可視化ならではの観測点）。
定義は [`pdp11.v`](../../vendor/cpus-pdp11/rtl/pdp11.v) の `parameter` ブロック。

### 3.1 値の一覧

| 値(2進) | 10進 | 記号 | フェーズ | 内容 |
|---------|------|------|---------|------|
| 00000 | 0 | **h1** | halt | 停止（HALT 命令） |
| 00001 | 1 | **f1** | fetch | 命令フェッチ。`isn ← M[PC]`、`PC++` |
| 00010 | 2 | **c1** | decode | 命令デコード |
| 00011 | 3 | **s1** | source | ソースオペランド実効アドレス計算 stage1（`ss_data`） |
| 00100 | 4 | **s2** | source | 〃 stage2 |
| 00101 | 5 | **s3** | source | 〃 stage3 |
| 00110 | 6 | **s4** | source | ソースオペランド値の確定 |
| 00111 | 7 | **d1** | dest | デスティネーション実効アドレス計算 stage1（`dd_data`） |
| 01000 | 8 | **d2** | dest | 〃 stage2 |
| 01001 | 9 | **d3** | dest | 〃 stage3 |
| 01010 | 10 | **d4** | dest | デスティネーションオペランド値の確定 |
| 01011 | 11 | **e1** | execute | ALU 実行。結果 `e1_result`、`PC`/`SP` 更新 |
| 01100 | 12 | **w1** | writeback | 結果をメモリ／レジスタへ書き戻し |
| 01101 | 13 | **o1** | pop | RTI/RTT: スタックから PC を pop（`SP++`） |
| 01110 | 14 | **o2** | pop | PSW を pop（`SP++`） |
| 01111 | 15 | **o3** | pop | レジスタを pop（`SP++`） |
| 10001 | 17 | **p1** | push | スタックへ push（mem write、`SP--`） |
| 10010 | 18 | **t0** | trap | トラップ/割込み開始: old-PC・old-PSW を保存 |
| 10011 | 19 | **t1** | trap | ベクタから新 PC を読む（mem read） |
| 10100 | 20 | **t2** | trap | ベクタ+2 から新 PSW を読む（mem read） |
| 10101 | 21 | **t3** | trap | old-PSW を push（mem write、`SP--`） |
| 10110 | 22 | **t4** | trap | old-PC を push（mem write、`SP--`） |
| 10111 | 23 | **i1** | interrupt | 割込み待ち（WAIT 命令） |

> 16（10000）など一部のコードは未使用（5bit 空間の歯抜け）。

### 3.2 1 命令の実行フロー

```text
通常命令:   f1 → c1 → [s1..s4] → [d1..d4] → e1 → [w1]
RTI/RTT:    f1 → c1 → o1 → o2 (→ o3)
トラップ:    … → t0 → t1 → t2 → t3 → t4 → f1（ハンドラへ）
HALT:       … → h1
WAIT:       … → i1（割込みで抜ける）
```

- **最短 3 状態**（例: モード0 のレジスタ間命令 `f1→c1→e1`）、**最長 12 状態**（`pdp11.v` コメント）。
- `s1..s4` / `d1..d4` の**使う段数はアドレッシングモードで決まる**:

| モード | 記法 | 使う段（dest 例） |
|--------|------|------------------|
| 0 | `R` | d1 のみ（`dd_data = R`） |
| 1 | `(R)` | d1 → d4 |
| 2 | `(R)+` | d1（`R++`）→ d4 |
| 3 | `@(R)+` | c1/d1 → d4 |
| 4 | `-(R)` | d1（`R--`）→ d4 |
| 5 | `@-(R)` | d1 → d2 → d4 |
| 6 | `X(R)` | d1（`ea=PC`）→ d2（`+R`）→ d4 |
| 7 | `@X(R)` | d1 → d2 → d3 → d4 |

### 3.3 トラップ系列と MMU abort

`t0..t4` がトラップ/割込みのベクタ処理。MMU abort（ページ違反、ベクタ 0o250）も
この系列に乗り、新 PC/PSW をベクタから読み、old-PC/old-PSW をカーネルスタックへ
push する（[[56-MMU-unix-v6-での使われ方]] のスタック expand-down / `grow()` と直結）。

## 4. 観測ポイント（可視化の勘所）

| 信号 | 場所 | 用途 |
|------|------|------|
| R0–R5 / SP | register パネル（`gpr_snap[0..6]`） | 命令実行前後のレジスタ変化 |
| **istate** | register パネル末尾（`gpr_snap[7]`）＋ ring `[4:0]` | **どのマイクロ状態にいるか**を逐次追える |
| PC | `get_pc()` | 実行アドレス・トリガ |
| PSW（CM/PM/IPL/T/NZVC） | ring バッファ | モード遷移・優先度・フラグ |
| バスサイクル（DATI/DATO） | ring / LA | f1/d4/w1/t1-t4 でのメモリアクセス |

Logic Analyzer で `istate` を並べると、「`f1→c1→d1→d4→e1` と進む」「トラップで
`t0..t4` に分岐」「mode が user→kernel に変わる」といった**命令の内部進行が波形で見える**。
これは命令エミュレータでは観測できない、本プロジェクト固有の価値。
