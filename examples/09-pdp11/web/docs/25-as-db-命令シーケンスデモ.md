# 25. Unix V6 の as / db で命令シーケンス図を見るデモ

Unix V6 自身のアセンブラ `as` とデバッガ `db` で小さなプログラムを書き、
そのプログラムが特定の命令を実行する瞬間を soft-FPGA の **Logic Analyzer（LA）** で
フリーズ捕捉して、**命令のバスサイクル・シーケンス図**を表示するデモ。

> **`db` はプロンプトを出さない（重要）** —
> Unix V6 の `db`（V7 以降の `adb` の前身）は、起動しても `>` のような
> **プロンプトを一切表示しない**。`db a.out` を実行すると黙って入力待ちになるだけなので、
> 「プロンプトが出ない＝固まった」と誤解しやすい。固まってはいない。
> そのまま `0?6i` のようなコマンドを入力して Enter を押せば即座に応答する。
> `$q` で終了する。（`adb` はこのディスクには無いことがある。`db` を使うこと。）
>
> **このデモが成立する理由** —
> LA の `PC 値一致` トリガは、命令フェッチ時の**仮想アドレス**（`obs_addr_v`、16bit）と
> 入力値を比較する（[harness.cpp](../../examples/09-pdp11/cxx/harness.cpp) `TRIG_PC`）。
> `db` が逆アセンブルで表示するアドレスも同じ**仮想アドレス**なので、
> `db` で調べたアドレスをそのまま LA トリガに入れれば、その命令で波形がフリーズする。
> ソフトウェアデバッガ（命令レベル）とハードウェアデバッガ（クロックレベル）が
> **同じ仮想アドレス空間で出会う**のがこのデモの肝。

[22-全命令タイミング図.md](22-全命令タイミング図.md) ／

## 1. 全体の流れ

1. Unix V6 をブートしてシェルプロンプト（`#`）まで進める
2. `EDITOR` ボタンでアセンブリソース `loop.s` を作成する
3. `as loop.s` でアセンブルし `a.out` を生成する
4. `db a.out` で逆アセンブルし、捕捉したい命令の**仮想アドレス**と**命令語**を読む
5. Web UI の `Trigger` パネルで `PC + データ一致`（推奨）に VA と命令語を設定（`Set`）
6. `./a.out` を実行 → LA がその命令でフリーズ（`FROZEN` バッジ点灯）
7. 命令シーケンス図（T-state・istate・Unibus バスサイクル）を読む

## 2. 題材プログラム（as で書く小ループ）

R0 を初期値から 0 までカウントダウンしながら R1 に積算する短いループ。
命令の並びが単純で、ループ本体のバスサイクルが LA で観察しやすい。

`EDITOR` ボタン（ツールバー）を押し、ファイル名 `loop.s` で以下を入力する。
コマンドラインへの直接貼り付けは UART が文字化けするため、必ず EDITOR を使う
（[14 章 §11](14-adb-デバッガー-使い方.md) 参照）。

```asm
| loop.s — count down R0, accumulate into R1
start:
        mov     $1000,r0        | R0 = 0o1000 (512 iterations; wide window for trigger)
        clr     r1              | R1 = 0 (accumulator)
loop:
        add     r0,r1           | R1 += R0
        sob     r0,loop         | R0--; branch to loop if non-zero
        sys     1               | exit syscall (assembles to trap 0o104401)
```

### 2.1 V6 `as` 構文メモ

- コメントは `|` から行末まで。`/` は除算演算子なのでコメントには使えない。
- ラベルは `name:`。即値は `$n`（8 進。`$1000` は 0o1000）。
- `sys 1` は `exit` システムコール。`as` では `trap` 命令（0o104401）に展開される。
- `sob r0,loop` は PDP-11/40 以降の「Subtract One and Branch」。1 命令でループを回せる。
  - `sob` 非対応の素朴な環境では `dec r0` ＋ `bne loop` でも等価
    （[24 章 ケース 04/34](24-全命令タイミング図-解説.md) のタイミングを合成した形になる）。
- 外部参照がない自己完結プログラムなので、`as` が出力する `a.out` はそのまま実行可能
  （`ld` 不要）。

## 3. アセンブルと逆アセンブル

### 3.1 アセンブル

```text
# as loop.s
# ls -l a.out
```

`as loop.s` は出力を `a.out` に書く。エラーがなければ何も表示されない。

### 3.2 db で逆アセンブルしてアドレスを読む

```text
# db a.out
0?6i
```

> **プロンプトは出ない。** `db a.out` を実行しても何も表示されないが、固まってはいない。
> そのまま `0?6i` を入力して Enter を押す（§冒頭の注記参照）。

`0?6i` は **a.out ファイル**（`?`）の先頭（仮想アドレス 0）から 6 命令を逆アセンブルする。
V6 の a.out はテキストセグメントを仮想アドレス 0 からロードし、エントリも 0 番地なので、
先頭命令が 0 番地に並ぶ。

期待される表示（**例** — 実際の値は `db` の出力で必ず確認すること）:

```text
0:      mov     $1000,r0
4:      clr     r1
6:      add     r0,r1
10:     sob     r0,6
12:     sys     1
```

| 仮想アドレス(8) | 命令語(8) | 命令 |
|----------------|-----------|------|
| `0` | `012700` `001000` | `mov $1000,r0`（2 ワード = 4 バイト）|
| `4` | `005001` | `clr r1`（1 ワード）|
| `6` | `060001` | `add r0,r1` ← **捕捉対象**|
| `10` | `077002` | `sob r0,loop` |
| `12` | `104401` | `sys 1`（exit）|

ここでは**ループ本体の `add r0,r1`（仮想アドレス `0o6`、命令語 `060001`）**を捕捉対象にする。
オペコード `060001` は PDP-11 命令フォーマット（ADD `06` ＋ src=R0 `00` ＋ dst=R1 `01`）からも
確認できる。`$q` で `db` を抜ける。

```text
$q
```

> **補助:** ラベルアドレスだけなら `nm a.out` でも確認できる（`0000006 T loop` のように
> 8 進で表示される）。バイナリを直接見たい場合は `od -o a.out`（先頭 16 バイトがヘッダ）。

## 4. Logic Analyzer トリガの設定

Web UI 右側の `Trigger` パネルで設定する。トリガ種別は 2 通りある。

### 4.1 `PC + データ一致`（推奨・確実）

仮想アドレス（VA）に加えて**バスデータ（命令語＝オペコード）**も照合する種別。
VA とオペコードは a.out 固有の固定値なので、**別プロセスが「同じ VA に同じオペコード」を
持つ確率は極小**。Unix V6 のマルチプロセス環境でも自分のプログラムを一意に捕捉できる。

1. `種別` を **`PC + データ一致`** にする。
2. `PC(8)` に捕捉対象の仮想アドレスを **8 進**で入力する（この例では `6`）。
3. `DATA(8)` に同じ命令の**命令語**を **8 進**で入力する（この例では `add r0,r1` の `060001`）。
   命令語は §3.2 の `db` 逆アセンブル（または [22 章](22-全命令タイミング図.md) の対応表）で確認する。
4. `Set` を押す。

> 内部的には VA を下位 16bit、オペコードを上位 16bit にパックして `sim_set_trigger`
> （[harness.cpp](../../examples/09-pdp11/cxx/harness.cpp) `TRIG_PC_DATA`）に渡し、
> フェッチ時に `obs_addr_v == VA && obs_data == opcode` の両成立で発火する。

### 4.2 `PC 値一致`（簡易）

VA だけで判定する従来種別。アイドルなシステムでは十分機能するが、
マルチプロセス下では別プロセスが同じ VA を踏むと誤検出しうる（§6 参照）。
手早く試したいときや単一プロセスが確実なときに使う。

1. `種別` を **`PC 値一致`** にする。
2. `PC(8)` に仮想アドレスを **8 進**で入力する。
3. `Set` を押す。

### 4.3 ズーム

LA のズームは `Logic Analyzer` ヘッダの倍率セレクトで **`8x`** 程度にすると
1 命令のバスサイクルが画面に収まりやすい（[24 章](24-全命令タイミング図-解説.md) と同じ zoom=8）。

## 5. 実行と捕捉

シェルでプログラムを実行する。

```text
# ./a.out
```

PC がループ本体（仮想アドレス `0o6`）に到達した瞬間、LA がリングバッファへの書き込みを止め、
`FROZEN` バッジが点灯し、`⏸ Triggered!` が表示される。
この時点の LA キャンバスが **`add r0,r1` 命令の命令シーケンス図**になる。

### 5.1 波形の読み方

[24 章 ケース 21（ADD R0, R1）](24-全命令タイミング図-解説.md) と同じ読み方:

- `istate`: マイクロシーケンサ状態。`f1`（フェッチ）→ `s1`/`s4` → 実行と遷移する。
- Unibus 波形: オペコード FETCH の 1 バスサイクル（レジスタ間演算なのでメモリ参照なし）。
- バスデータ語が **`060001`**（`add r0,r1` のオペコード）になっていることを確認する。
  → これが一致すれば、捕捉したのは確かに自分のプログラムの命令。

ループの前後（`clr r1` / `sob r0,loop`）まで波形に含めたい場合は、ズームを下げる（`1x`〜`2x`）か、
トリガを `sob`（仮想アドレス `0o10`）に変えて取り直す。

## 6. 確実に自分のプログラムを捕捉するコツ

### 6.1 まず `PC + データ一致` を使う（本命）

§4.1 の `PC + データ一致` を使えば、VA に加えてオペコードも照合するため、
別プロセスが同じ VA を踏んでも**オペコードが一致しない限り発火しない**。
これがマルチプロセス下での誤検出を実質的に排除する第一手段。

- `PC(8)` と `DATA(8)` の組は a.out 固有の固定値なので、**実行ごとの再計算が不要**。
  一度設定すれば `./a.out` を何度実行しても同じ命令で確実に止まる。
- 入力する `DATA` は必ず**その VA に存在する命令語**にすること
  （別の VA の命令語を入れると、フェッチ遷移時のバスデータ残留にまれに反応する）。

### 6.2 `PC 値一致`（簡易）を使う場合の補助

VA だけの `PC 値一致` を使うときは、以下で誤検出を抑える。

- **アイドル状態で実行**: シェルプロンプトで他に何も動いていない状態で `Set` → 直後に `./a.out`。
  プロンプト待機中のシェルは `read()` でカーネルにブロックされており、ユーザー命令を実行しない。
- **ループ回数を多めに**: 題材の `mov $1000,r0`（0o1000=512 回）のように回数を増やすと、
  捕捉窓の間に自分のループが何度も対象アドレスを踏むため当たりやすい。
- **誤検出したら `Resume`**: 別プロセスで止まった場合は `Resume` で再武装する。
  自分のループは多数回まわっているので、再武装直後に自分の命令で再び止まる。
- **バスデータ語で照合**: フリーズ後、波形のバスデータが自分の命令語（例 `060001`）と
  一致するかを必ず確認する。一致しなければ `Resume` で取り直す。

## 7. 応用

- **メモリ参照命令を観察**: `add r0,r1` を `add (r2),r1` 等に変えると、
  メモリ READ のバスサイクルが 1 本増える（[24 章 Phase F](24-全命令タイミング図-解説.md) と同じ）。
- **EIS のマルチサイクル待機**: `mul r1,r0` を入れると `mul1616` の ~16 クロック待機が
  istate のフラット期間として見える（[24 章 Phase N](24-全命令タイミング図-解説.md)）。
  ただし V6 の `as` が `mul` を受理するか、対象カーネルが EIS 前提かは確認すること。
- **MMU の動き**: ループ実行中は MMU が User I-space を引き続けるので、
  GPR パネル・MMU パネルと合わせて観察すると教育効果が高い
  （[20-デバッグパネル-使い方.md](20-デバッグパネル-使い方.md)）。

## 8. 自作プログラムの仮想・物理アドレス確認

LA トリガに入力する仮想アドレスや、物理メモリ上の配置を調べるコマンドをまとめる。

### 8.1 仮想アドレスの確認

ユーザープロセスの仮想アドレスは常に **0 番地** から始まる。

#### `size` — セグメントサイズ

```text
# size a.out
text   data   bss
  26      0     0
```

text / data / bss のバイト数を 10 進で表示。
仮想配置は text=0 から始まり、data・bss がその直後に続く。

#### `nm` — シンボルテーブル（8 進仮想アドレス）

```text
# nm a.out
0000006 T loop
0000000 T start
```

各ラベルの仮想アドレスを 8 進で表示。`T` はテキストセグメントのシンボル。
§3.2 の `db` 逆アセンブルで見たアドレスと同じ値になることを確認できる。

#### `od` — a.out ヘッダ直読み

```text
# od -o a.out | head -1
0000000  000407  000032  000000  000000  000000  000000  000001  000000
```

先頭ワードがマジック（`000407` = non-split I/D）。以降は 8 進バイト数。

| ワード位置 | 内容 |
|-----------|------|
| 1 | テキストサイズ（バイト） |
| 2 | データサイズ（バイト） |
| 3 | BSS サイズ（バイト） |
| 5 | エントリーポイント（通常 0） |

### 8.2 物理アドレスの確認（MMU PAR 経由）

ユーザープロセスの物理アドレス先頭は **PAR0 × 64 バイト** で求まる。
プログラム実行中（`./a.out &` のバックグラウンド実行、または LA フリーズ中）に
Web UI の `MMU — Page Address Registers` パネルで **User APR0** の値を読む。

```text
物理アドレス先頭 = PAR0（8進） × 0100 = PAR0 × 64 バイト
```

User APR0–7 で 8 ページ（最大 8 KB × 8 = 64 KB）の物理マッピングが見える。
テキスト・データ・スタックがそれぞれどの物理ページに割り当てられているかが分かる。

### 8.3 C でセグメント境界を表示するワンライナー

リンカが自動定義するシンボル `etext`・`edata`・`end` でセグメント境界を表示できる。

```c
/* showmap.c */
extern int etext, edata, end;
main() {
    printf("text end : %o\n", &etext);
    printf("data end : %o\n", &edata);
    printf("bss  end : %o\n", &end);
}
```

```text
# cc showmap.c && ./a.out
text end : 232
data end : 17560
bss  end : 17560
```

値は 8 進。`&end` がデータ＋BSS セグメントの末尾アドレスで、`sbrk(0)` の初期値と一致する。
物理アドレスは §8.2 の MMU パネルで確認する（仮想アドレス → PAR 変換は MMU が行う）。

## 9. このデモの位置づけ

| ツール | 観測対象 | 粒度 | このデモでの役割 |
|--------|---------|------|------------------|
| V6 `as` | ソース → 機械語 | 命令レベル | 題材プログラムを作る |
| V6 `db` | プロセスのメモリ・レジスタ・逆アセンブル | 命令レベル | 捕捉対象の仮想アドレス・命令語を調べる |
| LA（PC トリガ） | Unibus 信号・バスサイクル | クロックレベル | 命令シーケンス図を捕捉・表示 |

[24 章](24-全命令タイミング図-解説.md) の 61 ケースが**ベアメタルで生成した教材波形**であるのに対し、
本デモは**実際に動く Unix V6 上のユーザープログラム**を同じ波形ビューで観察する点が異なる。
「OS 上で走るプログラムの 1 命令を、ハードウェアのバスサイクルまで降りて見る」体験を提供する。
