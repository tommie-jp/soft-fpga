# 33. 最初のプロセスは、カーネルが手で写した 11 語 <a class="qr-link" href="../../../docs/09-PDP11/img/33-QR.png">QR</a>

UNIX のプロセスは、どれも `fork` で作られます。親がいなければ、子は生まれません。
それなら最初のプロセスは誰が作るのか。UNIX Version 6 の答えは、`sys/ken/main.c` の 2 つのコメントにあります。

> Icode is the octal bootstrap program executed in user mode to bring up the system.
>
> Return goes to loc. 0 of user init code just copied out.

訳すと次のようになります。

> icode は、システムを立ち上げるためにユーザーモードで実行される、8 進数で書いたブートストラップのプログラムである。
>
> リターンは、いま写したユーザーの初期化コードの 0 番地へ行く。

2 つのコメントは、次の 3 つのことを言っています。

| 番号 | コメントが言っていること |
| --- | --- |
| 1 | カーネルは、8 進数で書いた小さなプログラムをユーザーの空間へ写す |
| 2 | `main()` からリターンすると、そのプログラムの 0 番地に着く |
| 3 | そのプログラムはユーザーモードで動き、システムを立ち上げる |

この記事では、Verilog で書いた PDP-11 の上で本物の Unix V6 を起動し、3 つを波形で 1 つずつ確かめます。
使うのは [09-PDP-11 / Unix V6](https://tommie-jp.github.io/soft-fpga/examples/09-pdp11/web) のデバッグパネルです。

---

## 1. 該当のコード

`icode` は、`main.c` の先頭にある 11 語の配列です。

```c
int     icode[]
{
        0104413,        /* sys exec; init; initp */
        0000014,
        0000010,
        0000777,        /* br . */
        0000014,        /* initp: init; 0 */
        0000000,
        0062457,        /* init: </etc/init\0> */
        0061564,
        0064457,
        0064556,
        0000164,
};
```

C の配列ですが、中身は機械語です。0 番地から置いたときの意味は、次のとおりです。

| 番地（8 進） | 語 | 意味 |
| --- | --- | --- |
| 000 | 104413 | `sys exec`。引数は次の 2 語 |
| 002 | 000014 | 実行するファイルの名前の番地（014） |
| 004 | 000010 | 引数の表の番地（010） |
| 006 | 000777 | `br .`。`exec` が失敗したら、ここで回り続ける |
| 010 | 000014 | 引数の表。0 番目は名前の番地（014） |
| 012 | 000000 | 表の終わり |
| 014〜024 | 062457 … 000164 | 文字列 `/etc/init` と終わりの 0 |

C で書けば `execl("/etc/init", "/etc/init", 0);` の 1 行に当たります。

使うのは、`main()` の最後です。

```c
        if(newproc()) {
                expand(USIZE+1);
                estabur(0, 1, 0, 0);
                copyout(icode, 0, sizeof icode);
                /*
                 * Return goes to loc. 0 of user init
                 * code just copied out.
                 */
                return;
        }
        sched();
```

ここまでの `main()` は、メモリを数え、プロセス 0 を手で作っています。
`newproc()` はそのプロセス 0 を写して、プロセス 1 を作ります。`fork` と同じ関数で、親には 0 を、子には 1 を返します。
親のプロセス 0 は `sched()` へ進み、二度と戻りません。スワップを受け持つプロセスになります。

子のプロセス 1 は `if` の中へ入ります。`expand` と `estabur` でユーザーの空間を 64 バイトだけ用意し、`copyout` で `icode` をそこへ写します。
そして `return` します。

`main()` を呼んだのは、アセンブラで書かれた `conf/m40.s` の `start` です。

```asm
/ set up previous mode and call main
/ on return, enter user mode at 0R

        mov     $30000,PS
        jsr     pc,_main
        mov     $170000,-(sp)
        clr     -(sp)
        rtt
```

`main` から戻ると、PS にする値 170000 と、PC にする値 0 をスタックに積んで `rtt` します。
`rtt` は割り込みから戻る命令です。ここでは、戻る先の割り込みは起きていません。積んだ 2 語は、手で作ったものです。

## 2. 観測の準備

`icode` が動くのは、起動のときの 1 回だけです。トリガーは、カーネルを読み込む前に待ち受けにします。

1. [09-PDP-11 / Unix V6](https://tommie-jp.github.io/soft-fpga/examples/09-pdp11/web) を開く。
2. 上段の **Reset** を押す。端末に `@` が出て、入力を待つ。
3. 次のボタンを押す。
4. 端末をクリックして、`rkunix` と打って Enter を押す。

[▶ この設定を入れる](?scenario=icode)

ページを開いた直後は、`rkunix` が自動で打たれて `login:` まで進みます。Reset のあとは自動では打たれないので、`@` で止まります。

ボタンは次の 3 つの操作をします。手で設定するときも、この順です。

1. **Logic Analyzer** のパネルを開く。
2. **Trigger** の Preset で `V6 icode: first user instruction (sys exec)` を選び、**Set** を押す。
3. LA の信号を `VA`・`PhysAddr`・`Data`・`WR`・`RD`・`PC`・`Mode`・`TRAP`・`SP` だけにする。

プリセットは、0 番地で命令語 104413 をフェッチした tick で発火します。
`rkunix` の Enter から約 727 万 tick あとで、画面では数秒です。端末に何も出ないうちに止まります。

## 3. copyout: 11 語を 1 語ずつ写す

止まったら、波形を左へたどります。トリガーの 525 tick 前から、同じ形が 11 回繰り返されています。

![copyout のループ。カーネルの 057114 番地から読んだ語を、ユーザーの 0 番地から順に書く](docs/img/33-01-la-copyout.png)

`copyout` の中心は、3 命令のループです。

| 番地（8 進） | 命令 | 動き |
| --- | --- | --- |
| 002372 | `mov (r0)+,-(sp)` | カーネルの空間から 1 語読み、スタックに積む |
| 002374 | `mtpi (r1)+` | スタックの 1 語を、ユーザーの空間へ書く |
| 002376 | `sob r2,…` | 残りの語数を減らし、0 でなければ繰り返す |

1 回りは 34 tick です。波形では、次の順に書き込みが並びます。

| tick | 読む番地（カーネル） | 書く番地（ユーザー） | 語 |
| --- | --- | --- | --- |
| -525 | 057114 | 000000 | 104413 |
| -491 | 057116 | 000002 | 000014 |
| -457 | 057120 | 000004 | 000010 |
| -423 | 057122 | 000006 | 000777 |
| … | … | … | … |
| -185 | 057140 | 000024 | 000164 |

`mtpi` は、「前のモード」の空間へ書く命令です。`start` が PS に 30000 を入れたので、前のモードは User になっています。
書き込みの瞬間だけ、`Mode` の線が User に変わります。`VA` は 000000 で、`PhysAddr` は 125300 です。
カーネルの 0 番地は物理メモリの 0 番地ですが、ユーザーの 0 番地は `estabur` が決めた別の場所にあります。

## 4. rtt: 行ったことのない場所へ戻る

倍率を `16x` にして、赤い点線のあたりを見ます。

![main から戻った start が 170000 と 0 を積み、rtt でユーザーの 0 番地へ入る。直後に sys exec がトラップする](docs/img/33-02-la-first-user.png)

| tick | 番地 | 値 | 動き |
| --- | --- | --- | --- |
| -33 | 003504 | 012746 | `mov $170000,-(sp)` をフェッチする |
| -23 | 141776 | 170000 | PS にする値を積む |
| -20 | 003510 | 005046 | `clr -(sp)` |
| -14 | 141774 | 000000 | PC にする値を積む |
| -11 | 003512 | 000006 | `rtt` |
| -6 | 141774 | 000000 | PC を取り出す |
| -3 | 141776 | 170000 | PS を取り出す。Mode が User に変わる |
| 0 | 000000 | 104413 | ユーザーの 0 番地の `sys exec` をフェッチする（トリガー） |

`Mode` の線が、ここで初めて User になります。`rkunix` の Enter から 727 万 tick、この CPU はカーネルモードの命令だけを実行していました。
ユーザーモードで最初に実行する命令が、カーネルの写した 104413 です。SP は 0 で、スタックはまだありません。

プロセス 1 は、`fork` を呼んでいません。それでも、`newproc()` から 1 が返り、`rtt` でユーザーモードへ「戻り」ました。
戻り先の 2 語を手で積めば、行ったことのない場所へも戻れます。
同じやり方は、シグナルの配達（[32 章](?doc=32-signal-asks-the-process-to-do-something-to-itself.md)）でも使われています。

## 5. 最初のシステムコール

ユーザーモードは 5 tick しか続きません。104413 は `sys exec` なので、すぐにトラップします。

| tick | 番地 | 値 | 動き |
| --- | --- | --- | --- |
| +5 | — | — | `TRAP` の線が立つ |
| +10 | 000034 | 000320 | ベクタ 034 から、新しい PC を読む |
| +13 | 000036 | 000346 | 新しい PS を読む |
| +16 | 141776 | 170000 | 元の PS をカーネルスタックに積む |
| +19 | 141774 | 000002 | 戻り番地を積む |
| +22 | 000320 | — | カーネルの `trap` に入る |
| +671 | 000000 | 104413 | `trap()` がユーザーの 0 番地を読み直し、下位 6 ビットから番号 11（`exec`）を取り出す |

今度の 2 語は、ハードウェアが積んだ本物です。4 章で `start` が手で積んだ 2 語と、番地も並びも同じです。

`exec` は `/etc/init` をディスクから読み込み、ユーザーの空間を入れ替えます。`icode` の 11 語は、ここで消えます。
約 54 万 tick あとに、CPU はもう一度ユーザーの 0 番地の命令をフェッチします。今度の語は 170011 です。
`/etc/init` は C で書かれているので、最初の命令は SETD です（[28 章](?doc=28-setd-the-trap-is-ignored.md)）。

上段の **Resume** で再開すると、`login:` が出ます。
`login:` を出している `getty` は、`init` が `fork` して作ったプロセスです。ここから先のプロセスには、すべて親がいます。

## 6. 確かめた結果

| コメントが言っていること | 確かめたこと |
| --- | --- |
| 8 進数で書いた小さなプログラムを、ユーザーの空間へ写す | `copyout` が 34 tick ごとに 1 語、計 11 語をユーザーの 0〜024 番地（物理 125300〜）へ書いた |
| `main()` からリターンすると、その 0 番地に着く | `start` が 170000 と 0 を積んで `rtt` し、11 tick あとに 0 番地の 104413 をフェッチした |
| ユーザーモードで動き、システムを立ち上げる | `rkunix` の Enter から 727 万 tick で初めて Mode が User になった。最初の命令は `sys exec` で、54 万 tick あとに `/etc/init` の最初の命令が動いた |

`icode` がユーザーモードで動いたのは、命令 1 つぶん、5 tick だけです。
プロセス 1 を作る仕事のうち、`fork` に当たる部分はカーネルが手で済ませました。`exec` だけを、ふつうのシステムコールとして実行しています。
