# 29. fork は戻り番地で親と子を分ける <a class="qr-link" href="../../../docs/09-PDP11/img/29-QR.png">QR</a>

`fork` は、親には子のプロセス番号を、子には 0 を返します。UNIX を習うと最初に出会う説明です。
UNIX Version 7 のマニュアル `fork(2)` も、そう書いています。ただし、アセンブラ向けの節に次の一文があります。

> The return locations in the old and new process differ by one word.

訳すと次のようになります。

> 古いプロセスと新しいプロセスとでは、戻る場所が 1 語ずれている。

C ライブラリの `fork.s` には、もう 1 行のコメントがあります。

> in child, parents id is in par_uid if needed

子は 0 を受け取るはずなのに、親のプロセス番号を知っている、と読めます。
2 つを合わせると、カーネルの `fork` は次のように動いていることになります。

| 番号 | 確かめること |
| --- | --- |
| 1 | カーネルは、親の戻り番地だけを 1 語（2 バイト）進める |
| 2 | カーネルが子に渡す値は 0 ではなく、親のプロセス番号 |
| 3 | 0 にするのは、C ライブラリの `clr r0` |

この記事では、Verilog で書いた PDP-11 の上で本物の Unix V6 を動かし、3 つを波形で 1 つずつ確かめます。
使うのは [09-PDP-11 / Unix V6](https://tommie-jp.github.io/soft-fpga/examples/09-pdp11/web) のデバッグパネルです。
V6 のコードは、V7 のマニュアルが書いているとおりに動きます（7 章）。

---

## 1. 該当のコード

C のプログラムが呼ぶ `fork()` は、C ライブラリの `s4/fork.s` です。

```asm
_fork:
        mov     r5,-(sp)
        mov     sp,r5
        sys     fork
                br 1f
        bec     2f
        jmp     cerror
1:
        mov     r0,_par_uid
        clr     r0
2:
        mov     (sp)+,r5
        rts     pc
```

`sys fork` のすぐあとに `br 1f` があり、その次に `bec 2f` があります。
`sys fork` から戻った先が `br 1f` なら、`1:` へ飛んで R0 を `_par_uid` にしまい、R0 を 0 にします。
戻った先が `bec 2f` なら、R0 に手を付けずに `2:` へ進みます。

カーネルの側は `sys/ken/sys1.c` の `fork()` です。

```c
fork()
{
        register struct proc *p1, *p2;

        p1 = u.u_procp;
        for(p2 = &proc[0]; p2 < &proc[NPROC]; p2++)
                if(p2->p_stat == NULL)
                        goto found;
        u.u_error = EAGAIN;
        goto out;

found:
        if(newproc()) {
                u.u_ar0[R0] = p1->p_pid;
                u.u_cstime[0] = 0;
                ...
                return;
        }
        u.u_ar0[R0] = p2->p_pid;

out:
        u.u_ar0[R7] =+ 2;
}
```

`u.u_ar0` は、システムコールに入ったときに退避したユーザーのレジスタを指します。
`u.u_ar0[R0]` に書いた値はユーザーへ戻ったときの R0 になり、`u.u_ar0[R7]` は戻り番地になります。

`newproc()` はプロセスの写しを作り、親には 0 を、子には 1 を返します（[27 章](?doc=27-swtch-You-are-not-expected-to-understand-this.md) 6 節）。
子は `if` の中へ入り、R0 に親のプロセス番号 `p1->p_pid` を入れて `return` します。戻り番地には触りません。
親は `if` を通らず、R0 に子のプロセス番号 `p2->p_pid` を入れ、戻り番地に 2 を足します。

`fork()` のどこにも、0 を入れる行はありません。

## 2. 観測の準備

`fork` を呼ぶプログラムを作る必要はありません。シェルは、コマンドを 1 つ実行するたびに `fork` します。
`/bin/sh` の中の `fork.s` は、次の番地にあります。

| 番地（8 進） | 命令語 | 命令 |
| --- | --- | --- |
| 007776 | 104402 | `sys fork` |
| 010000 | 000403 | `br 1f`（子が戻る場所） |
| 010002 | 103005 | `bec 2f`（親が戻る場所） |
| 010004 | 000167 | `jmp cerror` |
| 010010 | 010067 | `1: mov r0,_par_uid` |
| 010014 | 005000 | `clr r0` |
| 010016 | 012605 | `2: mov (sp)+,r5` |
| 010020 | 000207 | `rts pc` |

[09-PDP-11 / Unix V6](https://tommie-jp.github.io/soft-fpga/examples/09-pdp11/web) を開き、`login:` に `root` で入ります。
`#` のプロンプトが出たら、次のボタンを押します。設定がまとめて入り、トリガーが待ち受けになります。

[▶ 親の戻りで止める設定を入れる](?scenario=fork-parent)

そのあと、端末で `date` を実行します。

ボタンは次の 3 つの操作をします。手で設定するときも、この順です。

1. **Logic Analyzer** のパネルを開く。
2. **Trigger** の Preset で `V6 sh: fork returns in parent (bec 2f)` を選び、**Set** を押す。
3. LA の信号を `VA`・`Data`・`WR`・`RD`・`PC`・`Mode`・`R0`・`SP` だけにする。

プリセットは、010002 番地で命令語 103005 をフェッチした tick で発火します。
番地と命令語の両方を比べるので、カーネルやほかのコマンドの同じ番地では止まりません。

この記事では、1 回の `date` で 3 回止めます。親が戻ったところ（3 章）、カーネルが子の R0 を書くところ（4 章）、子が戻ったところ（5 章）です。
ボタンを押すと、文書の画面は閉じます。次のボタンを押すときは、29 章をもう一度開いて戻ってください。

## 3. 親: 戻り番地が 2 進む

`date` を実行すると、日付が出る前に止まります。止まったのは親のシェルです。
波形を左へたどると、トリガーの約 1000 tick 前に、`fork()` の最後の 2 行が見つかります。

![fork() の最後の 2 行。退避した R0 に子のプロセス番号を、退避した PC に 010002 を書く](docs/img/29-01-la-parent-kernel.png)

| tick | 書く番地 | 書く値 | C の行 |
| --- | --- | --- | --- |
| -1013 | 141772 | 000007 | `u.u_ar0[R0] = p2->p_pid;` |
| -972 | 141774 | 010002 | `u.u_ar0[R7] =+ 2;` |

141772 番地と 141774 番地は、カーネルスタックの底の近くです。システムコールの入口で、ユーザーの R0 と戻り番地がここに退避されています。
`sys fork` は 007776 番地にあるので、退避された戻り番地は次の命令の 010000 でした。そこへ 2 を足して 010002 にしています。
000007 は子のプロセス番号です。ログインして最初のコマンドなら 7 で、実行するたびに 1 ずつ増えます。

途中にクロックの割り込みが入ると、この 2 つの tick は 600 ほど左へずれます。

続きは、トリガーのすぐ手前にあります。倍率を `16x` にして、赤い点線のあたりを見ます。

![親の戻り。rtt が 010002 を取り出し、bec から 2: へ進む。R0 は 7 のまま](docs/img/29-02-la-parent-return.png)

| tick | 番地 | 読んだ値 | 動き |
| --- | --- | --- | --- |
| -18 | 141772 | 000007 | `mov (sp)+,r0` が R0 を戻す |
| -12 | 000522 | 000006 | `rtt` をフェッチする |
| -7 | 141774 | 010002 | PC を取り出す |
| -4 | 141776 | 170010 | PS を取り出す。Mode が User に変わる |
| 0 | 010002 | 103005 | `bec 2f` をフェッチする |
| +6 | 010016 | 012605 | `2: mov (sp)+,r5` |
| +17 | 010020 | 000207 | `rts pc` |

親は `br 1f` を通りません。`bec 2f` は、失敗の印（C ビット）が立っていなければ分岐します。
R0 は 000007 のままで、`fork()` を呼んだ C の関数へ戻り値として渡ります。

## 4. 子のカーネル側: R0 に親のプロセス番号

親で止まったまま、29 章をもう一度開いて、次のボタンを押します。止まっていたシェルは再開します。

[▶ fork() の子の側で止める設定を入れる](?scenario=fork-child-kernel)

端末には何も打ちません。同じ `fork` の子が動き出したところで、すぐに止まります。
プリセットは `V6 fork: child gets parent pid (fork+52)` で、カーネルの 035010 番地の命令 `mov 12(r4),*u_ar0` で発火します。
`fork()` の中で、子だけが通る行 `u.u_ar0[R0] = p1->p_pid;` です。

![子の側の fork()。p1->p_pid の 6 を読み、退避した R0 の 141772 番地へ書く](docs/img/29-03-la-child-kernel.png)

| tick | 番地 | 値 | 動き |
| --- | --- | --- | --- |
| 0 | 035010 | 016477 | `mov 12(r4),*u_ar0` をフェッチする。R0 は 1 |
| +10 | 062734 | 000006 | 親の `proc` から `p_pid` を読む |
| +14 | 140426 | 141772 | `u.u_ar0` を読む |
| +20 | 141772 | 000006 | 退避した R0 に、親のプロセス番号を書く |

R0 の欄の 01 は、`newproc()` の戻り値です。子の側なので 1 になっています。
000006 はシェルのプロセス番号です。ログインしたシェルは、この環境では 6 番になります。
このあとは時間の記録を 0 に戻す `clr` が 6 回続き、141774 番地には何も書きません。戻り番地は 010000 のままです。

## 5. 子: `clr r0` で初めて 0 になる

もう一度 29 章を開いて、次のボタンを押します。

[▶ 子の戻りで止める設定を入れる](?scenario=fork-child)

プリセットは `V6 sh: fork returns in child (br 1f)` で、010000 番地の `br 1f` をフェッチした tick で発火します。

![子の戻り。rtt が 010000 を取り出し、br から 1: へ飛ぶ。R0 は 6 から 0 に変わる](docs/img/29-04-la-child-return.png)

| tick | 番地 | 値 | 動き |
| --- | --- | --- | --- |
| -7 | 141774 | 010000 | `rtt` が PC を取り出す。`sys fork` のすぐあと |
| -4 | 141776 | 170010 | PS を取り出す。Mode が User に変わる |
| 0 | 010000 | 000403 | `br 1f` をフェッチする。R0 は 000006 |
| +6 | 010010 | 010067 | `1: mov r0,_par_uid` |
| +17 | 024300 | 000006 | `_par_uid` に親のプロセス番号を書く |
| +19 | 010014 | 005000 | `clr r0` |
| +26 | 010016 | 012605 | `2: mov (sp)+,r5`。R0 は 000000 |
| +37 | 010020 | 000207 | `rts pc` |

子がユーザーモードへ戻った時点の R0 は 6 です。0 ではありません。
R0 が 0 になるのは、26 tick あとです。`clr r0` を実行したのは C ライブラリで、カーネルではありません。
`2:` から先は、親と同じ命令を通ります。違いは R0 の値だけです。

上段の **Resume** で再開すると、子は `date` を実行し、日付が表示されます。

## 6. 親と子の時間の関係

3 つの取り込みは、1 回の `fork` の別々の時刻です。`sys fork` をフェッチした tick を 0 として並べると、次のようになります。

| tick | プロセス | 出来事 |
| --- | --- | --- |
| 0 | 親 | 007776 番地の `sys fork` をフェッチする |
| 1,097 | 親 | カーネルの `fork()` に入る |
| 123,847 | 親 | `newproc()` が 0 を返す |
| 123,879 | 親 | 退避した R0 に子のプロセス番号を書く |
| 123,920 | 親 | 退避した PC を 010002 にする |
| 124,893 | 親 | 010002 番地へ戻る（3 章） |
| 142,132 | 子 | 初めて CPU を得る |
| 143,586 | 子 | `newproc()` が 1 を返す |
| 143,618 | 子 | 退避した R0 に親のプロセス番号を書く（4 章） |
| 149,518 | 子 | 010000 番地へ戻る（5 章） |

`fork()` の時間のほとんどは `newproc()` です。プロセスの中身を写すのに、約 12 万 tick かかります。
親は先にユーザーモードへ戻り、子の終了を待って眠ります。子が動き出すのはそのあとで、親より 24,625 tick 遅れて戻ります。
子は、4 章の書き込みから 5 章の戻りまでのあいだに、一度 CPU を手放します。4 章と 5 章を分けて止めたのは、そのためです。

## 7. なぜ戻り番地で分けるのか

`newproc()` は、親のプロセスを丸ごと写します。退避したレジスタも戻り番地も、親と同じものが子に入ります。
写しを作った時点では、2 つのプロセスに違いがありません。カーネルは、そこへ違いを 2 つだけ書き足します。R0 の値と、親の戻り番地です。

アセンブラで書くプログラムは、この戻り番地の違いをそのまま使えます。`sys fork` の次の 1 語に、子の行き先への分岐を置くだけです。
R0 を調べる命令は要りません。C ライブラリの `fork.s` は、同じ仕組みの上に「子では 0」という約束を載せています。

V7 でも、この作りは変わりませんでした。カーネルの `fork()` の終わりは次のとおりです。

```c
        if(newproc()) {
                u.u_r.r_val1 = p1->p_pid;
                ...
                return;
        }
        u.u_r.r_val1 = p2->p_pid;

out:
        u.u_ar0[R7] += NBPW;
```

`NBPW` は 1 語のバイト数で、2 です。C ライブラリの `fork.s` も、V6 と同じ `br 1f`・`bec 2f`・`clr r0` の並びです。
冒頭のマニュアルの一文は、この 2 つのコードを説明したものです。

## 8. 確かめた結果

| 確かめること | 確かめたこと |
| --- | --- |
| カーネルは、親の戻り番地だけを 1 語進める | 親では 141774 番地に 010002 を書き、`bec 2f` へ戻った。子では書かず、010000 番地の `br 1f` へ戻った |
| カーネルが子に渡す値は、親のプロセス番号 | 子の側の `fork()` が 141772 番地に 000006 を書いた。子がユーザーモードへ戻った時点の R0 は 000006 |
| 0 にするのは、C ライブラリの `clr r0` | 子は `br 1f` → `mov r0,_par_uid` → `clr r0` と進み、戻ってから 26 tick あとに R0 が 0 になった |

親と子は、戻ってから 2 命令だけ別の道を通り、`2:` で合流します。
`fork()` の戻り値が 0 かどうかを調べる C の `if` は、そのあとで実行されます。
