> However, **copying and pasting text may cause the UART to drop characters**, corrupting the source
> and resulting in `a.out` producing a "syntax error".
> Workaround: use the `ed` editor, or type input into the terminal slowly, one character at a time.
> See [41-cc-コンパイル-バグ調査.md](?doc=41-cc-コンパイル-バグ調査.md) section 10.1 for details.

Unix V6 ships the original C compiler written by Dennis Ritchie (circa 1975).
This predates ANSI C (1989) by 14 years, so the syntax differs from modern C in several ways.

---

## 1. Hello, World

### 1.1 Creating the Source File

Use `ed`, or redirect input with `cat >`.

```text
# cat > hello.c
main()
{
    printf("Hello, World!\n");
}
```

Press **Ctrl-D** (EOF) at the end to close the file.

> Unix V6 C notes
>
> - `#include <stdio.h>` is not needed (`printf` is available implicitly)
> - The return type `int` of `main()` can be omitted
> - A trailing `return` can also be omitted

### 1.2 Compiling

```text
# cc hello.c
```

If there are no errors, `a.out` is generated.

### 1.3 Running

```text
# ./a.out
Hello, World!
```

## 2. Accepting Command-Line Arguments

Use the K&R style (pre-ANSI) function argument declarations.

```text
# cat > greet.c
main(argc, argv)
int argc;
char **argv;
{
    int i;
    if (argc < 2) {
        printf("usage: greet <name>\n");
        exit(1);
    }
    for (i = 1; i < argc; i++)
        printf("Hello, %s!\n", argv[i]);
}
```

```text
# cc greet.c
# ./a.out Unix V6
Hello, Unix!
Hello, V6!
```

## 4. Internal Compiler Pipeline

`cc` is a driver that invokes the following stages in order.
During compilation, the MMU PAR/PDR and GPR change rapidly, making
the combination with the Logic Analyzer view ideal as a demo highlight.

```text
/lib/c0   — front end (lexing and parsing)
/lib/c1   — code generation (PDP-11 assembly output)
/lib/c2   — peephole optimization
/bin/as   — assembler (.s → .o)
/bin/ld   — linker (.o + /lib/libc.a → a.out)
```

To inspect intermediate files:

```text
# cc -S hello.c       # keep assembly as hello.s
# cat hello.s
```

## 5. Common V6 C Pitfalls

| Symptom | Cause | Remedy |
|---------|-------|--------|
| `int` is the default type | Return types and variable types may be omitted | Intentional; no warnings are issued |
| `void` is not available | V6 C has no `void` type | Write `int` for functions with no return value, or omit the type |
| No array bounds checking | Standard C behavior | Boundary checks must be done manually |
| `//` comments not allowed | Only `/* */` is valid | Pre-ANSI C specification |
| Passing `long` to `%d` garbles output | `printf` has no type information | Use `%ld` for `long` (or `%D` in V6) |

```text
# ls /usr/include
```

| Header | Contents |
|--------|----------|

| `signal.h` | Signal number constants |
| `sys/types.h` | Kernel types such as `dev_t` and `ino_t` |

## 7. EIS Instructions

**EIS (Extended Instruction Set)** is an optional PDP-11 instruction group that provides multiplication, division, and arithmetic shifts.

| Instruction | Operation |
|-------------|-----------|
| `MUL Rn, src` | Signed 16×16-bit multiply → 32-bit result stored in Rn/Rn+1 |
| `DIV Rn, src` | Signed 32÷16-bit divide → quotient in Rn, remainder in Rn+1 |
| `ASH Rn, src` | Arithmetic shift (positive=left, negative=right, up to ±31 bits) |
| `ASHC Rn, src` | 32-bit arithmetic shift (Rn:Rn+1 shifted as a unit) |

The `cc` compiler uses `MUL`/`DIV` when generating code for integer multiply and divide operations.

### 7.1 Status in This Project (cpus-pdp11)

This RTL (Brad Parker `cpus-pdp11`) **implements EIS**.
Confirmed passing the MAINDEC diagnostic test FKACA0 (11/34 EIS instruction test).
