# 26. Expression Trigger (Expr Trigger) Reference <a class="qr-link" href="../../../docs/09-PDP11/img/26-en-QR.png">QR</a>

Explains the syntax, signal mapping, and internal architecture of the "Expr" trigger  
in the PDP-11 debug panel.

---

## 1. Overview

An **expression trigger** is a trigger type that lets you describe a stop condition by combining multiple signals with an arbitrary boolean expression.

- Captures compound conditions that cannot be expressed with a `PC value match` or built-in triggers
- Allows simultaneous specification of address and CPU mode, e.g. `VA == 06 && Mode == "USER"`
- Supports edge detection (`.rising` / `.falling` / `.edge`) attached to any signal

### Comparison with Other Trigger Types

| Type | Condition | Speed |
|------|-----------|-------|
| PC value match | Specific virtual address (Wasm hardware) | ★★★ |
| I/O page | I/O page access detection (Wasm hardware) | ★★★ |
| Bus Error / TRAP | Bus error / trap detection (Wasm hardware) | ★★★ |
| **Expr** | Arbitrary compound condition (Wasm native evaluation) | ★★☆ |

---

## 2. Configuration Steps

1. Switch the `Type` selector to **`Expr`**
2. Enter a condition expression in the expression input field (CodeMirror editor)
   - Use Ctrl+Space for signal name and value autocompletion
3. Click the `Set` button
   - The sampling interval is automatically switched to **1tick/smpl** (see below)
4. Click `▶ Run` to start the simulation
5. When the condition is met, the LA stops and `⏸ Triggered!` is displayed

## 3. Expression Syntax Reference

### 3.1 Comparison Operators

```text
==    equal
!=    not equal
<     less than (unsigned)
>     greater than (unsigned)
<=    less than or equal (unsigned)
>=    greater than or equal (unsigned)
```

The right-hand side of a comparison accepts a numeric literal or a string literal (depending on the signal).

### 3.2 Edge Detection

```text
signal.rising    0 → 1 rising edge
signal.falling   1 → 0 falling edge
signal.edge      either rising or falling
```

Examples:

```text
RD.rising               the moment RD transitions from 0 to 1
RD.rising && istate == "F1"   instruction fetch start
```

### 3.3 Logical Operators

```text
&&    AND (both true)
||    OR (either true)
!     NOT
()    grouping
```

### 3.4 Numeric Literals

```text
010     octal (traditional PDP-11 notation)
0o10    octal (0o prefix)
0x10    hexadecimal
10      decimal
```

### 3.5 String Literals

```text
"USER"     case-insensitive ("user" is also accepted)
"KERNEL"
"F1"       istate state name
```

## 4. Signal Reference and Support Status

### 4.1 Key Signals

| Signal | Description | Numeric compare | String compare | Edge detect |
|--------|-------------|:---------------:|:--------------:|:-----------:|
| `VA` | Virtual address bus | ✅ | ❌ | ✅ |
| `PC` | Program counter (already +2 after fetch) | ✅ | ❌ | ✅ |
| `RD` | Bus read strobe | ✅ | ❌ | ✅ |
| `WR` | Bus write strobe | ✅ | ❌ | ✅ |
| `Mode` | CPU mode | ✅ | ✅ `"KERNEL"` `"SUPER"` `"USER"` | ✅ |
| `istate` | Internal state machine state | ✅ | ✅ (see table below) | ✅ |
| `ISN` | Instruction register (raw opcode) | ✅ | ❌ | ✅ |
| `PSW` | Processor status word | ✅ | ❌ | ✅ |
| `Cycle` | Bus cycle type (virtual signal) | ❌ | ❌ | ❌ |
| `R0`–`R5` | General-purpose registers | ✅ | ❌ | ✅ |
| `SP` | Stack pointer (R6) | ✅ | ❌ | ✅ |
| `bus_error` | Bus error flag | ✅ | ❌ | ✅ |

### 4.2 String Values for `istate`

```text
H1     HALT state
F1     instruction fetch
C1     instruction decode
S1–S4  source address calculation
D1–D4  destination address calculation
E1     execute
W1     write-back
O1–O3  offset calculation
P1     push (JSR)
T0–T4  trap sequence
I1     interrupt acknowledge
```

### 4.3 Alternatives for Cycle / ISN String / PSW String

`Cycle` (virtual signal), string comparison for `ISN`, and string comparison for `PSW` are not currently supported by the Wasm compiler.  
An error message and suggested alternative expressions are shown at compile time.

| Goal | Alternative expression |
|------|------------------------|
| `Cycle == "FETCH"` | `RD.rising && istate == "F1"` |
| `Cycle == "MEM_RD"` | `RD == 1 && istate != "F1"` |
| `Cycle == "MEM_WR"` | `WR == 1` |
| `ISN == "CLR R1"` | `ISN == 0o5001` |
| `ISN == "MOV R0,R1"` | `ISN == 0o10001` |
| Check PSW N flag | `PSW == 0o10` or `PSW >= 0o10 && PSW < 0o20` (numeric compare) |
| Check PSW C flag | `PSW == 1` |

## 5. Usage Examples

### 5.1 Capture an Instruction at a Specific Address in User Mode

```text
VA == 06 && Mode == "USER"
```

Stops when the instruction at VA=6 (octal) is executed in user mode.  
Adding `Mode == "USER"` prevents false positives when the kernel accesses the same virtual address.

### 5.2 Detect the Rising Edge of an Instruction Fetch Start

```text
RD.rising && istate == "F1" && Mode == "USER"
```

Captures the exact moment a user-process instruction fetch begins.

### 5.3 Specify an Address Range

```text
VA >= 04 && VA <= 012 && Mode == "USER"
```

Captures every instruction in the loop body (virtual addresses 4–10 in octal).

### 5.4 Stop on a Write

```text
WR.rising && VA == 0xfffe
```

Captures the start of a write to a specific address.

### 5.5 Capture a Specific Kernel Address

```text
VA == 015670
```

Omitting the Mode specifier captures both kernel and user accesses.

## 6. `VA` vs `PC`

| Signal | Description |
|--------|-------------|
| `VA` | Virtual address on the bus (corresponds to the instruction address) |
| `PC` | CPU internal PC register (already incremented by +2 after fetch) |

**Use `VA` when specifying a particular instruction address.**  
`PC` is auto-incremented after fetch, so its value is 2 greater than the instruction's virtual address.

---

## 7. Automatic Sampling Rate Switch

When you click `Set`, the LA header's **sampling interval** is automatically switched to **1tick/smpl**.

| Sampling | Setting | Use case |
|----------|---------|----------|
| 4tick/smpl | `ring_tick_mask = 3` | Normal operation / Unix V6 speed priority (default) |
| 1tick/smpl | `ring_tick_mask = 0` | Expression trigger (prevents missed samples) |

At 4tick/smpl, conditions that hold for only one tick (e.g. a single-clock-wide bus strobe) may be missed.  
Clearing the expression trigger (`Clear` or switching to a PC trigger) restores the original rate according to the selector.

## 8. Internal Architecture (Reference)

```text
UI thread
  │  _trigParse(exprStr)       → AST
  │  trigCompileToWasm(ast)    → Wasm binary (Uint8Array, ~70-150 bytes)
  │  postMessage({type:'set_expr_trigger', wasmBytes}, [wasmBytes])
  ↓
Worker thread
  │  new WebAssembly.Module(bytes) / new WebAssembly.Instance(mod, {})
  │  eval = inst.exports.eval    ← native Wasm function: i32×18 → i32
  │
  └─ simLoop() each frame:
       scan all new samples in ring buffer
       eval(w0..w8, pw0..pw8)    ← ~2–5 ns/sample
       → if true, trigger and stop
```

Signature of the Wasm function generated by `trigger-expr-compiler.js`:

```text
(i32×9, i32×9) → i32
 ├── params 0-8:  ring buffer words for the current sample w0..w8
 └── params 9-17: ring buffer words for the previous sample pw0..pw8 (for edge detection)
```

No memory is shared; each sample's ring words are passed directly as parameters.  
Synchronous instantiation inside the Worker is possible, so the async `WebAssembly.instantiate` API is not needed.
