# 14. db — Unix V6 デバッガの使い方

このディスクイメージには `/bin/db`（Unix V6 標準デバッガ）と
`/bin/cdb`（C 言語用デバッガ）が収録されている。ここでは `db` を扱う。

> **`db` は静的ファイルデバッガ** —
> 多くのデバッガと違い、`db` は調べる対象のコアイメージの一部としてロードされない。
> 代わりに **ファイルを開いて中身を検査**する。検査できるのは
>
> - **a.out**（実行ファイル）— テキスト／データを逆アセンブル・ダンプする
> - **core**（異常終了時のコアダンプ）— フォルト時のレジスタ・メモリを事後解析する
>
> ブレークポイント・ステップ実行・プログラム起動といった**実行制御機能は持たない**。
> 動的に追いたい場合はプログラムを直接実行し、落ちたら生成された `core` を解析する。

---

## 1. 起動

```text
# db a.out             ← a.out を検査（逆アセンブル・ダンプ）
# db core a.out        ← コアダンプを a.out のシンボル付きで事後解析
```

`db` は**プロンプトを表示しない**。起動すると黙って入力待ちになる
（固まったわけではない）。そのままコマンドを入力して Enter を押す。
`%` で終了する。

---

## 2. アドレス式

検査コマンドの前にアドレス（式）を置く。式は次の要素から組み立てる。

| 要素 | 意味 |
|------|------|
| シンボル名 | アセンブリのシンボル値（`start` など）|
| 8 進数 | 絶対値（例: `777`）|
| 10 進数 + `.` | 絶対値（例: `123.`）|
| 8 進数 + `r` | 再配置可能量（relocatable、例: `100r`）|
| `.` | 現在位置（カレントポインタ）|
| `*expr` | 間接参照（その番地のワードが指す先）|
| `+` / 空白 | 加算（再配置量は 1 つまで）|
| `-` | 減算 |

評価は左から右へ。レジスタ名 `r0`〜`r5` / `sp` / `pc` / `fr0`〜`fr5` も
式に使える（主に core 検査時に意味を持つ）。

---

## 3. 検査コマンド

書式は `address<コマンド文字>`。コマンド文字が**表示フォーマット**を兼ねる
（フォーマット文字列を別途取るのではなく、1 文字で番地と表示形式を指定する）。

| コマンド | 説明 |
|---------|------|
| `/` | その番地のワードを 8 進で表示 |
| `\` | その番地のバイトを 8 進で表示 |
| `"` | その番地のワードを ASCII 2 文字で表示 |
| `\|` | その番地のバイトを ASCII 1 文字で表示 |
| `g` | その番地のワードを 10 進で表示 |
| `?` | その番地を**機械語命令として逆アセンブル**（シンボル付き）|
| `&` | その番地を**シンボリックアドレス**として表示（最近傍シンボル + オフセット）|
| `<Enter>` | カレント位置を進め、直前と同じフォーマットで表示 |
| `^` | カレント位置を 1 つ戻し、直前と同じフォーマットで表示 |
| `%` | 終了 |

実行例:

```text
0?              ← 0 番地を 1 命令逆アセンブル
<Enter>         ← 次の命令へ
start?          ← シンボル start の番地を逆アセンブル
0200/           ← 0200 番地のワードを 8 進表示
msg"            ← msg の中身を ASCII で表示
```

---

## 4. 連続表示（count）

アドレスのうしろに `,式` を付けると、そのコマンドを**式の回数だけ連続実行**する。

```text
0,6?            ← 0 番地から 6 命令を逆アセンブル
0200,20/        ← 0200 番地から 20 ワードを 8 進表示
```

カレント位置は最後に表示した位置まで進む。

---

## 5. 式の評価

アドレス空間に触れず、式そのものを評価する。

| コマンド | 説明 |
|---------|------|
| `=` | 直前の式の値を 8 進で表示（式がなければ `.` の値）|
| `:` | 直前の式をシンボリックアドレス（シンボル + オフセット）で表示 |

```text
start=          ← start の番地を 8 進で表示
1000+10=        ← 式の評価結果（1010）を表示
4014:           ← 4014 を最近傍シンボル名 + オフセットで表示
```

---

## 6. メモリ書き換え

| コマンド | 説明 |
|---------|------|
| `!` | 直前の式の値を、現在の `.` が指す番地に格納する |

`!` は必ず式を前置する。`.`（カレント位置）に向けて書き込むので、
先に検査コマンドで対象番地を開いてから使う。

```text
0200/           ← 0200 を開く（. = 0200 になる）
177777!         ← 0200 番地に 177777 を書き込む
```

---

## 7. レジスタ／フォルト表示

| コマンド | 説明 |
|---------|------|
| `$` | フォルト種別と汎用レジスタ・各種レジスタを 8 進＋シンボリックで表示 |

`$` は **core ファイル検査時**にもっとも有用で、プログラムが
どのフォルト（不正命令・バスエラー等）で・どのレジスタ状態で
落ちたかを表示する。

---

## 8. 典型的な使い方

### 8.1 a.out を逆アセンブルしてアドレスを読む

`as` でアセンブルしたプログラムの命令を仮想アドレス付きで読む。
Logic Analyzer の PC トリガに入れる仮想アドレスの確認に使う
（→ [25-as-db-命令シーケンスデモ.md](25-as-db-命令シーケンスデモ.md)）。

```text
# as loop.s
# db a.out
0,6?            ← 先頭から 6 命令を逆アセンブル
%
```

> 補助: シンボルのアドレスだけなら `nm a.out`、生バイト列なら
> `od -o a.out` でも確認できる（`od` の先頭 8 ワードは a.out ヘッダ）。

### 8.2 コアダンプの事後解析

プログラムが落ちると `core` ファイルが生成される。`db core a.out` で
フォルト時の状態を調べる。

```text
# ./a.out            ← バスエラー等で落ちる → core 生成
# db core a.out
$                    ← フォルト種別とレジスタを表示
pc?                  ← 落ちた pc の命令を逆アセンブル
sp,10/               ← スタック先頭 10 ワードをダンプ
%
```

---

## 9. このシミュレータでの注意

- **実行制御は無い** — V6 `db` はそもそもブレークポイント・ステップ・
  プログラム起動を持たない（静的ファイルデバッガ）。動的に追いたい場合は
  プログラムを直接実行し、落ちたら `core` を `db` で解析する流れになる。
- **動作確認は a.out 直接実行で** — 自己完結プログラムなら `as` 出力の
  `a.out` をそのまま実行できる。正常終了ならプロンプトに復帰する。

  ```text
  # a.out
  #      ← 出力なし・プロンプト復帰 = 正常終了
  ```

- **a.out が "syntax error" になる場合** — コマンドラインに直接ソースを
  貼り付けると UART が文字化けし、`cc`/`as` が壊れた `a.out` を生成する
  ことがある。**EDITOR ボタン**でソースを入力すれば文字化けしない。

## 10. Web UI デバッグパネルとの併用

`db` は Unix プロセスレベル（命令レベル）のデバッガである。
soft-FPGA の **Logic Analyzer** と **GPR パネル** は RTL（ハードウェア）
レベルのデバッガで、観測の粒度が違う。

| ツール | 観測対象 | 粒度 |
|--------|---------|------|
| `db` | a.out / core のメモリ・レジスタ・逆アセンブル | 命令レベル |
| GPR パネル | CPU レジスタのリアルタイム表示 | クロックレベル |
| Logic Analyzer | Unibus 信号・バスサイクル | クロックレベル |

`db` で調べた**仮想アドレス**をそのまま LA の PC トリガに入れれば、
その命令のバスサイクルをハードウェアレベルで捕捉できる
（→ [25-as-db-命令シーケンスデモ.md](25-as-db-命令シーケンスデモ.md)）。

→ [20-デバッグパネル-使い方.md](20-デバッグパネル-使い方.md)
