# 14. db — Unix V6 デバッガの使い方 <a class="qr-link" href="../../../docs/09-PDP11/img/14-QR.png">QR</a>

このディスクイメージには `/bin/db`（Unix V6 標準デバッガ）と
`/bin/cdb`（C 言語用デバッガ）が収録されている。ここでは `db` を扱う。

> **⚠️ このシミュレータでは `db` および `cdb` は動作しない（既知の未解決問題・調査中）**
>
> `db` / `cdb` はどちらも内部で `fork` → `ptrace(0)` → `exec` を行い、
> ptrace（sys 26）経由で対象プロセスを制御する**動的デバッガ**である。
> このシミュレータでは ptrace の fork/exec/stop() フローが正常に完了せず、
> `Trace/BPT trap -- Core dumped` または `Bus error -- Core dumped` でクラッシュする。
> T-bit（PSW[4]、ベクタ 14）は RTL に実装済みだが、V6 カーネルの
> ptrace 実装がこのシミュレーション環境と整合しない。
>
> **現在できないこと（`db` / `cdb` 関連）:**
>
> - `db a.out` / `cdb a.out` — Bus error または Trace/BPT trap でクラッシュ
> - `db core a.out` — コアダンプ事後解析（同様にクラッシュ）
> - ブレークポイント設定・シングルステップ実行
> - 実行中プロセスのメモリ／レジスタ検査
>
> **調査中の対応策:** 根本原因は `V6 カーネルソースの exec() に psignal(SIGTRC) が欠落`
> していることと確定済み（→ §9.1）。ディスクイメージへのバイナリパッチまたは
> カーネル再コンパイルによる修正を検討しているが、未実施。
> 代替手段として `nm` / `od` / デバッグパネルを使うこと（→ §8.1・§10）。
>
> コマンド構文の説明（§2〜§8）は参照用として残してある。
> **仮想アドレスの確認には `nm a.out` または `od -o a.out` を使うこと**（§8.1 参照）。

---

## 1. 起動

```text
# db a.out             ← a.out を検査（逆アセンブル・ダンプ）
# db core a.out        ← コアダンプを a.out のシンボル付きで事後解析
```

`db` は**プロンプトを表示しない**。起動すると黙って入力待ちになる
（固まったわけではない）。そのままコマンドを入力して Enter を押す。
`%` で終了する。

---

## 2. アドレス式

検査コマンドの前にアドレス（式）を置く。式は次の要素から組み立てる。

| 要素 | 意味 |
|------|------|
| シンボル名 | アセンブリのシンボル値（`start` など）|
| 8 進数 | 絶対値（例: `777`）|
| 10 進数 + `.` | 絶対値（例: `123.`）|
| 8 進数 + `r` | 再配置可能量（relocatable、例: `100r`）|
| `.` | 現在位置（カレントポインタ）|
| `*expr` | 間接参照（その番地のワードが指す先）|
| `+` / 空白 | 加算（再配置量は 1 つまで）|
| `-` | 減算 |

評価は左から右へ。レジスタ名 `r0`〜`r5` / `sp` / `pc` / `fr0`〜`fr5` も
式に使える（主に core 検査時に意味を持つ）。

---

## 3. 検査コマンド

書式は `address<コマンド文字>`。コマンド文字が**表示フォーマット**を兼ねる
（フォーマット文字列を別途取るのではなく、1 文字で番地と表示形式を指定する）。

| コマンド | 説明 |
|---------|------|
| `/` | その番地のワードを 8 進で表示 |
| `\` | その番地のバイトを 8 進で表示 |
| `"` | その番地のワードを ASCII 2 文字で表示 |
| `\|` | その番地のバイトを ASCII 1 文字で表示 |
| `g` | その番地のワードを 10 進で表示 |
| `?` | その番地を**機械語命令として逆アセンブル**（シンボル付き）|
| `&` | その番地を**シンボリックアドレス**として表示（最近傍シンボル + オフセット）|
| `<Enter>` | カレント位置を進め、直前と同じフォーマットで表示 |
| `^` | カレント位置を 1 つ戻し、直前と同じフォーマットで表示 |
| `%` | 終了 |

実行例:

```text
0?              ← 0 番地を 1 命令逆アセンブル
<Enter>         ← 次の命令へ
start?          ← シンボル start の番地を逆アセンブル
0200/           ← 0200 番地のワードを 8 進表示
msg"            ← msg の中身を ASCII で表示
```

---

## 4. 連続表示（count）

アドレスのうしろに `,式` を付けると、そのコマンドを**式の回数だけ連続実行**する。

```text
0,6?            ← 0 番地から 6 命令を逆アセンブル
0200,20/        ← 0200 番地から 20 ワードを 8 進表示
```

カレント位置は最後に表示した位置まで進む。

---

## 5. 式の評価

アドレス空間に触れず、式そのものを評価する。

| コマンド | 説明 |
|---------|------|
| `=` | 直前の式の値を 8 進で表示（式がなければ `.` の値）|
| `:` | 直前の式をシンボリックアドレス（シンボル + オフセット）で表示 |

```text
start=          ← start の番地を 8 進で表示
1000+10=        ← 式の評価結果（1010）を表示
4014:           ← 4014 を最近傍シンボル名 + オフセットで表示
```

---

## 6. メモリ書き換え

| コマンド | 説明 |
|---------|------|
| `!` | 直前の式の値を、現在の `.` が指す番地に格納する |

`!` は必ず式を前置する。`.`（カレント位置）に向けて書き込むので、
先に検査コマンドで対象番地を開いてから使う。

```text
0200/           ← 0200 を開く（. = 0200 になる）
177777!         ← 0200 番地に 177777 を書き込む
```

---

## 7. レジスタ／フォルト表示

| コマンド | 説明 |
|---------|------|
| `$` | フォルト種別と汎用レジスタ・各種レジスタを 8 進＋シンボリックで表示 |

`$` は **core ファイル検査時**にもっとも有用で、プログラムが
どのフォルト（不正命令・バスエラー等）で・どのレジスタ状態で
落ちたかを表示する。

---

## 8. 典型的な使い方

### 8.1 a.out の仮想アドレスを調べる代替手段

`db a.out` はこのシミュレータでは動作しないため、仮想アドレスの確認には
以下を使う。

```text
# nm a.out              ← シンボル名と仮想アドレス（8 進）を一覧表示
0000006 T loop
0000000 T start

# od -o a.out           ← バイナリを 8 進ダンプ（先頭 8 ワードが a.out ヘッダ）
# size a.out            ← text / data / bss セグメントのバイト数
```

Logic Analyzer の PC トリガに入れる仮想アドレスは `nm` で確認できる
（→ [25-as-db-命令シーケンスデモ.md](?doc=25-as-db-命令シーケンスデモ.md)）。

### 8.2 コアダンプの事後解析（参考：実機での手順）

プログラムが落ちると `core` ファイルが生成される。実機 PDP-11 では
`db core a.out` でフォルト時の状態を調べる。

```text
# ./a.out            ← バスエラー等で落ちる → core 生成
# db core a.out
$                    ← フォルト種別とレジスタを表示
pc?                  ← 落ちた pc の命令を逆アセンブル
sp,10/               ← スタック先頭 10 ワードをダンプ
%
```

## 9. このシミュレータでの注意

### 9.1 `db` は動作しない（V6 カーネルの exec() バグ）

`db` はあらゆるコマンド（`0,6?`・`%` 含む）で `Bus error -- Core dumped`
でクラッシュする。**根本原因はシミュレータではなく、このディスクイメージの
V6 カーネル自体のバグ**である。

#### 障害シーケンス

1. `db a.out` を実行すると db は内部で `fork()` する
2. 子プロセスが `ptrace(TRACEME=0)` → カーネルが STRC フラグをセット
3. 子が `exec(a.out)` → ここで**カーネルのバグが発動**する
4. 親 db が `wait()` で WIFSTOPPED (status & 0377 == 0177) を期待するが返らない
5. db が ptrace でメモリを読もうとする → ESRCH エラー（子が SSTOP でない）
6. db が戻り値 -1 をポインタとして利用 → **Bus error**

#### カーネルのバグ詳細

正規 V6 ソース（`/usr/sys/ken/sys1.c`）の `exec()` には、
"clear sigs, regs and return" セクションに以下があるはずだが、
**このディスクイメージの exec() にはこの 2 行が欠落している：**

```c
if (u.u_procp->p_flag&STRC)
    psignal(u.u_procp, SIGTRC);
```

この行がないため `exec()` 後も `p->p_sig = 0` のまま、
`issig()` は `stop()` を呼ばず、子プロセスは SSTOP にならない。

#### 検証結果

カーネルソース全探索（`/usr/sys/ken/sys1.c` の全ブロックを raw 読み出し）で確認済み。
probe スクリプト（`ptrace(TRACEME) + exec("/tgt")`）を V6 シェルで実行した結果、
子プロセスは停止せず（`s` でなく `n` を出力）。

RTL レベルの T-bit（PSW[4]）・トレーストラップ（ベクタ 14）・mfpi の
前モード選択はいずれも正しく実装済み。修正にはカーネルの再コンパイルが必要。

### 9.2 動作確認は a.out 直接実行で

自己完結プログラムなら `as` 出力の `a.out` をそのまま実行できる。
正常終了ならプロンプトに復帰する。

```text
# a.out
#      ← 出力なし・プロンプト復帰 = 正常終了
```

### 9.3 a.out が "syntax error" になる場合

コマンドラインに直接ソースを貼り付けると UART が文字化けし、
`cc`/`as` が壊れた `a.out` を生成することがある。
**EDITOR ボタン**でソースを入力すれば文字化けしない。

## 10. Web UI デバッグパネルとの併用

`db` が動作しないため、アドレスレベルの観測は以下で代替する。

| ツール | 観測対象 | 粒度 | 備考 |
|--------|---------|------|------|
| `nm a.out` | シンボル仮想アドレス | 命令レベル | `db` の代替 |
| `od -o a.out` | バイナリダンプ | バイトレベル | ヘッダ・オペコード確認 |
| GPR パネル | CPU レジスタのリアルタイム表示 | クロックレベル | |
| Logic Analyzer | Unibus 信号・バスサイクル | クロックレベル | |

`nm` で調べた**仮想アドレス**をそのまま LA の PC トリガに入れれば、
その命令のバスサイクルをハードウェアレベルで捕捉できる
（→ [25-as-db-命令シーケンスデモ.md](?doc=25-as-db-命令シーケンスデモ.md)）。

→ [20-デバッグパネル-使い方.md](?doc=20-デバッグパネル-使い方.md)
