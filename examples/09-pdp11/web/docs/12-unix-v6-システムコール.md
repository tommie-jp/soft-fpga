# 12. Unix V6 システムコール参考 <a class="qr-link" href="../../../docs/09-PDP11/12-QR.png">QR</a>

Unix V6（1975）のシステムコール一覧。このシミュレータ上で `as` / C で
低レベルプログラムを書くとき、また Logic Analyzer でトラップ
（`sys` 命令 = `trap`）を観測するときの参考。

カーネル側の定義は `/usr/sys/ken/sysent.c`、ユーザ側のマクロは
`/usr/source/s4/*.s`（C ライブラリのスタブ）にある。

## 1. 呼び出しの仕組み

システムコールはアセンブラの `sys` 擬似命令で発行する。これは
PDP-11 の `trap` 命令にアセンブルされる。

```text
sys n   →   trap 命令 (8 進 104400 + n)
```

- `sys 1` = `104401`（`exit`）
- トラップ番号 `n` が `sysent[]` のインデックスになる
- カーネルは trap ベクタ経由で `trap()`（`/usr/sys/ken/trap.c`）に入り、
  `sysent[n]` のハンドラを呼ぶ

### 1.1 引数の渡し方

V6 は **インライン引数**方式。`sys` 命令の直後のメモリワードに引数を並べ、
カーネルがユーザ空間の PC 位置から読み取る。

```asm
| write(fd, buf, count) の例
mov     $1, r0          | fd = 1 (標準出力) を r0 に
sys     write; msg; 13. | buf=msg, count=13（10進）をインライン配置
```

- 一部の呼び出しは第 1 引数を **r0** で渡す（`read` / `write` の fd など）
- 残りの引数は `sys` 命令の後ろにインライン配置
- C ライブラリのスタブがこの配置を隠蔽する

### 1.2 戻り値とエラー

- 戻り値は **r0**（必要なら r1 も）に入る
- **キャリービット（C フラグ）** がエラー表示
  - C=0 … 成功
  - C=1 … エラー、r0 にエラー番号
- C ライブラリは C=1 を見て大域変数 `errno` に格納し、`-1` を返す

### 1.3 間接呼び出し（`indir`, sys 0）

`sys 0`（`indir`）は別アドレスにある `sys` 命令を間接実行する。
動的にシステムコール番号を切り替えるトリック。

```asm
sys     indir; callspot  | callspot 先の sys 命令を実行
```

| 4 | `SIGINS` | 不正命令 |
| 5 | `SIGTRC` | トレーストラップ（T ビット） |
| 6 | `SIGIOT` | IOT 命令 |
| 7 | `SIGEMT` | EMT 命令 |
| 8 | `SIGFPT` | 浮動小数点例外 |
| 9 | `SIGKIL` | kill（捕捉・無視不可） |

## 4. アセンブラでの最小例

「hello」を標準出力に書いて終了する V6 アセンブリ。`as` で
アセンブルできる（コメント文字は `|`、数値はデフォルト 8 進、
`.` 付きで 10 進）。

```asm
| hello.s — write(1, msg, 6) して exit(0)
.globl  start
start:
        mov     $1, r0          | fd = 1 (stdout)
        sys     write; msg; 6   | write(1, msg, 6)
        sys     exit            | exit()
msg:
        <hello\n>               | 文字列（\n 込みで 6 バイト）
```

```text
as hello.s          | a.out が生成される
a.out               | "hello" と表示
```

> このシミュレータでは `db` がプロンプトを出さない仕様のため、
> 動作確認は `a.out` を直接実行して確認する（詳細は
> [25-as-db-命令シーケンスデモ.md](?doc=25-as-db-命令シーケンスデモ.md)）。

### 4.1 逆アセンブル結果（機械語ダンプ）

上記 `hello.s` をアセンブルしたテキストセグメント（仮想アドレス 0 起点で
ロードされる前提）。すべて 8 進。`sys n` が `trap` 命令 `104400+n` に
化けている点に注目。

```text
アドレス  機械語   逆アセンブル          備考
000000   012700   mov   $1, r0          | MOV: 01 src=27(即値) dst=00(r0)
000002   000001                          |  └ 即値 1
000004   104404   sys   write           | trap = 104400 + 4 (write)
000006   000014        msg              |  └ インライン引数: buf = msg(=000014)
000010   000006        6.               |  └ インライン引数: count = 6
000012   104401   sys   exit            | trap = 104400 + 1 (exit)
000014   062550   msg:  <he>            | 'e'(0145)<<8 | 'h'(0150)
000016   066154         <ll>            | 'l'(0154)<<8 | 'l'(0154)
000020   005157         <o\n>           | '\n'(012)<<8 | 'o'(0157)
```

- テキストサイズ = `000022`（8 進）= 18 バイト（コード 12 + 文字列 6）
- 文字列は PDP-11 のリトルエンディアンで **下位バイトが先**。語単位で
  読むと `<he> <ll> <o\n>` のように 2 文字ずつ入れ替わって見える
- `write` の第 1 引数 fd は r0 で渡すため、インライン引数は `buf`・`count`
  の 2 ワードだけ（§1.1 参照）

実機・SIMH での確認コマンド（`od` は 8 進ワードダンプ）。

```text
od a.out            | a.out 全体（先頭に 8 ワードの a.out ヘッダが付く）
od -o a.out         | 同上（明示的に 8 進ワード）
nm a.out            | シンボル表（start / msg のアドレス確認）
```

> `od a.out` の先頭 8 ワードは a.out ヘッダ（マジック `0407` ＝ 通常実行形式、
> テキスト長・データ長・bss 長・シンボル表長・エントリ点ほか）。
> 上のテキストはヘッダの **次のワードから**始まる。

## 5. Logic Analyzer での観測

`sys` 命令は `trap` にアセンブルされるため、デバッグパネルの
**TRAP トリガ**で捕捉できる。

- トリガ種別 `TRIG_TRAP` を選ぶと、システムコールのトラップ進入で発火
- トラップベクタ経由でカーネルの `trap()` に入る流れ
  （PSW 退避 → ベクタフェッチ → カーネルモード遷移）を T-state 単位で観測できる
- トラップ番号 `104400+n` のフェッチが見えるので、どのシステムコールか判別可能

詳細は [20-デバッグパネル-使い方.md](?doc=20-デバッグパネル-使い方.md) と
[21-バスサイクル実例.md](?doc=21-バスサイクル実例.md) を参照。
