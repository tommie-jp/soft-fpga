# 32. シグナルは、プロセスが自分で自分に配る <a class="qr-link" href="../../../docs/09-PDP11/img/32-QR.png">QR</a>

UNIX Version 6 のカーネルには、シグナルの仕組みを 1 文で言い切ったコメントがあります。
`sys/ken/sig.c` の、`issig()` の前です。

> A signal does not do anything directly to a process; it sets a flag that asks the process to do something to itself.

訳すと次のようになります。

> シグナルは、プロセスに直接は何もしない。プロセスが自分自身に何かをするよう求める旗を立てるだけだ。

キーを押すとプログラムが止まるので、シグナルは外からプロセスを動かす仕組みに見えます。コメントは、そうではないと言っています。
確かめることは 4 つあります。

| 番号 | 確かめること |
| --- | --- |
| 1 | キーの割り込みは、旗を 1 つ立てるだけで戻る |
| 2 | 配るのはプロセス自身で、カーネルを出るときに行う |
| 3 | 配るとき、カーネルはユーザースタックに割り込みと同じ形の 2 語を積む |
| 4 | ハンドラは、ユーザーモードの `rtt` でその 2 語を取り出して戻る |

この記事では、Verilog で書いた PDP-11 の上で本物の Unix V6 を動かし、4 つを波形で 1 つずつ確かめます。
使うのは [09-PDP-11 / Unix V6](https://tommie-jp.github.io/soft-fpga/examples/09-pdp11/web) のデバッグパネルです。

---

## 1. 該当のコード

V6 の割り込みキーは DEL（8 進で 177）です。端末の入力を受ける `dmr/tty.c` の `ttyinput()` が見張っています。

```c
        if ((t_flags&RAW)==0 && (c==CQUIT || c==CINTR)) {
                signal(tp, c==CINTR? SIGINT:SIGQIT);
                flushtty(tp);
                return;
        }
```

`signal()` は、その端末を使っているプロセスすべてに `psignal()` を呼びます。`psignal()` がすることは、ほぼ 1 行です。

```c
psignal(p, sig)
int *p;
{
        register *rp;

        if(sig >= NSIG)
                return;
        rp = p;
        if(rp->p_sig != SIGKIL)
                rp->p_sig = sig;
        if(rp->p_stat > PUSER)
                rp->p_stat = PUSER;
        if(rp->p_stat == SWAIT)
                setrun(rp);
}
```

プロセス表の `p_sig` にシグナルの番号を書き、眠っていれば起こします。これがコメントの言う旗です。

旗を見るのは、プロセス自身です。システムコールやトラップの出口に、次の 2 行があります。

```c
out:
        if(issig())
                psig();
        setpri(u.u_procp);
```

`issig()` は `p_sig` を調べ、配るものがあれば番号を返します。配るのは `psig()` です。

```c
        if((p=u.u_signal[n]) != 0) {
                u.u_error = 0;
                if(n != SIGINS && n != SIGTRC)
                        u.u_signal[n] = 0;
                n = u.u_ar0[R6] - 4;
                grow(n);
                suword(n+2, u.u_ar0[RPS]);
                suword(n, u.u_ar0[R7]);
                u.u_ar0[R6] = n;
                u.u_ar0[RPS] =& ~TBIT;
                u.u_ar0[R7] = p;
                return;
        }
```

`u.u_signal[n]` は、プロセスが `signal()` で登録したハンドラの番地です。
`psig()` はユーザーのスタックポインタを 4 下げ、そこへ PS と PC を書きます。そのうえで、戻り番地をハンドラに書き換えます。
PS と PC の 2 語は、PDP-11 が割り込みやトラップのときにスタックへ積むものと同じ並びです。

ハンドラの側は、C ライブラリの `s5/signal.s` です。シグナルごとの入口が並んだ表 `tvect` と、共通の後半があります。

```asm
tvect:
        mov r0,-(sp); mov dvect+[NSIG*2],r0; br 1f; NSIG=NSIG+1
        ...
1:
        mov     r1,-(sp)
        mov     r2,-(sp)
        mov     r3,-(sp)
        mov     r4,-(sp)
        jsr     pc,(r0)
        mov     (sp)+,r4
        mov     (sp)+,r3
        mov     (sp)+,r2
        mov     (sp)+,r1
        mov     (sp)+,r0
        rtt
```

C の `signal(2, h)` がカーネルに登録するのは、`h` の番地ではありません。`tvect` の 2 番目の入口です。
入口はレジスタを退避して `h` を呼び、戻ってきたらレジスタを戻して `rtt` を実行します。
`rtt` は割り込みから戻る命令で、スタックから PC と PS を取り出します。取り出すのは、`psig()` が積んだ 2 語です。

## 2. 観測の準備

[09-PDP-11 / Unix V6](https://tommie-jp.github.io/soft-fpga/examples/09-pdp11/web) を開き、`login:` に `root` で入ります。

### 2.1 シグナルを捕まえるプログラム

`ed` のような既存のコマンドは、ハンドラから元の場所へ戻りません。`rtt` まで見るために、小さなプログラムを作ります。

```text
# cat >sig.c
int n;
h(){ n++; }
main(){ char c; signal(2, h); read(0, &c, 1); printf("n=%d\n", n); }
^D
# cc sig.c
```

`^D` は Ctrl+D です。`cc` は 10 秒ほどかかります。
プログラムは 2 番のシグナル（SIGINT）を `h` で受けるよう登録し、端末から 1 文字読もうとして待ちます。

### 2.2 DEL を送るキー

この端末では、**Delete** キーが DEL（177）を送ります。
**Backspace** キーは `#` を送ります。V6 では `#` が 1 文字消去だからです。割り込みには使えません。

### 2.3 3 回に分けて止める

Delete キーを 1 回押すと、4 つの出来事が順に起きます。この記事では 3 回止めて見ます。

| 章 | 止める場所 | ボタン |
| --- | --- | --- |
| 3 | `psignal()` の入口 | 1 つめ |
| 4 | `psig()` の入口 | 2 つめ |
| 5 | ハンドラの最初の命令 | 3 つめ |

ボタンを押すと、文書の画面は閉じます。次のボタンを押すときは、32 章をもう一度開いて戻ってください。

## 3. Delete キー: 旗を立てるだけ

端末で `a.out` を実行します。プログラムは入力を待って止まります。そこで、次のボタンを押します。

[▶ psignal で止める設定を入れる](?scenario=sig-psignal)

端末をクリックしてから、Delete キーを 1 回押します。すぐに止まります。

ボタンは次の 3 つの操作をします。

1. **Logic Analyzer** のパネルを開く。
2. **Trigger** の Preset で `V6 psignal: signal number written to p_sig` を選び、**Set** を押す。
3. LA の信号を `VA`・`Data`・`WR`・`RD`・`BYTE`・`PC`・`Mode`・`INT`・`Vec` だけにする。

プリセットは、カーネルの 022644 番地にある `psignal()` の最初の命令で発火します。
発火の後も 1000 サンプルを採るので、`psignal()` が 2 回呼ばれるところまで入ります。

トリガーより左には、キーの割り込みからここまでの道筋があります。

| tick | 番地 | 値 | 動き |
| --- | --- | --- | --- |
| -853 | 000060 | 000254 | 受信割り込み。ベクタ 060 から入口の番地を読む |
| -705 | 052432 | — | `klrint()` に入る |
| -574 | 177562 | 000177 | 受信バッファから、押されたキーの DEL を読む |
| -501 | 050110 | — | `ttyinput()` に入る |
| -252 | 022572 | — | `signal()` に入る |
| 0 | 022644 | 004567 | `psignal()` に入る（トリガー） |

割り込みが入ったとき、`a.out` は走っていません。入力を待って眠っているので、CPU は待機のループにいました。
ハンドラの `h` はおろか、`a.out` の命令は 1 つも実行されていません。

`psignal()` の中身は、トリガーの 146 tick あとにあります。

![psignal の中。BYTE が立った書き込みが 1 回だけあり、062725 番地に 2 を書く](docs/img/32-01-la-psignal-write.png)

| tick | 書く番地 | 書く値 | 相手 |
| --- | --- | --- | --- |
| +146 | 062725 | 002 | シェル（プロセス 6）の `p_sig` |
| +809 | 062753 | 002 | `a.out` の `p_sig` |

`BYTE` の線が立っている書き込みが、`rp->p_sig = sig;` です。1 バイトに 2（SIGINT）を書いています。
`psignal()` は 2 回呼ばれます。同じ端末を使うプロセスが、シェルと `a.out` の 2 つだからです。シェルは SIGINT を無視する設定なので、旗が立っても何も起きません。

この取り込みの中に、ユーザースタックへの書き込みはありません。`psig()` も呼ばれていません。
割り込みの中で起きたのは、プロセス表の 2 バイトの書き換えと、眠っていたプロセスを起こす `setrun()` だけです。

## 4. psig: ユーザースタックに 2 語を積む

止まったまま、32 章をもう一度開いて、次のボタンを押します。シミュレーションは再開し、すぐにまた止まります。

[▶ psig で止める設定を入れる](?scenario=sig-psig)

プリセットは `V6 psig: frame pushed on user stack` で、023144 番地の `psig()` の最初の命令で発火します。
Delete キーの割り込みから約 1 万 5 千 tick あとです。そのあいだに、起こされた `a.out` が CPU を得ています。

トリガーの左を見ると、`psig()` を呼んだのが誰かが分かります。

| tick | 関数 | 動き |
| --- | --- | --- |
| -887 | `issig` | 起こされた `a.out` が、`sleep()` の中で旗を調べる |
| -597 | `aretu` | 旗が立っていたので、`read` を打ち切って `trap()` へ戻る |
| -277 | `issig` | `trap()` の出口で、もう一度旗を調べる |
| 0 | `psig` | 配る（トリガー） |

旗を調べたのも、`psig()` を呼んだのも、`a.out` 自身です。コメントの「プロセスが自分自身に何かをする」は、この呼び出しを指しています。

`psig()` の中では、`suword` が 2 回呼ばれます。

![psig の中の 2 回めの suword。177730 番地へ、中断された番地 001226 を書く](docs/img/32-02-la-psig-push-pc.png)

| tick | 書く番地 | 書く値 | C の行 |
| --- | --- | --- | --- |
| +692 | 177732 | 170001 | `suword(n+2, u.u_ar0[RPS]);` |
| +938 | 177730 | 001226 | `suword(n, u.u_ar0[R7]);` |
| +1085 | 141774 | 001410 | `u.u_ar0[R7] = p;` |

`a.out` のスタックポインタは 177734 でした。その下の 2 語に、PS と PC が入ります。
書き込みの瞬間だけ `Mode` が User になるのは、`suword` が `mtpi` 命令でユーザーの空間へ書くからです。

001226 は、C ライブラリの `read` の中で、`sys read` の次にある命令の番地です。中断されたシステムコールは、ここへ戻るはずでした。
170001 は、そのときの PS です。最後の 1 は C ビットで、`read` が失敗したことを表します。
3 行目は、戻り番地の書き換えです。141774 番地は退避した PC で、001226 が入っていました。そこへ 001410 を書いています。`tvect` の SIGINT の入口です。

途中にクロックの割り込みが入ると、3 つの tick は 600 ほど右へずれます。

## 5. ハンドラ: ユーザーモードの rtt で戻る

もう一度 32 章を開いて、次のボタンを押します。

[▶ ハンドラの入口で止める設定を入れる](?scenario=sig-handler)

プリセットは `V6 sig.c: SIGINT handler entry (tvect+20)` で、ユーザーの 001410 番地の命令 `mov r0,-(sp)` で発火します。
この番地は、2.1 のソースを `cc` した `a.out` のものです。ソースを変えると変わります。

![ハンドラの入口。カーネルの rtt が 001410 を取り出し、SP は 177730 を指している](docs/img/32-03-la-handler-entry.png)

| tick | 番地 | 値 | 動き |
| --- | --- | --- | --- |
| -5 | 141774 | 001410 | カーネルの `rtt` が PC を取り出す |
| -2 | 141776 | 170001 | PS を取り出す。Mode が User に変わる |
| 0 | 001410 | 010046 | `mov r0,-(sp)`。SP は 177730 |
| +10 | 001412 | 016700 | `mov dvect+4,r0`。R0 に `h` の番地 000030 が入る |
| +70 | 001640 | 004710 | `jsr pc,(r0)` で `h` を呼ぶ |
| +156 | 000034 | 005267 | `h` の中の `inc _n` |

カーネルは、`read` を呼んだ 001226 番地ではなく、001410 番地へ戻りました。
`a.out` から見ると、`read` の途中で、呼んだ覚えのないルーチンが動き出したことになります。ハードウェアの割り込みと同じ見え方です。
スタックの先頭の 2 語も、割り込みのときと同じ並びです。177730 番地に戻り番地、177732 番地に PS があります。

ハンドラの終わりは、トリガーの 305 tick あとです。

![ハンドラの出口。ユーザーモードの rtt が 177730 から 001226 を、177732 から 170001 を取り出す](docs/img/32-04-la-handler-rtt.png)

| tick | 番地 | 値 | 動き |
| --- | --- | --- | --- |
| +305 | 001654 | 000006 | `rtt` をフェッチする |
| +310 | 177730 | 001226 | PC を取り出す |
| +313 | 177732 | 170001 | PS を取り出す |
| +316 | 001226 | 103002 | `bec` をフェッチする。SP は 177734 に戻る |
| +322 | 001230 | 000167 | `jmp cerror` |

`Mode` の線は、トリガーからずっと User のままです。ハンドラから戻るのに、カーネルは使いません。
`rtt` は、`psig()` が積んだ 2 語をそのまま取り出しました。割り込みが積んだ枠でなくても、`rtt` には区別がつきません。

PS も戻るので、中断の前の状態が続きます。`h` の中の `inc _n` は条件コードを書き換えましたが、`rtt` のあとの PS は 170001 です。
C ビットが立ったままなので、`bec` は分岐せず、`read` は `cerror` を通って -1 を返します。
上段の **Resume** で再開すると、端末に `n=1` が出ます。

## 6. 計算中のプロセスには、1 秒ごとに配る

5 章までのプログラムは、システムコールの中で待っていました。旗を調べる機会は、すぐに来ます。
システムコールを呼ばずに計算を続けるプロセスには、その機会がありません。`sig.c` の `main` を次のように変えると確かめられます。

```c
main(){ signal(2, h); while(n == 0); printf("n=%d\n", n); }
```

このプログラムに Delete キーを押すと、`psig()` を呼ぶのは `ken/clock.c` の `clock()` です。

```c
        if(++lbolt >= HZ) {
                ...
                if((ps&UMODE) == UMODE) {
                        u.u_ar0 = &r0;
                        if(issig())
                                psig();
                        setpri(u.u_procp);
                }
        }
```

`HZ` は 60 です。クロックの割り込みが 60 回たまるごとに、つまり 1 秒に 1 回だけ、ユーザーモードのプロセスの旗を調べます。
この環境のクロックの割り込みは 1 万 tick ごとなので、1 秒は 60 万 tick です。
Delete キーから `psig()` までを 4 回測ると、318,400〜620,600 tick でした。キーを押した時機しだいで、最長 1 秒待たされます。

このとき積まれる PC は、ループの 3 つの命令 `tst _n`・`bne`・`br` のどれかの番地です。
ハンドラが `n` を 1 にして `rtt` で戻ると、ループは次の `tst _n` で抜けます。

`clock()` は 4 秒に 1 回、再スケジュールも求めます。それと重なると、`psig()` の直後にプロセスの切り替えが入ります。

## 7. 確かめた結果

| 確かめること | 確かめたこと |
| --- | --- |
| キーの割り込みは、旗を 1 つ立てるだけで戻る | 受信割り込みから 853 tick で `psignal()` に入り、`p_sig` に 2 を 1 バイト書いた。ユーザースタックには触れていない |
| 配るのはプロセス自身 | 起こされた `a.out` が `sleep()` と `trap()` の出口で `issig()` を呼び、自分で `psig()` を呼んだ |
| ユーザースタックに割り込みと同じ形の 2 語を積む | 177732 番地に PS の 170001、177730 番地に PC の 001226 を書き、戻り番地を 001410 に書き換えた |
| ハンドラは、ユーザーモードの `rtt` で戻る | 001654 番地の `rtt` が 2 語を取り出し、001226 番地へ戻った。入口から 316 tick、カーネルには入らない |

Delete キーを押してからハンドラが動き出すまでは、約 3 万 tick でした。
そのあいだに、割り込み、プロセスの切り替え、システムコールの打ち切り、`psig()` が順に起きています。
