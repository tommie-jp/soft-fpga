# 57. 速度リファクタリング

## 1. 現状と課題

最大速度モードで **3.5MHz** 程度しか出ない。
原因は Logic Analyzer（ring buffer）のオーバーヘッドが支配的なため。

---

## 2. ボトルネック一覧

| # | 場所 | 内容 | 推定コスト |
|---|------|------|-----------|
| 1 | `sim-worker.js` `simLoop()` | `Module._step()` を 100,000 回 JS から呼ぶ（JS→Wasm FFI） | 大 |
| 2 | `sim-worker.js` `simLoop()` | ring コピー：24,576 要素の JS for-loop（96KB alloc） | 中 |

| 4 | `harness.cpp` `step()` | `f_byte` 計算（5 ビット演算）、`call_log` 書き込み | 小 |

## 3. 改善案

### 3.1 sim_run_n(n) の導入（推定 +30〜50%）

`step()` を C++ 側でループさせ、JS→Wasm FFI 呼び出しを 100,000 回 → 1 回に削減する。

```cpp
// harness.cpp に追加
extern "C" void sim_run_n(int n) {
    for (int i = 0; i < n; i++) step();
}
```

```javascript
// sim-worker.js
// Module._step() × n → Module._sim_run_n(n) の 1 呼び出しに変更
Module._sim_run_n(n);
```

`build-wasm-06.sh` の `EXPORTED_FUNCTIONS` に `"_sim_run_n"` を追加。

---

### 3.2 ring コピーの高速化（推定 +5〜10%）

JS for-loop を TypedArray の `subarray` + `slice` に置き換える。

```javascript
// 現在（遅い）
var snap = new Uint32Array(RING_SIZE * 6);
for (var j = 0; j < RING_SIZE * 6; j++) snap[j] = Module.HEAPU32[ringBase + j];

// 改善後（速い）
var snap = Module.HEAPU32.subarray(ringBase, ringBase + RING_SIZE * 6).slice();
```

---

### 3.3 Logic Analyzer ON/OFF ボタン（推定 +20〜40%）

LA を OFF にすると ring 書き込み・ring コピーを両方スキップできる。

**harness.cpp:**

```cpp
static bool la_enabled = true;

extern "C" void sim_set_la_enabled(int enabled) {
    la_enabled = (enabled != 0);
}

// step() 内の ring 書き込みブロックを条件付きに
if (!ring_frozen && la_enabled) {
    // ... ring への 6 ワード書き込み
    ring_head++;
}
```

**sim-worker.js:**

```javascript
case 'setLA':
    Module._sim_set_la_enabled(data.enabled ? 1 : 0);
    break;
```

ring コピーも LA 無効時はスキップ：

```javascript
var snap = la_enabled
    ? Module.HEAPU32.subarray(ringBase, ringBase + RING_SIZE * 6).slice()
    : new Uint32Array(0);
```

`build-wasm-06.sh` の `EXPORTED_FUNCTIONS` に `"_sim_set_la_enabled"` を追加。

---

### 3.4 FPS を下げる（推定 +5〜15%）

ring コピー・postMessage の発生頻度を下げる。効果は限定的。

| FPS | ring copy 回数/秒 | 推定改善 |
|-----|-----------------|---------|
| 60fps（現在） | 60回 | 基準 |
| 30fps | 30回 | +5〜10% |
| 15fps | 15回 | +10〜15% |

sim_run_n・LA OFF と組み合わせると相乗効果あり。単独では効果が薄い。

---

## 4. 優先順位

```text
1位: sim_run_n(n)         → 実装コスト低・効果大
2位: LA OFF ボタン         → 実装コスト低・効果大（LA 不要時）
3位: ring コピー高速化     → 1行変更・効果中
4位: FPS 削減              → 他の改善と組み合わせ
```

---

## 5. 目標

現状 3.5MHz → 改善後 **6〜8MHz** 程度を目指す。
