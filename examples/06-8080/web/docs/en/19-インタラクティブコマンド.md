# 19. Interactive Commands

Key operations and `!` commands available in the interactive mode of the CP/M simulator (`cpm`).

## 1. Special Keys

| Key | Action |
|------|------|
| `Ctrl+\` | Exit the simulator (auto-saves dirty drives) |
| `Ctrl+T` | Display status (PC and drive state) |
| `↑` / `↓` | Command history (navigate to older/newer entries) |

### `Ctrl+T` Output Example

```text
--- [Ctrl+T] status ---
CPU   PC=F234  [BIOS]
Disk  drive=B  trk=12  sec=5  dma=0080
      A: cpm22.dsk          [dirty]
      B: bdsc.dsk
      C: (blank)
      D: (blank)
```

PC region classification:

| Range | Label |
|------|------|
| `0x0000–0x00FF` | `page0` |
| `0x0100–0xDBFF` | `TPA` |
| `0xDC00–0xE3FF` | `CCP` |
| `0xE400–0xF1FF` | `BDOS` |
| `0xF200–0xFFFF` | `BIOS` |

## 2. Command History

Press the ↑/↓ keys at the CP/M `A>` prompt to recall previously entered commands.

| Key | Action |
|------|------|
| `↑` | Display one older entry |
| `↓` | Display one newer entry. Reaching the most recent entry restores the input that was in progress when ↑ was first pressed |

### 2.1 Behavior Details

- The current input is erased with backspaces before the history entry is displayed.
- While a history entry is displayed, you can type characters to edit it directly.
- Lines submitted with `Enter` are added to the history (blank lines and duplicates of the previous entry are excluded).
- Up to 100 entries are retained; older entries are removed when the limit is exceeded.

### 2.2 Implementation Notes

The host side (`main_linux.cpp`) intercepts ESC sequences (`ESC [ A` / `ESC [ B`),
then feeds the corresponding backspaces and new entry text into CP/M via `send_key()`.
CP/M itself has no knowledge of history; it works naturally through the CCP line buffer.

## 3. `!` Commands

Typing `!` at the beginning of a line enters command mode. Press `Enter` to execute.

### 3.1 Shell Escape

```text
!ls
!pwd
!cp foo.com ~/backup/
```

Executes a shell command directly and prints its output to the terminal.

### 3.2 `!cap` — Output Capture

```text
!cap output.txt      # start capture
!cap off             # stop capture
!cap                 # stop capture (no argument)
```

Saves CP/M console output to a file. Data is written in real time while capture is active.

**Use cases**: Saving CPU exerciser results, recording DIR listings, etc.

### 3.3 `!paste` — Text Injection

```text
!paste program.bas
!paste commands.txt
```

Injects the contents of a text file into CP/M as keyboard input.
`\n` is automatically converted to `\r`.

**Use cases**: Entering MBASIC programs, automating repetitive command sequences.

**Note**: Maximum 65,535 bytes. Data is sent 16 bytes per loop to avoid flooding the CP/M input buffer.

### 3.4 `!mount` — Disk Swap

```text
!mount A: /path/to/new.dsk
!mount B: work.dsk
```

Replaces a drive's disk image without restarting the running CP/M session.
The new path is also used as the auto-save destination on exit.

**Use cases**: Switching working disks, mounting a disk from a different project.

## 4. Web UI Commands (Browser Version Only)

Commands available in the terminal input field of the browser version (`index.html`).
Prefix a line with `!` and press Enter; the UI layer intercepts it before it reaches CP/M or the BIOS.
These are distinct from the Linux CLI `!` shell escape and use a different command set.

### 4.1 `!ls` / `!dir` — File Listing

```text
!ls
!dir
```

Lists files and timestamps on the WASM virtual filesystem.

### 4.2 `!script` / `!run` — Macro Execution

```text
!script FILENAME
!run FILENAME
```

Reads a file from the WASM FS and injects it character by character into the CONIN buffer
to automate CP/M commands.

- While running, `▶ macro: FILENAME` and a stop button `■` are shown in the top-right corner of the terminal
- Up to 64 bytes per frame are sent, checking `sim_con_in_space()` for available buffer space
- Line ending conversion: `\r\n` → `\r`, standalone `\n` → `\r` (CP/M uses CR-only line endings)
- `^Z` (0x1A, CP/M EOF marker) is stripped before injection
- The leading `\r` in a macro triggers command execution, so the CR from the `!script` input itself is not sent to CP/M

**Use cases**: Automating SUB file execution, testing repetitive command sequences.

#### Directives Available Inside Macro Files

The following lines can be written in a macro file (`.MAC`, etc.) to control injection.

##### `!sleep N` — Fixed-Duration Wait

```text
!sleep 200
```

Pauses character injection for N milliseconds before advancing to the next line.
Use this to wait for screen rendering or for CP/M-side processing to complete.

##### `!expect STR [N]` — Output Wait

```text
!expect -
!expect - 300
!expect \r- 500
```

Stops character injection until `STR` appears in CONOUT.
If `STR` does not appear, it times out after **N milliseconds** (default 200 ms) and advances to the next line.
On timeout, a yellow warning `[warn] !expect timeout: "-"` is printed to the terminal.

- `STR` must not contain spaces
- `\r` and `\n` are interpreted as escape sequences (`\n-` → LF + hyphen)
- When waiting for the DDT prompt, use **`!expect \n-` instead of `!expect -`** (see below)

**Choosing between `!sleep` and `!expect`**:

| | `!sleep N` | `!expect STR` |
|---|---|---|
| Wait strategy | Fixed duration | Waits for actual output |
| False positives | None | Depends on pattern |
| Over-waiting | Always possible | None |
| Recommended for | Rendering delays, last-resort guard | Prompt detection |

**Why to use `!expect \n-` instead of `!expect -` for the DDT prompt**:

DDT's D command (memory dump) displays each byte as ASCII.
If byte value `0x2D` (`-`) exists in memory, it appears in the ASCII column of the dump output,
causing `!expect -` to falsely match and inject the G command too early.

The actual DDT prompt always appears at the start of a line, so `\n-` (LF + hyphen) matches it correctly:

```text
DDT output \r\n-  →  contains \n-  →  match ✅
0x2D in dump row  →  surrounded by spaces, no \n-  →  skipped ✅
```

Notes on timeouts:

- Loading DDT.COM (disk I/O + memory expansion) can exceed 200 ms
  → Specify `2000` (2 seconds) or more for `!expect \n-` immediately after DDT starts
- When waiting for a D command (dump) to finish, `500` ms is also recommended

**Correct DDT.MAC example**:

```text
DDT
!expect \n- 2000
S0300
3E
FF
76
.
!expect \n- 1000
D0300,0310
!expect \n- 500
G300
```

### 4.3 `!type` / `!cat` — Display File Contents

```text
!type FILENAME
!cat FILENAME
```

Displays the contents of a file from the WASM FS in the terminal.
`\n` is converted to `\r\n` so text files are rendered correctly.

### 4.4 `!upload` / `!ul` — Upload from Host

```text
!upload
!ul
```

Opens the browser file-selection dialog and saves the chosen file to the WASM FS.

**Use cases**: Transferring `.COM` files or SUB files created on the host into the in-browser CP/M.

### 4.5 `!get` / `!dl` — Download from WASM FS

```text
!get FILENAME
!dl FILENAME
```

Downloads a file from the WASM FS to the host PC (via the browser save dialog).

### 4.6 `!rm` / `!del` — Delete File

```text
!rm FILENAME
!del FILENAME
```

Deletes a file from the WASM FS.

### 4.7 `!stop` — Stop Macro

```text
!stop
```

Immediately aborts a running `!script` / `!run` session.
All queued injection characters are discarded and the macro status display is cleared.
Clicking the `■` button in the top-right corner of the terminal performs the same action.

### 4.8 `!help` — Command List

```text
!help
!?
```

Prints a list of available `!` commands to the terminal.

---

### Macro Status Display

While `!script` is running, the following is shown in the top-right corner of the terminal:

```text
▶ macro: FILENAME   ■
```

Clicking the `■` button triggers the same stop processing as `!stop`.
